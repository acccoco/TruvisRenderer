## 发现与处置

### 输入内容和实际工具变化不使缓存失效（P1，已修复并验证）

`runner/mod.rs:FileStamp::from_path` 只记录长度和毫秒时间；`run` 比较 manifest 编译器配置字符串，`ShaderTaskManifest` 只记录 executable 路径。临时进程夹具复现：同长度修改 entry/shared input 并还原时间、同路径替换 compiler、替换同目录 DLL、切换 PATH 中同名 compiler，均未调用 compiler 而返回成功；只更新时间戳却会重编。bare compiler 删除后，已有缓存仍被接受。

修复归属现有 runner：文件按内容摘要比较；只解析当前任务实际使用的 compiler，bare 名称显式按 PATH 查找并将实际绝对路径传给 Command；记录该 executable 与同目录 DLL 内容。源码包仍按既有依赖闭包传播变化，工具变化保守失效本次全部任务。只靠版本字符串不能识别同版本重新打包或 DLL 替换，因此不以 `--version` 代替内容身份。

范围限制：工具目录之外的动态库、系统 loader/环境和 SDK 行为不是完整可重现构建描述；改变这些输入需要 `--force`。构建期间输入保持稳定，工具不支持与编辑/工具安装并发执行。

### 未使用 compiler 也阻止构建（P2，已修复并验证）

`ShaderBuildRunner::new` 无条件检查三种配置路径。只有 Slang entry 时，配置的 GLSLC/DXC 文件不存在仍在任务发现前失败。夹具已复现。将实际 compiler 解析/校验移到完整任务发现之后；实际所需工具必须在任何输出清理前确认可用。

### 发现阶段吞掉遍历错误（P1，已修复并验证错误传播）

`collect_tasks`、`collect_shared_inputs`、`ShaderDependencyValidator::validate_sources` 使用 `filter_map(Result::ok)`，嵌套目录访问失败会被当作文件不存在；构建器随后可能按不完整集合执行清理/缓存。最小修复是发现失败立即返回错误，保留已有输出和状态。根目录缺失已有 canonical/include 检查，夹具确认该反例不会误删；不能把根目录反例当成嵌套访问失败的运行验证。

## Binding 与 manifest 判断

- Shader codegen 使用 C++17、禁止递归 allowlist、基础 Slang 类型重命名和 owner namespace 映射；CXX codegen 使用 C++20，支持 function allowlist、Default/layout_tests。输入契约不同，保留两个 owner。
- hash/write-if-changed 的小段实现重复，但 hash 只作为生成诊断/编译依赖提示，实际写入比较完整字节；没有据此确认缓存错误。B26 可复核共用价值，本批不建通用生成框架。
- 两次 `parse_callbacks` 并非覆盖：本地锁定的 bindgen 0.72.1 `options/mod.rs` 将 callback push 到列表。CargoCallbacks 记录实际 header include；ABI root 与 manifest 额外 rerun 声明有用途。
- Engine/Renderer build.rs 决定 allowlist 和跨 namespace re-export，工具不拥有 ABI。paths.toml 由 `truvis-path/build.rs` 跟踪，绑定输出按 target/owner 分开。不同 profile 并发写同一输出及写入中断不在本次单进程验证内，保留为 B27 风险。
- manifest 校验 package id、依赖环、shared root/include 覆盖及 binding output crate，不能替代实际文件系统身份。大小写/嵌套输出冲突与清理路径校验交给 B02-b3；ABI/include 逐边约束交给 B03。
