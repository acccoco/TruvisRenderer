本轮保持单渲染线程、graphics queue、BLAS barrier、immutable CPU identity、FIF 窗口和
公共 API。使用现有 owner 的私有集合和释放方法，无通用事务框架、重试线程、兼容设施，
不复制 GPU 资源。RtGeometry::destroy_mut 仍由该类型负责成对回收，避免在完成/退役路径
重复拆分 vertex/index 生命周期。同步模块 README，未改变 shader ABI。

## 保留项与证据边界

- CPU 删除不提前销毁在飞上传；完成结果再次验证包含 generation 的 handle。旧身份不能
  写入复用相同 slot 的新身份。ready 删除进入 retired，`current_frame - retired_frame`
  使用 saturating_sub，达到 FrameLabel::COUNT（当前 3）才回收。
- Runtime::begin_frame 先成功等待 frame timeline 的 `current_frame - COUNT`，再传入同一
  frame id；正常 destroy 先执行 Gfx idle。上传 timeline 只证明 copy/build 完成，不能
  替代已发布 mesh 的消费者使用安全点，已修正 destroy 注释以明确此前置。
- 独立 mesh owner 仍有明确职责：vertex/index copy、BLAS build、scratch 和 metadata 同批
  移交。当前 GfxCore 的两条 VkQueue 来自同一个 graphics family，因此不能宣称硬件上
  绝对无法合并；本轮保留 graphics 上的 mesh 调度，未仅因与 texture/sky 队列字段相似
  就引入共享框架。合并会涉及调度/同步契约，留 B10-e/B26 依据完整链评估。
- GpuMeshStore::destroy 仍消费 self。若上传等待失败，局部 queue 不移出 pending，但上层
  继续 unwind 的终止行为不等同于“整个 Runtime 可恢复”；不承诺 device-lost 重试。
  RenderAssetSystem 其它 owner 的聚合关闭仍由 B10-d/B12 复核。
- 发布通知只保留到 sync 成功返回。Runtime 在此前已 take CPU instance_changes，且返回
  后到 RenderWorld 消费之间仍有录制/binding/material 等步骤；更外层失败时的通知恢复
  属于 B11/B12，不能以本轮局部保留宣称端到端事务成立。

## 验证

后续复核：上述 sync 返回后的通知窗口已由 [B11-a2](B11-a2.md) 的 RenderWorld 持久
通知及 CPU 候选交接修复。叶子 mesh owner 的本批证据保持，不扩展为整帧失败恢复。

`.temp/code-design/B10-b3/{run.py,mocks.rs,main.rs}` 编译基准/当前完整 mesh 队列与 store
源码、实际 RtGeometry 销毁方法和 SoA 布局方法。保留真实 ash/glam/log/slotmap；CPU view、
RHI 与 geometry 描述投影使用替身。替身模拟资源计数、释放后日志异常和 timeline 完成。

28 类场景在新旧版本、debug assertions/overflow checks 同开/同关各执行一次，112 次
进程运行满足对应预期：

- 正常/部分完成，第一/后续 staging 与 scratch 回收异常；修复后目标仍在 queue，后续
  sync 可完整发布，不重复释放资源。
- 第一/第二笔 ready 日志或 address 查询失败：修复后当前与后续结果保留，前一笔安装
  通知也保留；下次返回全部三笔，随后 sync 不重复通知。旧版丢失目标与通知。
- 上传中删除、真实 slotmap generation 复用、ready 删除、duplicate 拒绝及诊断异常、
  stale geometry 回收异常；旧结果不会复活，正常 metadata 与 resolver 数据保持。
- 在 frame 10 退役后，9/10/12 不释放、13 释放；混合 10/12/10 退役集合在 13 只释放
  两项，到 15 再释放剩余项。retire 日志与 vertex/index/BLAS 诊断异常均不丢失未到期项。
- shutdown 同时包含已发布、退役、pending 或 completed 资源，分别注入 stage/scratch/
  vertex/index/BLAS/semaphore 及全部释放诊断失败；修复后模拟 native 计数归零。
  queue 等待超时仍保留 35 个模拟对象，模拟完成后再关闭可全部回收。

为了观察旧版消费 self 后的泄漏，夹具将 queue Drop 的 debug assert 改为记录未关闭，
叶子也仅记录 native 计数；真实 debug unwind 可能二次 panic 终止。夹具不证明 driver
同步、真实设备恢复、native free 失败或 allocator abort 安全；未运行 GPU/图像回归。
跨 queue 与各 shader stage 的内存可见性继续 B10-e。
