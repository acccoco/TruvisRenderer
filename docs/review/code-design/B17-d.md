## 公共事件类型收敛

**P2：Realtime/Offline 复制类型，通过相同 guard 选择其中一份。** 两份 MaterialType、
RtSurfaceHit、RtTracePayload 和 ShadowMissPayload 完全相同，却需要手工同步字段、方法和
注释；B17-c2b 的 Offline 编译失败已经证明遗漏风险。现原样移到 Renderer
`lib/renderer/ray_payload.slangi`。各入口保留自己的 ABI、push constants、max_depth 和既有
namespace remap；没有把 pass 配置提升为共同不变量，也没有新增兼容层、公共 CPU API 或资源。

此提交为机械性去重。提取脚本先断言两份类型原文相同；Slang `-E -target spirv` 对全部
24 个 Renderer 入口比较，排除注释/行标记后的代码 token 与基准完全相同。`just shader`
24 编译、7 复用、两个 binding crate 通过；全部 24 份 Renderer SPIR-V 通过
`spirv-val --uniform-buffer-standard-layout`。初试 spirv-opt 归一化二进制时工具崩溃，
因此改用预处理等价与构建/validator 证据，没有宣称二进制逐字节一致。临时脚本与记录位于
`.temp/code-design/B17-d/`。无算法变化，不重复 GPU 或完整应用构建。

## 纯发光反射契约

**P2：纯 EMISSIVE 的 guide 仍携带反射率。** sample_next 对 EMISSIVE 输出 emission 并终止，
两条主 raygen 与 SHARC 也在累加 emission 后结束；ReSTIR 排除该类型。但 RR writer 在
主路径终止前已经写入 guide，compute_rr_albedo 的普通分支仍会生成 diffuse/F0；通用
eval_brdf/PDF 也没有拒绝纯发光类别。这些结果与当前零反射 BSDF 不符。

修复限定为 MaterialType::EMISSIVE：连续反射值/PDF 和 RR diffuse/specular guide 现统一为零。
不能按 emissive RGB 是否非零判断；带 emissive factor 的 Surface 仍同时反射和发光。
主 radiance、emission、motion/depth、GBuffer 与 RR hit distance 不改变。

RR 参考本地 Streamline v2.14.1 固定提交
`2122257e0fce486f91b385aa63b9a09b0a34b363` 的 `ProgrammingGuideDLSS_RR.md` §4.1.1/4.1.2；
文档 SHA-256 仍为 `6298e42ee84a664ff67b62adc2b6de465e7b0421ec9927c809a915760ebe354b`。
其中 albedo 表示反射分量；纯发光返回零是从项目实际终止语义得出的适配，不是声称 SDK
规定所有含 emission 的材质都不反射，也不代表 DLSS 图像已验收。

数值验证 `check-emission.py` 抽取实际公共事件类型、sampler/eval/PDF 和 RR writer，以 C++
float 在 O0/O2、禁用 contraction 下执行：108 组纯发光参数中，基准有 96 组非零 guide、
90 组不符合零反射的 eval、81 组不符合零密度的 PDF；修改后全部为零且有限，emission/done
保持正确。216 组同时带 emission 的普通/rough fallback/镜面/透明对照，其求值、guide 与
采样权重的 float32 文本与基准完全一致。没有运行纹理采样、GPU 或 DLSS 图像验收。
第二次 `just shader`：24 编译、7 复用、两个 binding crate 通过；Realtime/Offline raygen
通过 `spirv-val --uniform-buffer-standard-layout`。

## 已核对的共同语义与消费差异

| 消费方 | 当前共同入口与边界 |
|---|---|
| Realtime/Offline | 同一 surface evaluator、material sampler 和 path state；均先累加 emission，再对纯 EMISSIVE 终止，之后才做 NEE/续路。pass 策略与资源仍各自拥有。 |
| NEE | candidate 只表达 light 侧；shade 调用共同 eval_brdf/PDF。analytic 的固定 MIS=1、候选 PDF/visibility 是否正确仍归 B18。 |
| ReSTIR | target/reconnection 经 RtDirectLighting 使用共同材质求值，未复制另一份 GGX；key 重建仍只支持 rough fallback 子集，缺独立几何法线。 |
| SHARC | update 调用相同 sample_next 并传 radiance throughput；query 返回的缓存 radiance 乘主 path throughput。roulette 乘子不传入 cache，估计器本身尚待 B20。 |
| RR | delta 用共同 Fresnel/镜面权重，rough 仍为 F0 近似；primary normal/motion/hit distance 不等于完整透射运动。 |

ShadowMissPayload 仍被两套 pipeline 注册的 shadow miss entry 使用，不能只因 NEE 当前采用
inline RayQuery 就删除类型。RtRussianRouletteResult 的 throughput_scale 没有读取者，两个
调用点只读 survived；这是可在 B18 路径状态审阅中收敛的小型冗余，不扩展本批第三个提交。

## 后续交接与统一方案

以下是方案与验证要求，不实施最终全局模型修改。

- **B18 路径估计器：** 核对候选、路径 MIS/PDF、终止/深度/roulette 与 emission 的完整组合；
  保留 B17-c3 已证实的 radiance 溢出/下溢问题。RR reflection-distance 仍会为纯发光事件
  生成近似查询，可连同无消费者的 roulette 返回字段评估清理；不要把 guide 当成光学模型。
- **B19 ReSTIR：** 必须补齐独立几何法线的持久化、历史、绑定与资源访问。当前重建统一为
  ROUGH_SURFACE，与 ROUGH_TRANSMISSION 相同的结果仅依赖既有反射 fallback；将来实现
  rough BTDF、自定义 IOR 或复合 lobe 时，必须扩充 eligibility/key，而不是仅替换 BSDF 函数。
- **B20 SHARC：** 核对缓存保存量、更新/查询、normal 分桶、透射 throughput、终止/历史与
  emission 的估计关系。已有单个材质公式复用不证明 cache 无偏或生命周期正确。
- **B27 材质模型方案：** 以固定 OpenPBR 版本选择 dielectric layer 的 diffuse 能量分配、
  多次散射补偿及 RR 方向反射率；一起修改 eval/sample/PDF，不用单项 Fresnel 或 guide 调参
  掩盖白炉偏差。B17-b2 的非金属增能/金属多次散射缺失证据保留。
- **B27 复合 lobe/透射方案：** 分离“材质包含哪些 lobe”和“本次采中了哪个离散/连续事件”，
  让 smooth 非金属保留 diffuse；同步 NEE/MIS、ReSTIR 和 RR。rough BTDF、opacity/体积吸收、
  介质栈与 CPU/导入语义统一设计，不能保留参数名称却悄悄改变含义。
- **B27 法线与数值方案：** 联合定义 shading/geometric 半球、双面/负缩放、切线 UV/烘焙
  约定和 transport 能量处理。明确 IOR/HDR/路径长度支持域及异常策略，承接 c1 临界精度、
  c2b 几何侧穿透和 c3 累积失败；验证必须包括参考资产、白炉/边界积分、GPU FTZ 与画面回归。

上述方案分别落在材质模型、路径事件、资源 key 和资产表达的实际 owner；不新增中央注册表、
通用兼容层或一套平行材质求值框架。B17 约定范围已扫描，下一批 B18；
这不表示完整 OpenPBR、ReSTIR、SHARC、GPU 数值或最终图像已经通过。
