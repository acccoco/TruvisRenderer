## 已确认问题与局部方案

- **P1**：embedded fail_startup 只 log+exit，child 创建/rect 应用失败可以令窗口线程
  正常返回，shutdown 得到 Ok；非零 pump 退出码也只写日志。由 Handler 保存首个
  具体宿主错误，窗口线程返回 Result，shutdown 在 join 后传播该结果。
- **P1**：standalone 在非零退出码处先 assert，正常 pump 退出后先 log，再显式
  destroy；这两处 panic 都会改走 Drop 并丢失显式 join 的渲染异常。先退出 pump、
  显式 join/drop window，再报告退出码；移除中间日志断点。
- **P1**：EmbeddedWinitHost::Drop 记录关闭错误时可能在宿主 unwind 中再次 panic。
  Drop 仅作 join 兜底，错误由显式 shutdown 返回，不调用日志后端。

架构预检：错误状态归现有 EmbeddedWinitHandler，线程结果仍由 EmbeddedWinitHost
独占；复用 Result/String 与现有 join，不增加事件类型、跨线程请求、重试或 GPU owner。
保留先返回 EventLoopProxy 再创建 child 的启动顺序和 render join → child drop 顺序。
同步维护模块 README/线程设计，公共方法签名不变；窗口错误的异步结果在 shutdown
边界交付，不把 set_viewport_rect 投递成功改成同步 native 应用确认。

## 扫描结论与交接

- Win32RenderSurface 只携带具体可 Send 句柄，raw enum 在目标 RenderThread 重建；
  没有新增 unsafe Send 或把 Window 跨线程移动。parent 必须由 App 持有到 shutdown
  返回，这仍是调用方契约，不是 raw handle 类型自动保证。
- startup proxy 早于 child 创建，避免主线程等待 child 创建期间无法泵消息。不能为了
  同步确认 renderer ready 把该握手挪后。当前错误在 shutdown 时可见，运行中即时
  通知/产品 UI 策略交 B25/B27，不新增协议或 callback API。
- desktop::take_resources 先停止接收并从锁内取走 owner，随后在锁外 shutdown；
  CloseRequested/ExitRequested 调用同步 join。parent 消息泵与 child native 操作是否
  形成实际循环等待仍缺运行时证据，交 B25/B27 验收，不凭静态 join 宣称已证实死锁，
  也不临时加入消息泵重入/后台关闭线程。
- 正常路径 render join → child drop → window thread join 的 CPU 顺序成立；Runtime
  panic 跳过回收与 WSI 完成凭据仍是 B12/B27 的 P1 偏差。当前宿主仍会在 join 错误后
  drop child；需要跨层结果分类方案，本次不伪造可安全销毁的证明。
- standalone/embedded 共用线程宿主与输入适配；平台事件分派和错误出口有必要差异，
  不抽象成通用 host trait。下一批 **B13-c：输入、resize/零尺寸与平台边界汇总**，
  继续检查 WM_SIZE/焦点/输入消费链，最终全局修改仍不实施。
