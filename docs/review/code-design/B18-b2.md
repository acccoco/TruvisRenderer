## 修复一：命中竞争 PDF 的原始顶点

**P1：** NEE 按未偏移的 surface.position 连接 light_position，命中查询却使用从偏移
ray origin 起算的 hit_t 与 ray.Direction，距离和光源余弦不属于同一连接。共享一个
emissive_solid_angle_pdf 函数不足以保证输入契约相同。

主路径与 SHARC Update 现保存上一次散射的原始表面位置，命中查询用当前命中位置减去它，
重新计算距离/方向；相同距离 guard 与 NEE 一致。camera/delta 链不竞争的规则不变；
状态在续路时更新，两条主 raygen 共用 RtPathState，SHARC 使用相同查询入口。
不改变 payload/shared ABI、资源 owner、pass 顺序或表结构，新增三个局部 float 未做寄存器分析。

`.temp/code-design/B18-b2/check-hit.py` 抽取真实 offset_ray_origin 与命中/共同 PDF 方法，
mock table/instance；C++ float O0/O2、关闭 contraction。72 组覆盖三个坐标尺度
0/10/10000、四个顶点距离 0.01/0.1/1/100、三种偏移法线及 2/3 个 light class。
以可表示顶点的 double 连接公式为基准，原实现 66 组相对误差超过 5e-7，修复后为零，
最大相对误差 1.98e-7。大坐标短连接包含偏移跨过目标的压力输入；这是 PDF 查询隔离验证，
不是 72 条实际 GPU 路径或全部位置/距离均受支持的证明。

`just shader`：24 编译、7 复用，两个 binding crate 通过；Realtime/Offline raygen
均通过 `spirv-val --uniform-buffer-standard-layout`。未执行 GPU 图像或 SHARC 运行验证。
本阶段提交 `51765ab0`；visibility 修复为本报告所在提交。本报告保存端点子批证据，后续 CPU 表构建与数值修复已完成，见 [B18-b2b](B18-b2b.md)。

## 修复二：发光几何 visibility 的两端连接

**P1：** 原 helper 沿未偏移 light_dir 发射，只从 TMax 扣掉起点偏移的投影。
它仍是一条横向错位的平行线，终点没有偏移，可能命中光源三角形自身。
现有 RtDirectLighting 内增加明确的 emissive 双表面连接入口，采样与 ReSTIR 重建共用；
起点复用 offset_ray_origin，光源端沿三角形法线向起点侧偏移，随后重新计算连接方向/长度。
起点已跨过目标、双端偏移后反向或区间过短时输出 TMax=0，由现有调用方丢弃空候选。
PDF、radiance/BSDF 使用原始几何连接，visibility ray 不反向覆盖其参数。

参考本地 PBRT `b4ce9687e6c695f5582997c61b0c66cf064bdb4a` 的 `ray.h::SpawnRayTo`
双 Interaction 端点版本。本项目保留已有 Ray Tracing Gems origin offset、单位方向和米制区间；
未复制 PBRT 的 Point3fi 误差界、非单位 ray 或固定 ShadowEpsilon，因而不声称同等误差保证。

`check-visibility.py` 抽取实际 helper 与 offset，C++ float O0/O2，double 平面求交作观测。
162 组覆盖三个坐标尺度、三种连接尺度、三种起点法线、三种光源平面及两面法线方向：
修改前/后均有 18 组空区间；其余目标平面自遮挡从 54 组降为零，中途阻挡平面漏检及超远
平面误命中均为零。与偏移终点的最大相对连接误差从 0.07877 降为 5.56e-8。
另检查原点附近 1e-6 短连接的起点越界拒绝。初版仅检查双端 segment 方向会遗漏此情况，
夹具发现后补充了起点到原目标的正向检查，最终两种优化配置全部通过。

这不是 Vulkan triangle traversal、薄遮挡物、全尺度误差界或 GPU 图像验证；不能将偏移
后的可见性近似推广为精确物理连接。Analytic 的旧 helper 留给 B18-b3；ReSTIR 重建表面
缺少真实几何法线仍按 B17-c2a 交 B19，不能从本 helper 修复推出输入法线已经正确。
第二次 `just shader`：24 编译、7 复用，两 binding crate 通过；两套 raygen 的 SPIR-V 通过。

## 表/材质复核与必须继续的范围

- CPU base_map 与 geometry indirect 的紧凑顺序有断言；每个发光 submesh 保留完整
  primitive 顺序，包括退化记录，alias 仅含正且有限的权重记录。shader alias 保存的是
  record index，命中按 base+primitive 查完整记录，重建按 record_count 而非 alias_count 判界。
- proposal 权重为常量 emission 估计亮度×世界面积，不直接采样 emissive 纹理；实际 radiance
  经 MaterialAccess::emission。evaluate_emissive 先检查 base-color alpha cutout，采样到洞
  返回零 radiance，不能仅因此重归一化 proposal。仍需数值夹具覆盖真实表/映射和零支持域。
- 当前 RT emission 无单面门控，PDF 使用 abs(light.normal·-wi)，因此现有两面策略一致；
  负 determinant 导致 CPU winding 法线反号不改变绝对余弦或面向连接的端点偏移。
  glTF doubleSided 与整套 shading/geometry 约定仍属 B17 的模型提案，不能在此局部改成单面。
- **已交 B18-b2b 并完成局部修复的基准证据：** GpuMeshStore::build_triangle_metadata 与
  RenderEmissiveLightTable::append_submesh_triangles 均以 f32 cross.length() 计算面积。
  `check-metadata.py` 抽取真实 metadata 方法、mock SubmeshData，链接现有 glam rlib：
  直角三角形边长 1e-12 时 local_area=0，double 为约 5e-25；边长 1e10 时 local_area=Inf，
  double 为 5e19，后者仍可由 f32 面积表示。世界面积/normal 路径也需与 metadata 一并检查，
  不能只改 shader 或删除 local_area 门控。该夹具未覆盖上传与 BLAS，依赖路径保存在临时日志中。
- B18-b2b 同时继续 alias 概率质量与稀疏 record 映射、面积/solid-angle 运算的溢出/下溢、
  掠射 guard 与零 PDF、非有限候选的消费策略。当前仅检查 <=0 不等于保证有限；本次未掩盖
  这些生产端缺口。HDR/FTZ 与随机网格仍承接 B18-b1 的共同问题。

两个提交均仅修改 shader 内部状态/算法与相关文档，未做完整应用/GPU 构建运行或性能验证。
端点局部修复与 [B18-b2b](B18-b2b.md) 数值续批已完成，B18 父项保持进行中；下一批 B18-b3。
