## 局部修复

**P2：Alpha Cutoff 的控件域小于 World 域。** `MaterialData::validate` 和 Editor controller
允许 finite、非负的 cutoff，明确允许大于 1；原控件复用 `[0,1]` 的 `RangeField`，大于 1 的现有值
无法可靠编辑。改用已有 `NumberField`，只设 `min=0`，不设上限。

**P2：材质数值输入把空字符串转换成 0。** IOR、emissive radiance、base color、normal strength、
emissive factor 和 texture transform 原先直接调用 `Number(event.target.value)`；清空后会立刻把
草稿和失焦命令变成 0，无法表达“尚未输入”，也可能把无效 IOR/UV 写入命令。扩展现有 `NumberField`
支持 `step` 和局部 class，所有这些控件复用其编辑字符串、finite、min/max 和 blur 提交边界；
空值或非法值只保持 invalid，不发送 draft/command。归一化 metallic、roughness 和 opacity 仍使用
RangeField 的 `[0,1]` 约束。

**P2：mock connect 的旧 ready 回写。** mock transport 的延迟 connect 在 close 或 StrictMode 重挂载
后仍可发出 `ready`。增加与 Tauri transport 相同的 generation 检查；mock 仍只用于 `?mock=1` 视觉
验收，不改变真实 IPC。

**P2：viewport 清理矩形顺序。** cleanup 原先与在途 `set_render_viewport_rect` 并发发送零矩形，旧矩形
可能在零矩形之后完成。现在在途请求完成后再发送排队的零矩形，并阻止 `document.fonts` 的迟到
回调重新排队测量；native child HWND 的 owner 和 IPC 命令不变。

## 未改项

`EditorWorkspace` 的最小/最大宽度、窄屏断点、键盘 resizer 和 `ResizeObserver` 约束在当前代码中
保持一致，没有发现可独立修复的越界或重复 owner。`vite.config.ts` 只允许仓库根静态资源且端口
固定，`tsconfig` 的严格检查和 generated protocol 边界也与既有设计一致。

## 证据

`.temp/code-design/B23-c/probe.mjs` 用 rolldown 编译实际 `NumberField`，验证空值不产生 draft/commit、
有效 `1.75` 可提交；同时对真实 material、mock 和 viewport 源码检查 Alpha cutoff 上限、连接代次
和清理顺序。基准输出 `baseline_empty_number_would_be_zero=true; alpha_range_max=1`，修复输出
`actual_number_fields=empty_preserved; alpha_cutoff_unbounded_above_one=true; mock_connect_generation=true; viewport_cleanup_ordered=true`。

`npm run build`（包含 `tsc -b`）、`npm run typecheck` 和 `git diff --check` 通过。没有运行真实 Tauri
React StrictMode、桌面 child HWND、RenderThread/World 或 GPU 验收；mock 探针与 Web 构建不能替代这些证据。
