## 组合生命周期（P1，已确认并修复）

`RenderWorld::new` 原来直接依次创建 asset、灯光和 FIF buffer；后项失败会让此前已交付
的 owner 离开作用域而未显式回收。叶子构造的回滚仅覆盖叶子自身，不能覆盖这个组合。
`destroy` 原来串行调用，任一场景 owner 的释放诊断异常会跳过后续 owner。

保持 CPU table、共享 asset、灯光、FIF buffer 和 TLAS 的归属及依赖方向。构造期先完成
CPU table，GPU 子 owner 暂存为候选，全部完成后交付；失败逐项回收已完成候选，最后
关闭 assets，并保留原始构造错误。成功返回的 asset fallback 已同步完成且尚未接收
scene 上传；失败叶子内部的未知 native 提交仍由该叶子负责，不能据此宣称可安全回收。

正常关闭仍要求调用方已等待全部场景 GPU 消费结束。逐项尝试灯光、TLAS 和各 FIF，
最后关闭共享 assets；assets 关闭异常直接传播，包括 queue 等待失败。assets 正常关闭
后才传播先前场景释放的首个诊断异常。没有吞掉 native 等待错误，也不保证等待失败后
资源全部释放。实现及直接模块 README 已在 `91b3feb5` 更新。

临时夹具 `.temp/code-design/B11-e/run-life.py` 提取实际 RenderWorld 构造/关闭，并纳入
实际灯光表、SceneBuffers、SceneTlas、RenderData 和 FrameLabel；用模拟 buffer、AS、
assets 记录分配/释放及注入错误。每种配置覆盖正常构造/关闭、64 个创建失败点、6 个
回滚诊断组合、67 个释放失败点、asset 等待失败及异常优先级、全部释放报错，共 141 类。
修复前后各启用/关闭 debug assertions 和 overflow checks，**564 次通过**：前版本确认
外层遗漏，后版本回收全部已交付候选；等待失败保留 asset，未冒充释放成功。

`cargo check --offline --locked -p truvis-app`（包含 Runtime）通过。夹具不模拟真实 native
Drop/abort、设备丢失或 GPU 在飞使用，不证明失败后还能恢复渲染；未运行 GPU/完整构建。

## 冗余与抽象

单字段 `RenderAnalyticLightUpdateResult` 仅由一个调用点取 binding，没有额外状态或
独立契约；本报告所在提交已直接返回 `AnalyticLightBinding`，同步修改唯一调用方，
未改变地址/count/version、dirty/pending 确认或公共 API。复用 B11-d1 容量/上传夹具，
仅适配返回类型：32 类 × 2 配置 **64 次通过**，App 编译和空白检查通过。

其余 owner 分离有明确用途：
CPU World 是权威，资源发布、稳定 slot 对账、FIF 上传确认、TLAS revision 分别约束不同
生命周期，不因都带 dirty/version 就合并。RenderWorldPrepareResult 的具名历史失效结果
承载 prepare 阶段交接，当前没有足够维护代价证据要求同时清理。
