## 结论与保留理由

未确认本批范围内需要修改实现的缺陷，不为减少 helper 数量或统一格式而重构。
两个 HDR 数值 helper 无状态且真正局部；RGBA8/RGBA16F 的区分承担字节布局、色彩解释
与上传格式契约，不能合并成可任意指定 format 的 bytes 容器。

- `TextureBytes::new` 拒绝零尺寸、非 2D、通道数量溢出和长度不符。字段私有，后续
  texel_count/index 乘法受构造校验保护；合法 Arc slice 本身已满足分配字节范围约束。
  as_bytes 借用既有存储，clone 共享像素，不重复复制大型 HDR 数据。
- loader 不翻转行；普通图片扩为 RGBA8，包含 16 位整数图片的有损量化。显式颜色空间
  决定 UNORM/SRGB；不依靠文件 metadata 推断材质用途。linear_rgb 只对 RGB 解码 sRGB。
- HDR/EXR 的 f32 路径在转 RGBA8 前分流为 RGBA16F；Srgb 请求失败。RGB 负数与
  非有限值清零，有限值上限 65504；alpha 限制到 [0,1]，非有限值取 1，RGB 输入补 alpha=1。
  此为当前 loader 的规范化，不是通用 TextureBytes 构造器的浮点值校验。
- 文件按扩展名选择 decoder，embedded 按内容识别；mime_type 当前仅用于诊断。
  无扩展名/错误扩展名文件会失败；TGA 文件可解码，但 embedded TGA 不能靠 MIME 开启
  decoder。当前 glTF 图片与未来 Assimp embedded 支持范围交 B08-c，不擅自添加 fallback。

**P3 文档补充**：模块 README 原文未说明整数 16 位量化、格式选择和数值校验职责。
本批只补这些已验证的限制及构造器注释，不改变 API、owner、线程、像素转换或 GPU 契约。

## 验证

`.temp/code-design/B08-b/run.py` 编译实际 handle/material_texture/texture_loader，复用
真实 image/half/bytemuck 依赖；仅 task request/result 外壳为同字段替身，直接执行任务。
生成并读取真实 PNG、Radiance HDR、OpenEXR、TGA 文件和 encoded bytes；不使用假 decoder。

断言与溢出检查开/关均通过 **24 类**：RGBA8 Linear/Srgb 的文件/embedded 一致性、中文
大写扩展名、行顺序/alpha/共享存储，RGB/灰度/灰度 alpha 扩展，RGBA16 PNG 量化，MIME
不参与选择，空/损坏/截断输入，文件缺失/无扩展名/扩展名不符，TGA 两种输入的差异，
HDR 数值保留与 Srgb 拒绝，EXR RGB/RGBA/非有限值/alpha/Srgb，已知 sRGB 数值，
无效 extent/算术溢出、短长 payload、texel 越界，以及公开 F16 payload 只校验形状的边界。

运行代码未改变，不重复整个项目构建；本批无新增仓库单元测试。未做 GPU upload、图像
回归、全部格式或跨平台验收，CPU 结果不证明天空采样或最终画面正确。

B13/B27，GPU 尺寸/创建/提交失败交 B10；本批没有按未经确认的预算硬截断输入。
