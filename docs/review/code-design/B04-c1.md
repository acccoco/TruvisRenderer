## 修复前发现

1. **P2，Win32 错误缓冲异常泄漏，已确认，已修复。** `StringUtils::win32_error_message` 在 FormatMessageW 分配后先 to_utf8，再 LocalFree；UTF-8 std::string 分配抛异常会跳过 LocalFree。正常输出不暴露此缺口。用标准 unique_ptr 配 LocalFree 接管系统缓冲，保持返回文本和异常传播语义。
2. **P1，loader 诊断异常跨 C ABI 且泄漏 DLL 引用，已确认并复现，已修复。** `load_streamline_api` 的 LoadLibraryW 返回裸 HMODULE，resolve_required_export 在错误路径构造多个 std::string；分配失败可能在 FreeLibrary 前退出，truvixx_sl_init 没有捕获。加载本身失败时的诊断分配也可能跨 C ABI。仅把未发布 DLL 引用改成 RAII，并在 loader 边界捕获 C++ 异常返回既有 eErrorExceptionHandler；catch 不再构造错误文本。本批不以捕获为由卸载已进入 SDK 初始化/运行的实例。

冗余与抽象：StringUtils 聚合 Windows 编码职责，native loader 管理模块引用，责任划分可保留。日志 callback→bounded queue→drain thread 避免 SDK 栈承担日志 IO，有保留理由；不能只因几层转发删除。暂不整理全部 free helper，避免把局部异常修复扩成重构。

## 架构预检

修复归属 StringUtils 和既有 SlApi/loader；复用标准 unique_ptr，释放责任仍在 native。DLL 仅在完整函数表解析成功后交给 SlApi；SDK 未被调用的失败路径才在栈展开时释放临时引用。public ABI、线程、feature 选择、GPU 和正常 init/shutdown 顺序不变。直接更新 StringUtils 注释与 binding README，各项验证后分别提交，总计不超过两次。
