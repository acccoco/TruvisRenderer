## 证据与处置方案

- **P1，已确认：直接构造不闭合。** `resources/buffer.rs::new` 在 VMA 分配后 map/name 失败不释放；
  `image.rs::new/from_external` 与 `image_view.rs::new` 在 naming panic 后由 Drop 再次断言；
  `sampler.rs::new` 在 naming 后才交付 wrapper，失败泄漏。`GfxDevice::set_*debug_name` 的 CString
  转换和 Vulkan Result 都会 panic，不只是 OOM 的理论路径。复用已有 command pool 的局部 catch，
  回收创建成功但未交付的 native 对象，再 resume 原始 panic；external image 只撤销 wrapper。
- **P2，已确认：special buffer 二次 naming。** index、vertex、stage、SBT 的 new 在 GfxBuffer 已命名
  后再次命名；没有新增所有权信息，却制造额外失败点。保留底层命名及传入业务标签，删除重复调用；
  usage、对齐、元素数和 SBT region 封装仍有必要，不删除这些类型。
- **P1，已确认：失效地址未撤销。** buffer destroy_mut 只清 handle/map/allocation，device_address
  仍返回旧地址。显式 release 应同时撤销派生地址与容量，不能把已释放 native allocation 当成活资源。
- **P1，已确认：view 描述和实际对象不一致。** `image_view.rs::new` 固定 base_array_layer=0、
  layer_count=1，却缓存调用方的 layer_range。应完整投影描述，并在 native 调用前拒绝空范围。
- **P2，已确认：像素格式范围的末端被遗漏。** `VulkanFormatUtils::pixel_size_in_bytes` 的区间判断为
  `< end`；BGR sRGB、BGRA sRGB、RGB16F 被拒绝，只为 RGBA16F 加了特例。改为包含终点，去除特例；
  image 上传的 width*height 目前先用 u32 乘法，需在宿主可寻址范围内 checked_mul，并在分配/录制前验证。
- **P2，已确认：concurrent sharing 输入缺少局部约束。** `GfxImageCreateInfo::queue_family_indices`
  接受空、单一或重复 family，却总是标记 CONCURRENT，并在持久 inner 中重复保存 Vec 的裸指针。
  拒绝不足两个或重复 family，裸指针只在 as_info 的短暂借用投影中产生；不尝试隐式切换 EXCLUSIVE。

## 保留与跨批交接

sampler 的 filter/address/compare/aniso 描述按字段传入；当前 root 启用 samplerAnisotropy，manager
使用 16 倍各向异性，但 wrapper 不持有设备上限。能力与输入合法性仍属于 root/上层契约，不能由本次
构造清理推出“任意描述合法”；不添加隐式 clamp/fallback。外部 image 只由 swapchain presenter 创建，
wrapper 当前不保存 WSI usage，后续 B05-d 核对 WSI，B07 核对 graph 消费（B05-c4 按总清单纠正交接），不能把空 flags/usage 当成完整 native 描述。
view/image 生命周期、任意 ctx 销毁、raw handle 和外部 Rc 的完整 safe API 仍交全局建议，B26/B27 不实施。

失败回收不包含 panic=abort、native 内存错误或 allocator/device 已失效；日志不参与构造回滚。正常
显式释放先清 native 和状态，再记录诊断，避免 logger panic 令本对象再次触发遗漏释放断言。

## 验证

第一提交 `a3a8fc0d`：直接叶子构造回收、special buffer naming 和 buffer 失效状态已修复。
各 wrapper 在 native 创建后立即接管句柄/分配，catch 只包围交付前的 map/地址获取/naming；
private release 不记录日志。正常显式 destroy 复用同一 release，之后才记录诊断。

`.temp/code-design/B05-b2/make_probe.py` 引入实际 buffer/image/view/sampler 与四种 special buffer
源码，只替换 VMA/device/command 依赖为计数/CPU 内存夹具，不把假 handle 传入真实驱动。

- debug assertions 开/关各 **54 个场景**通过：创建成功、native 创建失败、map 失败、name 失败、
  CString NUL、诊断 logger panic、释放 logger panic、四种 special buffer 不再二次 naming、
  重复显式释放以及释放后 device_address 拒绝访问。每个成功创建对象恰好释放一次，unmap 先于
  buffer destroy；external image 无 native release。
- 修复前 buffer/map 只记录 `buffer+`；buffer/name 只记录 `buffer+,map+`。无断言构建中 image/view/
  sampler 命名失败同样遗漏释放；开启断言时 image/view/external 和 special buffer 二次 naming
  失败进程退出码为 3221226505，发生 unwind 中的 Drop assertion。修复后错误仍传播，释放已完成。
- 夹具验证 Rust wrapper 的控制流与调用次序；不是实际 Vulkan/VMA 分配、GPU 同步或 SDK 故障验收。
  `cargo check --offline --locked -p truvis-gfx -p truvis-renderer`、Gfx 构建和修改范围的空白检查通过。
  未新增仓库单元测试。

第二提交为本报告所在提交：图像描述/尺寸投影已修复。view 传递实际 mip/layer 范围并拒绝零计数；
