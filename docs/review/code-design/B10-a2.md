# B10-a2：上传队列构造、准备与提交接管

> 历史说明：本文项目 hash、提交次数及“本报告所在提交”均按压缩前历史解释，实验引用保留为“压缩前证据基准”；第三方版本不变。当前分组见[提交压缩映射](commit-squash.md)。


基准 `b2cee818`。覆盖共享队列 new、texture/sky 准备与 native submit 交接，复核 RHI 的
command/pool/semaphore、Image.transfer_data 和 buffer 显式销毁。没有修改 RHI、GPU ABI 或

## 发现与修复

- **P1：部分构造/录制失败遗留资源。** semaphore 构造失败时 pool 尚未被 owner 接管；
  texture 的 command/录制/end 失败遗留 image 或 staging，sky 的 staging/map/command 等
  失败遗留目标 buffer。构造先保留 pool 并在失败时回收；两条上传复用仅限提交前的私有
  AssetUploadPreparation，逐项持有部分构造结果，失败撤销 command 后释放本次目标/staging。
  Image.transfer_data 内部失败仍由既有 RHI helper 回收它尚未交出的 staging。
- **P2：容量/存活校验发生过晚。** 关闭后仍先分配 native 资源；时间线加法溢出在 debug
  中留下资源、无断言时回到 0；pending 扩容位于 submit 后。现在分配前检查关闭/不确定状态，
  checked_add 预检下一值并 try_reserve pending 容量，失败返回 Err；准备失败不消耗时间线值。
- **P1：submit 异常时失去本次 owner。** pending 原先只在 native submit 返回后登记。
  现在录制和 submit info 完整准备后，预留槽接管全部资源，再进入 submit；统一私有方法
  维护该顺序。submit 未正常返回则保留 pending 并标记 submission_uncertain，拒绝新的上传
  与 poll 发布；只有 shutdown 成功等待相应 timeline 后才能释放，不把未知状态当成未提交。

rollback 的叶子资源日志在 native release 后执行；逐项捕获这些诊断异常以继续释放并保留
原始准备错误。不新增通用事务/自动 Drop 释放框架，不尝试在 native submit 的未知边界回滚。
只有准备阶段的纯 CPU/native 未提交资源可回收；原有 pending 不受另一次准备失败影响。

## 验证与限制

`.temp/code-design/B10-a2/{run.py,mocks.rs,main.rs}` 编译新旧队列完整实现（仅移除 imports
与 Tracy，以受控 RHI/typed payload 替身连接），保留实际分支、owner 结构、catch、容量计算、
FIFO、poll 与 shutdown。真实 anyhow 提供 Err/宏；native 分配、录制、submit、计数和释放由
事件替身注入故障。不是实际 Vulkan 驱动、VMA、ABI 字节或跨 queue 同步实验。

断言/溢出检查同开、同关时各运行 39 类新旧对照：

- pool/semaphore 构造，texture/sky 目标与 staging 分配、map、command 分配/begin/end、
  copy/barrier、submit info/signal 失败；新版已交付的未提交对象配对回收。
- rollback 中叶子日志 panic，保留最初 end 错误且继续回收其他对象。
- 关闭后误用、空 sky、u64::MAX、接近耗尽、正常 texture/sky/混合；新版前置拒绝无新 native
  分配，空 sky 和正常流程保留既有语义。宿主真实 OOM/try_reserve 故障未注入。
- submit 故障保留 pending，禁止继续派发/发布；未证明完成时 shutdown 失败仍保留资源，
  模拟完成后才释放。另一次准备失败保留原先 pending，不重置共享 command pool。
- B10-a1 的查询/等待失败回归与之后 typed completion 继续通过。

替身没有 native owner 的 Drop 断言，因此可观察旧版遗留；真实 debug 运行可能二次 panic
终止。资源释放假定 native destroy 正常，未覆盖自定义 panic payload 的 Drop 或 abort。
submission_uncertain 不是设备恢复机制：若失败提交永不发出 signal，关闭等待仍失败，外层
Runtime 的 device-lost/终止策略继续交 B12/B27；不自动 clear 标记或声称可以继续渲染。
