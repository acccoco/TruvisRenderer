# B11-c：SceneTlas、raster 与拾取映射

> 历史说明：本文项目 hash、提交次数及“本报告所在提交”均按压缩前历史解释，实验引用保留为“压缩前证据基准”；第三方版本不变。当前分组见[提交压缩映射](commit-squash.md)。


基准 `55500f60`，分支 `refactor`；修复随本报告所在提交落地。范围为 SceneTlas owner、
raster cache、selection 和同步 raycast 的 instance slot 反查。本批约定范围已扫描。

## 发现与局部修复

**P2，已修复**：SceneTlas::destroy_mut 在逐 FIF 关闭时直接调用叶子 destroy。
GfxAcceleration 先释放 AS handle，backing GfxBuffer 在 native 释放后记录日志；
该诊断异常会中断循环，使后续 FIF 未被清理。在外层 consuming destroy 展开时，
未释放的 wrapper 还可能触发 debug Drop 断言。现沿用已有 catch/resume 模式，
在所有 FIF 已 idle 的前提下逐项清理，再传播首个异常；重复关闭不重复释放。

这没有修改公共 API、Shader ABI、同步提交方式或资源 owner；SceneTlas 继续独占
每 FIF 的 TLAS。修复不增加 native wait，不保证 GPU 提交状态未知时可恢复。
RenderWorld 还拥有其它资源，其组合收尾仍待 B11-e，Runtime 安全退场交 B12。

## 已核对的正常路径与边界

- 构造只建立空 Option，不分配 native 资源。每 FIF 独立保存 TLAS/revision；相同版本
  复用，active 集合、transform 或 any-hit 要求改变时推进版本并重建当前 FIF。
  空场景释放当前 TLAS，其余 FIF 保留原快照。重建先释放旧 TLAS，成功取得新对象
  后才确认 revision；局部 build 失败可留下 None，不能把它解释为完整帧可继续运行。
- custom index 使用稳定 slot 并检查 24-bit 范围；BLAS 地址来自对应 mesh。transform
  投影为 Vulkan 3x4 行布局，World 的输入约束允许 shear/负缩放但要求可逆 affine。
  FORCE_OPAQUE 仅由 any-hit 要求决定；禁用 triangle facing cull 的现有策略不变。
- raster cache 按 instance/submesh 展开，使用既有 SoA offset 与 UINT32 index；普通
  draw 和选中 draw 共用同一缓存。两条 draw 路径有少量重复绑定代码，但职责局部且
  无状态，本轮不为消除几行重复新增抽象。
- selection 先用 CPU handle 解析 Active binding，再核对 slot record 的 handle 和
  submesh 边界，最后在当前 FIF cache 中查找。删除、Pending、身份不符及越界会跳过。
  同步 raycast 的 raw hit 通过同一 prepare 记录映射回 instance/mesh/material，未知
  slot 或越界 submesh 返回错误；miss 不查询 slot。
- 实际 Loop 顺序为 prepare → after_prepare 同步 raycast → render，selection label
  来自本帧 record context。CPU 查询期间借用不允许同时重新 prepare。反查表没有按 FIF
  保留历史，所以接口只支持当前 prepare；已补充 selection 的调用契约，不能把它用于
  旧 FIF 或异步 readback。未新增历史快照设施或声称任意 label 都能被运行时拒绝。

## 验证

`.temp/code-design/B11-c/run.py` 编译真实 SceneTlas、RenderData、RenderInstanceTable、
resolver 接口、raster cache、SoA layout、FrameLabel 和生成 GPU 类型，并提取真实
convert_raw_hits。替换 Scene/resolver 资源叶子及 RHI build/destroy/command 为受控对象。

修复前后分别启用/关闭 debug assertions 与 overflow checks：**19 类 × 4 = 76 次通过**。

- 12 类 TLAS：正常三 FIF、版本复用/单 FIF 更新、空场景/再次激活、build 失败、替换和
  清空时释放诊断异常、缺失 BLAS、slot 越界、关闭第 1/2/3 项异常及所有项异常。
  核对 descriptor 的 transform、custom index、mask、SBT offset、flags、BLAS 字段，
  以及 owner/revision、构建/释放次数、首个异常和重复关闭。
- 7 类映射：正常共享 mesh、删除、延迟 slot 回收后新 handle 复用、Pending、材质
  替换、未知 slot/越界 hit、record 身份不符。检查 raster 参数、selection key、SoA
  offsets 和命中字段转录。正常映射在前后版本一致。
- 关闭故障基准会留下后续 owner；修复后全部释放。夹具没有实现 native wrapper 的
  debug Drop abort，以便记录遗漏对象数量，不代表旧实现能在真实 shutdown 中恢复。
- `cargo check --offline --locked -p truvis-app`（含 Runtime）及 `git diff --check` 通过。
  未新增源码单元测试，未运行 GPU/RT/raster 回归；受控描述符与调用记录不证明实际
  GPU 同步、命中结果或完整退出。Gfx 同步 build 内部沿用 B05 的既有边界。
