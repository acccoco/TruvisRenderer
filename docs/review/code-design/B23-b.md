## 局部修复：会话清理

**P2：cleanup 后旧分页和 connect 续接仍可更新投影。** cleanup 只推进 inspection 与 selection
序号，未使独立的 listSequence 失效；再次 setup 将 active 设回 true，旧列表就能回写。
connect 回调只在进入 poll 前检查 disposed，poll 等待期间 cleanup 后仍会启动 refresh。

cleanup 同时推进现有查询序号与材质检查代次；connect 在 poll 返回后重新检查 disposed。
状态仍由 session 拥有，不新增 transport 或协议层，不取消已发送的 mutation，不改变 GPU 契约。

修复后两项均被拒绝。探针不替代真实 React effect 调度或 Tauri 运行验收。

## 材质 ACK 与查询顺序

**P2：MaterialDto 没有 `scene_version`，命令回包不能直接视为当前材质投影。** 原实现无条件用
`command_applied.material` 替换当前 material；如果 ACK 期间启动了新的查询，旧 ACK 会覆盖查询已经
得到的投影。命令仍按 `commandTail` 串行发送，但这不能排序独立 query。

命令在实际发送前记录 `materialSequence`。若回包期间序号变化，或 ACK 的 `scene_version` 低于当前
session 版本，只清理未被新输入修改的字段 revision，并重新读取当前 material；没有交叠查询时才
直接采用 ACK 的 material。这样不扩展协议，也不把 Web projection 误当成 World authority。

`.temp/code-design/B23-b/probe.mjs` 的基准模式复现了：清理后旧列表回写、清理后旧 connect/poll
继续刷新、查询完成后旧 ACK 覆盖、查询未完成时旧 ACK 覆盖。修复版七组检查通过：清理隔离、ACK
恢复、revision 与 command 顺序、分页 conflict 重试、selection notification 优先，以及上述两种
查询交叠次序。`npm run build`、`npm run typecheck`（`app/editor/web`）和 `git diff --check`
通过；`node .temp/code-design/B23-b/probe.mjs before/after` 均通过预期断言。

未执行真实 Tauri React StrictMode、RenderThread/World、GPU 或完整桌面验收；这些仍是本批证据边界。
