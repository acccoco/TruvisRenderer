结构表写入、复制范围、GpuScene 根字段及 scene_access 的索引消费。分为两个行为提交：

## 发现与局部修复

- **P2，已修复**：累计 geometry/indirect 偏移和若干数量为 usize，写 GPU uint 时
  直接 as u32；mesh/材质数量相等只作 debug assertion。普通 producer 已保持排序和
  对齐，但累计范围缺少显式约束。RenderData 现在验证 mesh 前缀、唯一递增 slot、
  mesh 引用、材质并行数组和实际 uint 索引范围；SceneBuffers 复用其数量计算结果，
  校验先于任何扩容和 raster cache 更新。顶点数在 Geometry 写入时显式转换。
  table 累加使用 checked_add，写入端保留显式转换和数量断言。
- **P3，已修复**：geometry 和两张 indirect 表原先每次以 stage.size() 复制整个
  预分配容量。现复用既有 flush/copy/barrier，按实际写入的类型化前缀复制；
  空表不录制 copy，字节计算检查乘法和源/目标容量。不声称已经测得性能收益。

继续由 RenderWorld 拥有打包和上传，RenderData 只提供只读派生快照及容量校验。
不新增框架、公共 API、资源 owner 或同步机制。保留稳定 slot 与紧凑间接表的分工；
GPU 实际索引必须适配 uint，宿主排他上界可为 u32::MAX + 1，不能误写为 GPU 数量。
索引异常属于内部契约失败，不是可恢复的导入错误；顶点数量检查发生在写表时，
不承诺回滚之前的扩容或 stage 写入。资源与失败退场边界保持 B11-b1/b2 约定。

## 核对与验证

- scene root 继续使用生成的 `gpu::engine::scene::GpuScene`。结构 buffer 地址来自
  当前 FIF，material/light/sky 地址与计数来自对应 owner 的 binding；TLAS revision
  进入累计签名而非 root 地址字段。实际上传函数的逐字段转录没有发现遗漏。
- instance 通过稳定 slot 写四个 range 字段，geometry/material indirect 按 active
  instance/submesh 顺序紧凑写入；共享 mesh 复用 geometry 前缀。矩阵写入与提交确认
  仍由 B11-b2 路径处理，不在这里重复写入或确认。
- 临时夹具位于 `.temp/code-design/B11-b3/`，提取真实 RenderData、SceneBuffers 和
  五个上传/复制函数，使用真实 FrameLabel 与生成 GPU 类型，替换 RHI buffer/command
  和资源叶子为可记录的受控对象。未在源码加入单元测试。
- 最终实现与基准在 debug assertions/overflow checks 启用、关闭两种配置下比较：
  基准 16 类、最终实现 20 类，共 **72 次通过**。覆盖空/共享 mesh/稀疏 slot、错误前缀、
  mesh 引用、材质数组、重复/乱序 slot，以及几何地址/数量、indirect 映射、有效复制
  字节数、root 全部字段与错误 barrier 后不提前发布累计签名。非法布局同时配有需要
  扩容的 slot，最终实现在分配前拒绝；基准接受并扩容。
- 顶点数和 geometry offset 使用轻量受控数值 u32::MAX + 1，基准发生截断，修复后
  拒绝。额外检查 24-bit slot、排他上界、usize 加法溢出、copy 乘法溢出及容量拒绝。
  大范围检查是标量/模拟资源实验，没有分配巨量 native buffer 或复现实际 GPU 故障。
- 最终实现 `cargo check --offline --locked -p truvis-app`（含 Runtime）通过；提交前
  索引校验分组版本也已通过同一编译检查。`git diff --check` 通过。

没有修改 Slang ABI、字段布局、pass 顺序或屏障 mask；受控字节检查不等于新 SPIR-V
布局验证或 GPU 渲染验收。没有运行完整 GPU/RT/raster 回归，绑定 owner 的资源有效性、
triangle metadata 与灯光语义分别交后续 B11-c/d；未提交 command 的处置交 B12。
