## 边界与契约

`ImGuiSubsystem` 持有 ImGui context、font atlas、per-FIF `GuiMesh` 和 `GuiPass`；Renderer 在 update 构建 frame，在 render 的 prepare 阶段上传当前 frame label 的 mesh，RenderGraph pass 只借用 draw data 和当帧 mesh。格式变化时 `GuiPass` 在 resize 期间重建 pipeline，字体、context 和 mesh 不随格式重建。`renderer-render-ui` 只修改传入的 Renderer-owned settings，不接触 GPU 资源或归一化；`DebugImageSelection` 只保存稳定 ID，Renderer 每帧调用 `normalize_options`。

输入适配把物理像素坐标和按键状态交给 ImGui；具体 Renderer 决定 `want_capture_*` 后是否继续写入 `InputManager`。当前支持拖动所需的移动/松键穿透，控件层没有独立输入 owner。

## 发现

### 运行时 DPI 改变没有进入 Renderer 契约（P2；已确认，跨模块）

- 证据：`RendererInitCtx` 仅在 `engine/e50-render-loop/truvis-render-loop/src/renderer.rs:13-21` 提供 `scale_factor`；`RendererResizeCtx:23-29` 只有 `window_size`。三个 Renderer 只在 init 调用 `set_hidpi_factor`（`renderer/truvis-renderer/src/truvis_renderer.rs:311-315`、sample 同类入口），`ImGuiSubsystem::init_font` 在 `renderer/renderer-imgui/src/subsystem.rs:197-214` 将该值一次性烘焙进字体像素尺寸。
- 触发与影响：winit 收到 `WindowEvent::ScaleFactorChanged` 时，standalone 直接忽略（`engine/e60-platform/truvis-winit-host/src/standalone.rs:147`），embedded 只写日志（`embedded.rs:388-390`）；resize 只传物理尺寸。窗口移到另一 DPI 显示器或系统缩放改变后，新的物理 viewport 会重建，但字体 atlas、`TruvisRenderer::ui_scale` 和首次窗口几何仍沿用旧 scale，导致 UI 字体/布局比例与当前 DPI 不一致。
- 保留现状的理由/反证：当前 host 可能只在单显示器固定 DPI 运行，且 ImGui display size 与输入均使用物理像素，所以常规 resize 不会触发坐标错位；这不能证明动态 DPI 合约已闭合。
- 最小建议：由平台 host 把 scale-factor 变化作为独立的 render-loop 输入/resize 信息交给 Renderer；统一更新 `ui_scale`、font atlas（必要时重建字体纹理）和采样/布局状态。需要同时覆盖 standalone、embedded、`RendererResizeCtx`/输入事件和三个 Renderer，不能只在 `ImGuiSubsystem` 增加一个未被调用的 setter。
- 验证：静态证据已完成；需要在至少两个 Windows DPI 显示器间移动窗口，确认字体、主面板首次布局、鼠标拾取和 viewport overlay 均按新比例更新，并运行 Vulkan validation 检查 font image 重建退场。暂不在本批实现。
- 处置：等待相关批次；目标 B25 App、场景和示例中的平台/RenderLoop 交接。B25 修复后需回看本报告与 B13-c/B14-c 的坐标结论。

后续复核：以上为 `50f5612a` 时的证据；[B25-a](B25-a.md) 已实现独立 DPI 回调、事件合并与
idle 后字体重建，并验证 CPU 合并和真实 ImGui atlas。当前处置以 B25-a 为准，动态显示器/GPU 验收仍未完成。

### 冗余与过度抽象（未确认问题）

- `ImGuiSubsystem`、`GuiPass`、`GuiMesh` 的三层分别持有 context、pipeline 和 per-FIF buffer；`prepare_render_data`、`contribute_passes` 与 shutdown 的调用方均为具体 Renderer，未看到可删除的中间 owner。
- `DebugImageSelection::normalize_options` 在 Renderer 固定阶段执行，选择器视图只展示和修改稳定 ID；没有把 GPU handle 或候选归一化复制到 UI。`RenderControlsOverlay` 直接写 settings，配置失效/历史资源清理留给 rendering subsystem，职责变化原因不同。
- `DebugInfoOverlay` 和 `DebugImageSelectorView` 是无状态 UI 视图，当前没有第二套同规则实现；不因函数数量或 thin wrapper 形状提出合并。
