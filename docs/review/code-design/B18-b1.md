## 局部修复：极区方向精度

**P1，已修复主要消减误差：** 原 shader 在行内先插值 sin(latitude)，再经过
asin→UV→sin/cos。4096×2048 的首行高度在 y≈1 附近，f32 只剩很少可表示值；
舍入到极点后 cos(π/2) 的近似负值还会翻转经度，重新查询 PDF 无法恢复实际抽样分布。

修复归属已有 EnvMap：极区插值球冠面积 q=2*sin²(alpha/2)，水平半径为 sqrt(q*(2-q))，
中部直接插值 Y；直接构造方向，避免反三角往返。查询以 atan2(length(xz),y) 求北极夹角，
保留水平分量中的纬度信息，也避免 0.5-latitude/π 的抵消。删除只服务旧链路、无外部调用的
angle_to_uv、dir_to_angle、uv_to_dir 和 row_sin_bounds；新增行为仍封装在 EnvMap::sample_row。
修正旧注释中经度正方向写反的问题，实际坐标约定不变。

参考 PBRT 本地 commit `b4ce9687e6c695f5582997c61b0c66cf064bdb4a`，配置 git_ref=master；
核对 SampleUniformSphere 与 SphericalDirection 的球轴采样/直接构造公式。项目保持 Y-up
和已有经度方向，使用半角恒等式适配窄球冠，不照搬 PBRT 的整球坐标和框架。

`.temp/code-design/B18-b1/check-env.py` 抽取实际 EnvMap，mock scene/table 与随机槽，
以 C++ float O0/O2、关闭 contraction 执行；覆盖高度 1/3/16/2048 的 12 个代表行，
每行 65,536 个纬度区间中点，共 786,432 个样本。用 double 的独立球冠面积反算行内 CDF。
表中密度为可区分的测试值，用于追踪 cell 身份，概率归一化由下述 Rust 夹具另行验证。

| 指标 | 基准 | 修复后 |
|---|---:|---:|
| 首行样本的不同水平半径数量 | 21 | 65,536 |
| 首行查询错误 cell | 3,276 | 0 |
| 全部代表行查询错误 cell | 7,111 | 0 |
| 代表行最大 CDF 误差 | 0.0381893 | 3.82e-7 |
| 非有限输出 | 0 | 0 |

`check-boundary.py` 补充 2048 行×64 个内部样本：错 cell 从 10 降为 0；最大行内 CDF
误差从 0.036641 降至 0.000100465，单位长度误差小于 8.60e-8。全行结果比代表行误差大，
不能用极区改进数值代表所有纬度。CPU 数学内建函数与 lerp 模拟不代表 GPU intrinsic 的逐位结果。

## CPU 表与消费链

`check-builder.py` 抽取真实 Rust 构建方法与结果类型，仅 mock TextureBytes 的已解码 RGB
和日志，不涉及 worker/上传。独立二维卷积对照实际三行滚动缓存，独立 cos(colatitude)
公式对照行面积，重建 alias 概率质量与 PDF×cell_area。O0/O2 均覆盖 25 组：
1×1、6×3、32×16、4097×5、17×2051，分别使用黑、常量、接缝/极点亮斑、非均匀、极端 HDR。

- 全黑/零能量进入 UniformFallback；0 维 extent 拒绝。两组越界分辨率分别降为
  4096×4、16×2048，8192×4096 的 extent 单独检查为 4096×2048。
- 所有 Ready 表总概率与 1 的差小于 4.04e-8；单 cell PDF 概率质量误差小于 4.04e-8，
  alias 概率质量误差小于 3.10e-9。真正零权重 cell 的 alias 概率质量和 PDF 均为零。
- 过滤为源分辨率 [1,6,1]/8，U 环绕、V 钳制，权重乘源 texel 面积后按源中心映射目标 cell；
  它是 proposal 近似，不承诺精确匹配 bilinear radiance，也未模拟真实 image 解码或 GPU filtering。
- shader 无资源/显式 Uniform 回退、有效表内零 PDF 保持零、alias 阈值相等时选择 alias
  的半开区间均经夹具检查。class_count 恒含 HDRI，加上启用的 emissive/analytic；
  sample_unified_candidate 只乘一次 1/class_count，sky miss/rebuild 使用同一因子。
- GpuSkyStore 在 texture identity 改变时撤下旧分布，CPU/GPU completion 均核对 request
  与 texture；新 image ready、alias 未 ready 时使用 uniform，旧表不会配给新 image。
  本次是源码复核，未重跑既有资源生命周期故障夹具，也未验证 GPU 实时切换。

## 仍未闭合的数值边界

1. **接缝/端点：** 2160 组刻意选取 U/V 的 0、2^-24、1-2^-24 等边界，包含极点、
   行分支边界与首末列；错 cell 从 1087 降为 884，仍存在。它们不是均匀随机统计，
   不能解读为实际画面错误率。有限方向的 cell 归属与采样返回密度仍可能不一致；
   RtDirectLighting 现有重查 PDF 没有因此被宣称正确或移除。交 B18-d/B27 评估边界策略与 GPU 误差。
2. **随机网格：** 穷举 k/2^24 的 column 乘法/取整，3、18、8,382,465 个 column 的
   每桶命中数分别为 5,592,405–5,592,406、932,067–932,068、2–3，不能等同精确 1/N。
   这里只验证实际输出网格，未证明 LCG 相邻槽独立、alias 联合分布或完整估计器无偏。
   Random 被多个采样器共享，交 B18-d/B27 联合制定方案，不在 HDRI 内增加平行 RNG。
3. **HDR 动态范围：** 有限 RGB 1e30/1e-30 对比时，6×3 表有 12 个正权重 cell 的 f32
   PDF 下溢为零；32×16 为 506 个。概率总质量接近 1 不代表正支持域保留。
   这是数值输入域缺口，不能靠给零 cell 单独写 uniform 修复 alias/PDF 配套关系。
   与 B17 HDR throughput/FTZ 交 B18-d/B27 共同评估；没有据此声称当前所有 HDR 输入合法。

`just shader`：24 编译、7 复用，两个 binding crate 通过；Realtime/Offline 的 raygen
和 miss_sky 共四个 SPIR-V 通过 `spirv-val --uniform-buffer-standard-layout`。
未改 ABI、依赖方向、线程、资源所有权或 RenderGraph；未执行完整应用构建、GPU 图像、
性能、方差、intrinsic/FTZ 或切换验收。数值夹具和构建证据不能替代这些验证。
