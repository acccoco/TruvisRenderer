## 局部修复与边界

`debug_cache_radiance` 原先无条件调用 Query，即使 Off 已停止维护，仍显示旧 resolved
内容。现在复用 maintain_enabled：Off 返回零且不构造查询参数；Update/On 允许观察
当前 Resolve 后的反射 radiance。Hash grid 只计算几何 hash，不访问缓存，Off 仍可用。

raygen 的 miss 分支先于 primary SHARC debug 分支，原先两个表面通道的背景都会累加
sky，容易误认成缓存数据。现在只在这两个通道的 primary miss 跳过 sky；此前的
GBuffer/DLSS miss 输入、空 ReSTIR key/initial 写入仍执行。普通 sky 与 secondary
miss 的行为不变，Query depth 沿用自己的黑色未命中输出。

修复归属 RtSharc 与现有 raygen 分支；没有新增 helper、资源、ABI 或同步机制。
RT pass 的入口依赖保守保留，但删除了“Off debug 仍会读 cache”的过期说明。

## 扫描结论

| 通道 | 来源与结果 | 状态影响 |
|---|---|---|
| Hash grid（19） | primary position / 几何法线的 hash 着色，miss 黑色 | 不读取缓存；primary hit 提前退出并写空 initial |
| Cache radiance（20） | Update/On 当前 resolved 反射 radiance；Off、miss、冷缓存为零 | 只读 Query；不为 debug 单独重置缓存 |
| Query depth（21） | 正常路径首次 Query 终止深度：黑=无，绿=1，黄=2，红=3+ | 不增加 Query；Off/Update 不命中 |

UI 直接修改 RealtimeRenderSettings，mode 的三种映射与 shader 一致；没有第二份缓存
状态。Off/无 TLAS 的提交切断历史、Update↔On 共享维护签名，沿用 B20-b3。
维护 pass 在主路径前执行，debug 不改变 Update/Snapshot/Resolve 的调度或随机种子。
相机/resize 不清世界空间 cache；后续复用仍取决于场景与配置签名。

primary 表面 debug 会停止普通主路径并生成空 initial；ReSTIR temporal/spatial 仍然
运行，不等于保留与 Final 完全相同的 reservoir。final phase 对这些通道直接返回，
不会覆盖 debug 图像或追加 primary DI。不能把这些观测模式宣称为零业务影响。

Cache radiance 使用 SDR radiance 显示变换，hash/depth 属数据通道；只有 Final 更新
自动测光。当前 DLSS 开启时仍消费该帧输出，debug 选择不是 DLSS reset 信号，因此
最终显示可能包含重建/时域影响；原始语义以 single-frame-rt 为准，未做 SDK 画面对比。
Offline 的 UI 过滤与 normalize 都拒绝三个 SHARC 通道；Renderer 层没有把它们暴露
为 Runtime 公共配置。
