## 已确认的 owner 与范围

- `truvixx-utils` 是内部 STATIC Windows helper，无独立 C ABI；PathUtils / StringUtils 的直接消费者主要是 Streamline。此处核对实现与借用契约，调用方异常/回调/初始化生命周期交 B04-c。
- `TruvixxScene` 持有唯一 `SceneImporter`；Assimp::Importer 持有原始 aiScene 和顶点，SceneData 持有转换后的 UV/index/material/instance。load 后 C API 只读，free 释放全部存储。
- `truvis-assimp-binding` 只生成 raw FFI；安全使用约束收敛在 `TruvixxSceneGuard` / `TruvixxSceneReader`，不是另缺一个通用 wrapper。每个 Rayon task 创建自己的 scene，返回 RawSceneData 前把数据复制为 Rust owned Vec/PathBuf；没有共享 importer 或把 raw pointer 传回 runtime。
- 实际检查 utils 两组源/header、Assimp importer/数据结构/base 类型/C API 全部头和实现、CMake 依赖、binding build.rs/lib.rs、asset worker/reader 的直接调用路径。材质模型、格式语义、资产同步与 slot 生命周期留给 B08–B11。

## 修复前发现与处置

1. **P1，加载异常越过 C ABI 并泄漏 handle，已修复并验证。** `truvixx_scene_load` 的裸 new 和 `SceneImporter::load` 均可能抛 C++ 异常；Rust 的 catch_unwind 不能代替 C++ 异常边界。用实际 module.cpp 配临时可抛异常 importer：构造抛出时 escaped=1/live=0；load 抛 std::exception 或未知异常时 escaped=1/live=1。修复在 C API 加载入口用 unique_ptr 管理，catch 全部 C++ 异常并返回 null；普通 importer 失败继续返回可查询错误的非空句柄。
2. **P2，UTF-8 路径承诺未实现，已修复并验证。** Rust 传 UTF-8，C API 却隐式用窄字符串构造 filesystem::path；Windows 下采用 ACP。真实 DLL 在 ACP=936 时 ASCII OBJ 成功、中文/emoji 目录失败。importer 的 path.string 与纹理 path 拼接也同样走窄编码。现使用 C++20 u8string 构造路径、u8string 输出编码，保持 Assimp 5.4.3 的 UTF-8 DefaultIOSystem 契约，不改格式/单位转换。
3. **P2，纹理路径静默截断，已修复并验证。** 真实 OBJ/MTL 输入中的长纹理路径被截成 255 字节，material_get 仍返回成功，Rust 随后把错误路径当真实文件名。固定 C ABI 数组先保留，写出前检查路径容量，不可完整表示则失败且不写 out；display name 的原有有界截断不扩展为路径策略。
4. **P2，相对模型目录重复拼接，已修复并验证 native 输出。** importer 将 dir_/texture 拼接后仍可能输出相对路径，`AssetSystem::register_scene_texture` 又按 scene parent 拼接一次。现在 importer 的 dir_ 取 absolute(path).parent_path，输出外部纹理绝对路径；原路径仍由 Rust RawSceneData 保存。相对路径夹具确认 native 输出正确，未运行完整 AssetSystem 纹理注册流程。

架构预检：修改分别归属 C API load 和既有 importer/path 投影，不新增公共类型、全局错误状态、兼容层或通用 FFI 框架。不改变线程、scene owner、raw pointer 存活期、GPU 或渲染坐标约定。相关说明同步到 cxx/README 与 C API header；每项修复随本报告提交，最多两次。

## 第一项修复与验证

第一提交 `fecd7b69` 修复加载异常。同一 module.cpp 夹具中，构造异常、load 的 std::exception 和未知异常均变为 escaped=0/live=0/handle=0；普通失败仍为非空 handle、is_loaded=false，free 后 live=0。该夹具替换 importer 以确定性注入失败，不冒充真实 Assimp 内部故障注入。

`just cxx-debug` 实际编译和部署通过，更新 Assimp C API DLL/PDB，未改其它 native 行为。构建使用项目既有 VS2022 CMake preset；PATH 中的 Git link.exe 不参与此构建，临时 clang++ 探针显式使用 lld。异常边界不处理非法指针、访问违规或其它未定义行为，也不保证内存耗尽时有详细错误文本。

## 第二项修复与验证

第二提交为本报告所在提交，保证 external texture 路径完整、编码及定位含义一致。实现使用标准 filesystem/C++20 字符串转换，不增加 dependency 或通用 helper，不引入被 C++20 弃用的 u8path 适配。

- `native_probe.py` 调用已部署的实际 Debug DLL：ASCII、中文/emoji 模型目录、中文纹理名和相对模型路径均成功，纹理返回完整绝对 UTF-8 路径；超长路径返回 Fail，812 字节 out 全部保持原哨兵内容。
- `capacity_probe.py` 对真实 OBJ/MTL 验证路径 UTF-8 长度 255 字节成功且 NUL 位于最后一字节，256 字节失败且不改写 out。这里拒绝无法表示的路径，不声称已经支持任意长度的 native 材质路径。
- `ffi_probe.py` 对真实 DLL 验证 null scene、缺失文件、目录和空 OBJ 的失败状态/错误文本/释放；正常 Unicode scene 的 positions/normals/UV/indices 借用数据与 fill 输出一致，输出尾部哨兵未越界，非法 mesh index 不写输出。仅覆盖合法容量，不能据此声称 raw fill API 会检测过小 buffer。
- 临时 C++ static_assert 核对 aiVector3D 与 TruvixxFloat3 的 size=12、align=4、offset=0/4/8；Mat=812、Instance=324、MeshInfo=20、ResType=4。生成 binding 已有 size/align/offset 编译期断言，`cargo check --offline --locked -p truvis-asset -p truvis-assimp-binding` 通过。实际 Rust reader 不 transmute glam，逐项复制 union 数值；本批没有修改 ABI 字段。
- utils 探针验证中文/emoji UTF-16→UTF-8、空串、fallback 指针借用、Win32 错误文本、executable 绝对目录、目录重复创建和文件占位失败。`StringUtils::to_utf8` / `win32_error_message` 有 Streamline 调用；PathUtils 和 utf16_ptr_or_default 当前没有生产引用，保留为后续清理候选，不据此增加新框架。
- 最终 `just cxx-debug` 编译部署通过；以最终 module.cpp 重跑三类异常探针仍无异常逃逸或残留 importer；空白检查通过。使用本地 vcpkg 的 Assimp 5.4.3 DefaultIOSystem 源码确认 Windows Open 按 UTF-8 转 UTF-16 后 `_wfopen`。未升级第三方版本。

## 未闭合范围与交接

**本首轮的加载/路径修复已完成，Assimp 数据接口仍需 B04-a2 续接，暂不转入 Vulkan：**

- `truvixx_instance_get_refs` 对非空 out 无条件 memcpy；空向量的 data() 可能为空，需补查零长度复制的合法性并修复必要边界。Rust reader 对 mesh_count=0 已提前返回，因此当前正常消费链未触发；不能把这一事实当成 public C API 完整性证明。
- raw fill 接口没有容量参数，query→allocate→fill 依赖 caller 前置；借用视图由 scene 持有，不能与 free 并发。继续检查空记录/可选属性、引用数组的一致性、typed view 的 C++ 别名/布局前提与 public header 的契约说明。当前布局相等和正常模型输出不是全部合法输入的证明。
- StringUtils 的 FormatMessage buffer 在后续 string 分配抛异常时没有 RAII 保护；PathUtils 的 `.` fallback 与 Streamline 默认日志路径策略也需结合实际 SDK 初始化边界判断，交 B04-c。这里没有做内存耗尽或 loader 失败的真实进程实验。
- Assimp 嵌入纹理、其它 texture channel、反射率到 metallic、UV fallback、非三角 primitive、空 scene 处理及 FBX 单位/轴向不是本轮格式验收，交 B08；已有 FBX 转换未修改。native importer 构造后 load/clear 再建 importer 的冗余可在该处复核，不改变尚未检查的重载契约。
- 未执行 Release 全量构建、GPU 渲染、真实 FBX/其它格式资产回归或完整 worker→AssetSystem 集成。Native 成功读取 OBJ 不等于贴图文件存在或最终场景加载成功。
