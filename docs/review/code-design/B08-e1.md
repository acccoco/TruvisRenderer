## 发现与修复

- **P1：固定临时目录会删除已有数据，已复现并修复。** 原先将输出目录下的
  `_source_textures` 当作私有目录，成功后无条件 rmtree。即使没有 staging 输入，用户
  已有目录也会被删除；源 scene 位于其中时同样会删除。本次以 TemporaryDirectory
  创建每次独有的目录，仅回收本次所有的工作目录。
- **P1：输出与源路径重叠，已复现并修复。** 入口拒绝输出包含 source scene，staging
  拒绝输出与 texture root 互为祖先；Blender 加载后、任何转换写入前检查已知源 image
  路径，考虑 Blender 相对路径和 linked library。发布前检查所有目标不会经 symlink/
  目录重定向逃出输出根，目标与其父目录类型必须允许写入。不是对任意 Blender 插件的
  文件行为作沙箱保证，也不处理检查与写入间的外部并发改名。
- **P2：失败先删除上一版 manifest，已复现并修复。** 原先启动 Blender 前 unlink
  scene.gltf；现在 worker 在私有 result 目录完成导出，已有 GltfValidator 检查资源和
  引用通过后再发布。正常资源先替换、manifest 最后替换，成功标记只报告最终路径。
- **P2：同 stem 的图片覆盖，以及材质名参与文件路径，已修复。** staging 明确拒绝
  casefold 后同名的不同源文件；扩展名大小写统一识别。烘焙文件名使用 material index /
  channel，不将包含路径分隔符的材质名拼入写出路径。非正 texture-size 和不支持的
  source suffix 在创建转换内容前失败。

owner 仍是 SceneExporter，复用已有 GltfValidator，无新通用事务框架/兼容层。host 负责
临时目录与发布，worker 只在指定工作目录产生结果；CLI 的公开参数不变，新增 publish-dir
仅供 worker 校验最终输出边界。validator 只由宿主 Python 导入，避免依赖 Blender 的
脚本模块搜索路径。runtime、资源 ABI、线程和 shader 均不变。模块说明已同步。

## 验证

临时夹具与日志位于 `.temp/code-design/B08-e1/`：

- `host.py` 执行真实基准/当前 SceneExporter，仅替代 Blender 子进程：各 15 案例，
  共 30 次通过。覆盖旧固定目录保留、worker 失败/缺失 manifest/缺失资源、scene 与
  texture root 重叠、同名贴图、缺失 root、错误 suffix/尺寸、大小写图片转换、目标目录/
  父文件冲突。旧版的删除、覆盖或误成功按案例复现；新版失败保持原 manifest/source。
- `redirect.py` 实际创建目录 symlink，验证输出 textures 指向外部目录时，在发布任何
  文件前拒绝，外部源图和旧 manifest 不变；测试后只回收夹具自有临时目录。
- 实际 Blender **5.2.1 LTS / 9e2066aef7ef** 后台独立进程：普通 cube 导出、材质名
  `../../escape` 的程序材质 CPU 烘焙/导出成功，生成 PNG 名称受控；含发布目录源图的
  `.blend` 明确失败。各例源 blend 校验值不变，源图字节与用户已有 `_source_textures`
  文件保持；本次工作目录回收。实际生成文件由 validator 检查，不声称图像保真通过。
- 无仓库单元测试，Python 语法及空白检查通过；未运行 Truvis GPU 或 Rust 构建（无 Rust
  改动）。worker 的独立成功标记不等于最终发布成功，最终成功标记由 host 产生。

剩余边界：最终发布为逐文件 replace，不是多文件事务。发布途中 I/O 错误、进程终止或
并发导出可能留下新旧混合的资源；未承诺恢复旧版本。其它已有文件不删除，历史不再引用的
资源可能保留。validator 当前只检查部分引用和外部路径，不能保证当前 importer 接受所有
导出字段，详细审阅留给 B08-e2。
