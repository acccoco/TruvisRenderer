## 上传结果交接

- **P2，已修复：准备失败消费了当前 CPU 分布。** GpuSkyStore 原来先 pop，再将
  SkyDistributionBuild 按值交给上传队列；创建、映射或录制失败时，queue 会回收未提交
  native 资源，但 CPU 分布已丢失，latest_request 仍使同一 texture 被去重。现在队列
  借用 build，store 在提交成功、明确拒绝或 uniform fallback 处理后才消费队首。
  准备 unwind 保留当前和后续结果，不复制大型 entries，也不新增重试队列。
- 原生 submit 已开始后的 GPU owner 仍属于共享 queue，其 submission_uncertain 阻止
  继续发布；CPU 结果保留不表示允许重试不确定提交。明确返回 Err 时仍清除请求身份，
  允许既有 observe 路径重新请求；没有把 native panic 转成可恢复错误。
- **P3，已修复：地址契约检查晚于 native owner 移交。** GPU completion 先检查请求
  身份及有效 buffer 地址，再从完成队列移出。地址断言失败时 buffer 仍由完成队列持有。
  当前合法 producer 已设置 SHADER_DEVICE_ADDRESS，此项针对内部契约破坏，未观察到
  正常上传产生缺地址 buffer。过期结果仍先销毁资源，再记录诊断。

沿 SceneStore→RenderAssetSystem→GpuSkyStore→共享 queue→RenderWorld 核对：CPU Ready
不等于 GPU 发布；CPU/GPU 完成都必须匹配 request id 和完整 texture handle，A→B→A
不能复活旧 request。切换 texture 立即撤下旧分布，旧 buffer 交 registry 按 FIF 延迟回收。
真实 image 已 ready 而新分布未 ready 时使用真实 image + uniform sphere distribution；
关闭环境保留资源、禁用分布，brightness revision 不要求重建分布。

临时夹具 `.temp/code-design/B10-d2/{run.py,mocks.rs,main.rs}` 编译实际完整共享上传队列、
GpuSkyStore 的状态对账/CPU 提交/GPU 发布/binding 方法与实际状态字段；RHI、registry、
texture resolver、builder 完成缓存及 shader payload 为替身。上传/身份/正常 binding 的
22 类场景在两种断言配置下对照基准，共 88 次运行符合预期（独立第一提交日志见
`.temp/code-design/B10-d2/first/`）。该提交的 Runtime 编译及空白检查通过。覆盖：

- target/stage 创建、映射、command 创建/录制/屏障/submit-info/signal 准备失败，临时
  GPU owner 全部回收；新版 CPU 结果保留并在受控重入后成功提交，旧版当前结果丢失。
- submit 异常后 pending 保持完整、禁止 poll；仅在夹具明确模拟等待成功后执行关闭。
  空 entries 拒绝、拒绝诊断异常、uniform fallback、CPU 旧 id/handle 分别覆盖。
- timeline 未完成不发布；完成后原样交付尺寸/身份。A→B→A 和不同 generation 值拒绝
  旧结果。发布诊断失败仍保留已安装状态与 pending 通知；过期释放诊断不丢失后续结果。
- 地址断言失败的新旧 owner 保留差异；退役记账在 frame 12 保留、13 收敛，实际资源仍
  在 registry；分布版本饱和时，已有 state_changed_pending 仍能通知这次发布。

已检查当前 builder 生成非零、受 4096x2048 上限约束的 entries，未增加重复形状验证层。
不改变 Alias/PDF 算法、公共 API、shader ABI、barrier 或 queue 顺序；本批夹具不证明
真实 GPU 同步、数值分布、ABI 布局或驱动行为。跨 queue 同步仍由 B10-e 核对。

## Binding 通知

**P2，已修复：解析失败提前确认了变更。** update_sky_binding 原来在 readiness 查询前
取走 state_changed_pending，在切换诊断前推进 using_real_sky，在 resolve_texture 前
推进 last_active_distribution_version；后续失败会遗漏尚未交付的历史失效信号。现在先
完成解析与诊断，再一起推进这三个状态并返回 binding。成功返回后下一次无变化不重复
报告 changed，不增加额外 revision 或确认协议。

最终夹具增加 readiness/resolve 异常、进入/离开真实 sky 的诊断异常四类；故障注入后
恢复调用，旧版遗漏 changed，新版交付一次且随后不重复。**最终 26 类 / 104 次进程
运行**符合预期。这里是受控失败边界；当前 GpuTextureStore resolver 是只读表查询，
没有声称正常查询必然触发这些异常，也没有新增 Runtime panic 恢复能力。

Runtime 和 app 的 `cargo check --offline --locked` 均通过，无新增编译警告；
`git diff --check` 通过。未运行 GPU、图像回归或完整构建，未新增仓库单元测试。
临时 fixture 替换了 shader entry/handle 类型，不能据此验证真实 ABI 或 slotmap allocator；
真实生产方法的完整身份相等比较经源码核对，夹具只覆盖不同身份值不能相互替代。

## 交接

本轮保留 worker 负责 CPU 合并、共享 queue 负责 GPU 提交、store 负责身份与发布的分工，
未发现需要引入统一调度框架的证据。distribution version 当前饱和递增，发布本身另设
pending 变化，因此不在本轮扩展全局版本策略。Alias 数值/PDF 一致性留在 B18。

通知只保留到 update_sky_binding 成功返回：RenderWorld::prepare 随后还会上传 material、
准备 instance 等，后续失败依然可能丢失整次结果，交 B11/B12 继续核对。借用 CPU entries
也不承诺 uncertain submit 后重用 queue，原有 native owner/等待契约不变。

后续复核：binding 返回后的变化提示已由 [B11-a2](B11-a2.md) 立即写入 RenderWorld 的
pending history，并保留到 prepare 提交确认；本批叶子验证保持，整帧恢复仍由后续批次核对。
