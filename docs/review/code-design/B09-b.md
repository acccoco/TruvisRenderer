## 局部问题与修复

- **P2：instance transform 缺少 World 边界校验。** 导入器已经拒绝非有限、非 affine、
  奇异或 inverse 非有限矩阵，但直接创建与编辑可以绕过；RenderInstanceTable 随后直接
  求 inverse。校验归属 `Instance`，SceneStore 在发布前调用，不借用会拒绝 shear 的 TRS
  分解。错误增加 `SceneEditError::InvalidInstanceData`；现有调用方没有遗漏的穷举匹配。
  保留 stale handle 优先、合法 shear/负缩放及 no-op 行为。
- **P2：MaterialData 校验遗漏 class/coverage 内部参数。** 公开枚举允许绕过构造器，
  NaN/无穷可进入 World 与 GPU material，破坏相等比较与版本语义。现沿用既有类别构造器的
  可表示范围校验 opacity [0,1]、IOR >= 1、非负 radiance，并检查 GPU 投影相加的 emission
  是否溢出。coverage 只要求有限非负，保留 [B08-c3a](B08-c3a.md) 已确认的 cutoff > 1。
  不改变普通因子的现有有限性边界，不引入 OpenPBR 模型迁移或新 shader 算法。

沿用 World 的 CPU owner、依赖方向、反向引用和版本机制，不新增通用验证框架。
不改变线程、GPU ABI 或渲染算法；最终全局修改仍只在 B26/B27 提方案。

## 验证与交接

`.temp/code-design/B09-b/{run.py,probe.rs}` 编译基准与当前 World 源码快照，调用实际
GameWorld 编辑路径（未替换 scene/asset store）。8 类非法矩阵的创建与更新共 16 条对照：
旧版均接受，新版拒绝，且实例内容、引用、版本与变更集合不变。6 类合法矩阵覆盖 shear、
负缩放、小尺度及 no-op；成功编辑只推进一次版本，stale handle 优先于非法矩阵错误。
`cargo build --offline --locked -p truvis-world` 与现有 4 个 lib 测试通过，未运行 GPU。

15 类非法材质在注册/更新两条路径共 30 条新旧对照通过：旧版接受，新版拒绝且保持记录数、
材质内容、纹理反向引用与 revision/scene version。覆盖 class 的 NaN/无穷/越界、cutoff
负值/非有限值，以及两个有限 emission 的和溢出。8 类合法材质覆盖 HDR、负 normal scale、
IOR=1、opacity 两端、cutoff=0/>1/大有限值；写回相同内容不推进版本。

引用/编辑夹具在新旧两版均通过，未发现需要重构索引的证据：

- 共享材质需要满足每个 instance 的每个对应 submesh 的 UV 要求；拒绝时不迁移纹理引用。
- 多个 material slot 重复引用按 instance 去重；rebind、删除和旧 generation 不残留引用。
- instance 成功编辑只推进对应 revision 并记录候选；material 内容变化走自己的 revision，
  不伪造 instance 编辑。后续唤醒和 GPU prepare 仍需 B10/B11 验证。
- 被引用的 mesh/material/texture 删除失败；禁用 sky 仍保留 texture 引用。
- sky enabled/brightness 原子编辑、非法 brightness、相同值、旧 texture handle，均保持
  对应失败/no-op 语义；成功组合编辑只推进一次 sky/scene 版本。

第二项后的现有 4 个 lib 测试与 `cargo check --offline --locked -p truvis-app` 均通过，
后者覆盖 World、Runtime、Renderer 与 App 的调用链；`git diff --check` 通过。夹具只验证
CPU 语义，没有运行 GPU 或宣称 temporal history、TLAS、最终画面已通过。
