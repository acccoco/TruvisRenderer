## 顺序与确认

| 边界 | 当前实现事实与保持的约束 |
|---|---|
| 帧开始 | Runtime::begin_frame 先等待当前 FIF 的旧 timeline，再 reset command/清理资源；等待失败不会继续复用 |
| update → prepare | Loop 先消费输入、update，再同步内部 extent；prepare 后 render ctx 无 CPU world 可变借用 |
| prepare | prepare_render_world 的 graphics submit 正常返回后才 commit_uploaded_frame；这是上传版本确认，不是 GPU 完成 |
| 主视图 | Renderer::render 正常返回 bool 后才 finish_rendered_frame；true 推进实例历史，false 清理帧内记录而保留上一实际主视图历史 |
| present | 发生在历史确认之后；present 异常不会回滚此前确认，也不会执行 end_frame |
| 无 acquired image | update/extent 同步之后直接空 signal submit → end；不 prepare、raycast、render、确认历史或 present |
| 零尺寸/debounce | run 外层暂停，尚未 begin_frame；没有空 signal，也不推进帧号 |
| 正常退出 | wait_idle → Renderer shutdown → Runtime destroy；后者仍有自身安全点要求 |

入口：`engine/e50-render-loop/truvis-render-loop/src/render_loop.rs` 的 `run:38`、
`run_frame:147`、`shutdown:271`；Runtime `begin_frame:362`、`prepare:422`、
`finish_rendered_frame:430`、`signal_current_frame_complete:543`、`end_frame:557`。
行号是本批定位提示，后续以符号和当前代码为准。

TruvisRenderer 在同一次 graphics submit 中提交 compute/present 两份工作，最后 graph
signal frame timeline；只有加入主视图场景 pass 才返回 true。两个 sample 同样提交
timeline，但返回 false。B11-b2 的实例版本确认约束仍成立，本批未重写该算法。
after_prepare 的同步 raycast 依赖已提交更新的同队列顺序及自身 fence；不要求 prepare
CPU 返回时 GPU 已经完成。相机/DLSS 等 Renderer 私有历史留给 B14–B16 独立检查。

resize 前设置的 history_invalidated 会在 begin_frame 重置，但当前 Truvis on_resize
另行重置 DLSS/view_accum/ReSTIR；不能仅凭该赋值认定现有 resize 丢失历史重置。
跨帧提示是否应有更窄契约交 B12-d/B14–B16，本批未引入第二份持久状态。

## 正常退场前日志（P1，已确认并局部修复）

原 `run` 在退出循环后、shutdown 前调用 info 日志。如果日志后端 panic，整个显式
关闭序列被跳过；不能用 Rust 字段 Drop 推导 Vulkan root/surface 已关闭。该调用不
承担资源或业务职责，直接移除；保留日志会引入额外异常边界，收益不足。

变更只去掉该诊断调用，正常关闭顺序不变；没有泛化 cleanup guard、shutdown trait
或新 owner。模块 README 与 design 同步区分零尺寸暂停/无 image 跳帧、提交/GPU 完成，
修正 idle 与 Renderer shutdown 的图示顺序，并移除 Runtime 累积计数的过期注释。

## 未闭合失败路径与保留理由

- **P1，已确认，B13/B27**：init/frame/shutdown 中途 panic 会跳过后续关闭。Runtime
  仅在 Renderer init 返回后存入 Loop；即使提前保存，Renderer 部分初始化与未知 GPU
  submit 的完成前置仍不明确，不能据此安全统一 destroy。RenderThread catch 包围整个
  Loop，finished 是线程状态，不是 surface 回收凭据。其错误日志还可能打断 finished
  发布，交 B13 核对真实宿主通知与 join，未扩大本批修改。
- **P1，已确认，B12-d/B27**：WSI 完成凭据仍独立于 graphics timeline/device idle；
  延续 B05-d2/B12-b2，未因上述顺序检查关闭该项。
- **B13**：输入 channel 与 Loop Vec 无界；零尺寸/debounce 仍 drain 输入但不消费。
  积累路径可从代码确认，实际增长速率、事件合并/背压策略尚未验证，不临时丢弃事件。
- 阶段内部日志、Renderer shutdown、Runtime 中未分类关闭异常仍可中止流程。本次
  修复只覆盖正常退出入口的一条日志；不声称解决任意日志后端异常或 native 二次 panic。

没有发现需要合并 Loop/Runtime/Renderer 的证据：固定调用顺序、资源所有权与具体
渲染策略分别承担不同职责。两条 end_frame 路径对应不同提交前置，不为消除几行重复
增加调度抽象。new/destroy runtime 的私有薄包装不单独构成有验证价值的设计故障。
