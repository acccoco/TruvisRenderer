# B08-d3：native 几何、静态场景与生命周期

> 历史说明：本文项目 hash、提交次数及“本报告所在提交”均按压缩前历史解释，实验引用保留为“压缩前证据基准”；第三方版本不变。当前分组见[提交压缩映射](commit-squash.md)。


基准：`refactor` 的 `7b364475`。承接 B04 native 所有权、B08-d1 Rust payload 校验与
B08-d2 材质边界。实际依赖为 Assimp 5.4.3，已读取锁定 vcpkg 源码的 GenFaceNormalsProcess、
CalcTangentsProcess、FBXConverter 及本项目 C API/SceneData/SceneImporter。

## 静态几何转录，已修复

- **P1：未表达的形变与顶点色被静默丢弃。** 复制前拒绝含 bones、anim meshes 或颜色
  通道的 mesh。即使权重为零或颜色全白也不假装具备相应载荷；未新增 skin/morph/顶点 ABI。
- **P2：非三角 face 被跳过，计数存在截断风险。** 所有 face 必须是三索引并在顶点范围内，
  face_count <= UINT32_MAX/3 后才 reserve/copy。node 发布前检查实例计数及 mesh 引用，
  mesh 复制前检查 material 引用，避免 native 在 Rust 校验前已解引用坏引用。
- **P1：纹理需要 UV0，缺失却补零。** 消费颜色/normal 外部路径时必须有二维 UV0；
  无贴图的 mesh 保留补零行为。非二维 UV0 拒绝，额外未消费的 UV 集继续忽略。

检查归属既有 SceneImporter 私有方法，错误经 bool/last_error 传播；只有全部转换完成才
置 is_loaded=true。C API、资源 owner、线程和 GPU ABI 不变，scene guard 仍负责最终释放。
输入更严格，不代表合法外部文件本身错误；运行时不支持的载荷需显式失败。
裸指针的实际有效性仍依赖 Assimp 的输出契约，本批不是任意损坏 aiScene 的内存安全验证器。
总数上限保护 u32 表达，不是 CPU 内存预算；未尝试分配数十亿个实例。

## 现有语义与验证

临时夹具位于 `.temp/code-design/B08-d3/`，不加入仓库单元测试。

- `geometry.cpp` 对照完整基准/当前 SceneImporter，18/22 个案例通过。覆盖有效数组与
  tangent 复制、UV0/未消费 UV1、缺属性、skin/morph/color、非三角/越界索引、材质引用、
  多 mesh 引用顺序、矩阵列主序、真实 hard-edge OBJ/带贴图无 UV/线段 OBJ。
  极端 face_count、空指针和坏 node 引用只在修复后执行，避免旧实现的大分配或非法访问；
  超大计数夹具只检验早期拒绝，不冒充巨型文件导入。
- `files.cpp` 对照基准/当前 actual Assimp DLL，共 7 个文件案例通过。项目 cube-coord 与
  cornell-box FBX 仍成功；Assimp 上游 box（有顶点色）及 animation_with_skeleton、合成
  morph/color glTF 由旧成功变为明确失败。直接传入 Assimp 的 glTF 只用于此边界验证，
  不改变生产 worker 的 Rust glTF dispatch。
- 两个项目 FBX 的 UnitScaleFactor=1；所有节点列主序矩阵与原始 Assimp world 前乘
  scale(0.01) 数值一致，局部顶点未二次缩放。与 [5.4.3 FBXConverter](https://raw.githubusercontent.com/assimp/assimp/v5.4.3/code/AssetLib/FBX/FBXConverter.cpp)
  的 root 单位/轴向转换一致；未覆盖所有 exporter、单位值和轴向组合，未验证 GPU 画面。
- [GenFaceNormalsProcess](https://raw.githubusercontent.com/assimp/assimp/v5.4.3/code/PostProcessing/GenFaceNormalsProcess.cpp)
  生成逐面法线；真实两个正交三角形 OBJ 产出 6 个顶点和不同 face normals。native 仍保留
  CalcTangentSpace 的 XYZ 供现有 C API；Rust 因缺 handedness 不消费它，使用零标记走 shader
  重建。未增加 CPU MikkTSpace，也不把两种切线约定视为已验收等价。
- 动画 glTF 的原始 aiScene 有动画、相机、灯光；输出只保留静态 translation=2，未采用
  动画 key=20/30。当前能力是静态 mesh 场景，相机/灯光不进入 RawSceneData；范围已文档化。
- `just cxx-debug` 与 asset/assimp-binding/world 的 offline locked check 通过，未运行 GPU。

几何修复提交：`6b422d34`。实际部署 C API 另通过 8 个文件案例，失败时返回非空可查询句柄、
is_loaded=false、mesh_count=0，均对称释放；说明未完成的转换不会通过 loaded 查询发布。

## Importer 复用，已修复

**P3：构造后首次 load 就再次创建 Importer，每次 clear 也重新创建格式插件。**
SceneImporter 的 owner 不变；clear 改为调用已有 Importer::FreeScene，继续清空 owned
结果、借用指针、loaded 状态及诊断。已检查实际 5.4.3 Importer.cpp：FreeScene 删除原始
scene，同时清空内部 error string/exception；不存在为了清除这些状态而重新创建的必要。
当前项目不对外暴露 importer 配置；本次不建立池、共享 importer 或跨任务缓存。

`lifecycle.cpp` 对照 `6b422d34` 与当前实现，34 次操作通过：重复空 clear、正常加载、
文件缺失、解析失败、geometry 拒绝、material 拒绝，以及每种失败后不手动 clear 直接
重新加载，再显式 clear。当前 importer 地址保持，旧版每次替换；成功结果一致，clear
后 aiScene、内部 scene、输出 vector 和诊断都清空。没有用时间测量宣称性能收益。

最终 `just cxx-debug`、8 个实际 C API 文件案例及 asset/assimp-binding/world 的 offline
locked check 通过，空白检查通过。未运行 Release 或 GPU；native/CPU 验证不能代替图像回归。
