## P1：SHARC debug 留下旧 initial

两条 primary-hit SHARC debug 分支写当前 surface 后 break，但 initial 直到正常 NEE
阶段才生成或清空。后续 ReSTIR pass 不因这些 debug channel 而跳过，因此可把 FIF
槽位的旧候选配到当前 surface；final 不覆盖 debug 图像不能消除历史污染。

架构预检：修复归属 realtime raygen 的出口编排，复用 RtReservoir::empty/store_initial，
合并 HASH_GRID/CACHE 的相同出口。ReSTIR owner、资源、ABI、pass/线程/同步顺序不变，
没有新增 helper 或 CPU debug history 状态。设计说明更新到 radiance-cache-and-debug。

修复在 SHARC debug 返回颜色前清空 initial，两个颜色函数仍互斥调用。普通路径不增加
写入，不改变 surface-only、miss、EMISSIVE、delta 和正常候选生成的原有处理。
对应提交 `542b9fee`。

临时验证位于 `.temp/code-design/B19-d3/`：

- `check-raygen.py` 抽取实际 main_ray_gen、surface debug 判断和 ReSTIR primary 替换
  条件，mock TraceRay、材质/光照、图像和 SHARC。4 modes × 22 channels × 5 primary
  事件 × 5 类终止 × 16 深度共 35,200 组合，未写 initial 的 1,920 组合修复后为零。
  每个启用 ReSTIR 的 primary 路径只写一次 initial；Off 不写。另核对 11 个维护/非 path
  dispatch 不访问 primary 输入。O0/O2 通过；前后路径输出、trace 次数、primary 输出、
  新候选与 SHARC 颜色函数调用记录逐字节一致。并非实际 ray tracing 或材质正确性验证。
- `check-handoff.py` 从当前源码重新提取 reservoir 接受、计数、归一化、pack/unpack 和
  temporal 逻辑，复用既有 CPU 资源 mock。1,560 个 debug 帧与 260 次正常恢复检查通过：
  空 initial 不增加 M，合法历史随帧推进年龄，超过 8 后拒绝；reset/版本/class mask/
  几何不匹配拒绝历史，正常恢复重新生成 initial。O0/O2 一致。几何匹配和 visibility 是
  mock，不代表动态场景实测；初次夹具编译遗漏 Slang out/inout 到 C++ 引用的转换，
  修正夹具后通过，生产代码未因此改变。
- `just shader` 1 编译、30 复用，两个 binding crate 构建通过；Realtime raygen 经
  `spirv-val --uniform-buffer-standard-layout` 校验通过。既有 E41035 条件 candidate
  初始化告警保留。未改 Rust/ABI，未重复完整 App 构建或 GPU 图像验收。

源码复核：SHARC query 的 depth==0 守卫禁止 primary 提前终止；后续 query、材质完成、
roulette 和末顶点退出都发生在 primary 输入完成之后。max_depth 固定为 16。history
仍只来自 temporal，不把 spatial 结果反馈；debug selection 本身不改变 proposal class
或 surface target，因此不额外扩大 CPU reset 签名。持续 debug 可以耗尽历史年龄，
关闭 debug 后从新 initial 恢复，这是当前明确行为，不承诺切换后噪声/画面连续。

## P2：final debug 计算未被消费的着色结果

复核 final dispatch 发现：原实现先执行 shade_final_reservoir，再判断 initial weight、
temporal valid 和非 ReSTIR debug 的输出分支，导致这些通道计算不用的重建/BRDF/visibility。
现由 RtRestirDI::run_final_phase 按消费方分支读取 reservoir；最终着色只用于正常输出
与 final contribution 通道。普通 surface/path debug 直接保留 path 输出，InitialOnly 的
temporal debug 仍取空 reservoir。算法、资源、ABI 和 pass 顺序不变；此项与本报告所在
提交一致，不修改 temporal/spatial/history 写入或正常渲染的最终 visibility。

- `check-final-dispatch.py` 抽取当前与修复前的实际 final 分支和 mode selector；mock
  reservoir image 和最终着色返回值。3 modes × 22 channels × 8 valid 状态 × 5 weights
  × 4 ages 共 10,560 组，前后输出按十六进制浮点记录逐字节一致，O0/O2 一致。
  最终着色函数调用 10,560 → 960，只留下两个消费通道；新版本每次最多读一组 reservoir，
  InitialOnly temporal debug 不读旧 temporal 图像。不是实际 shadow ray 次数或性能测量。
- selector、shade_final_reservoir、temporal/spatial dispatch 的函数体与首个提交完全相同。
  源码追踪被省略的着色链只进行重建、只读 RayQuery/alpha 检查、BRDF 和局部运算，
  不推进随机序列或写回 reservoir/cache，故无需保留其执行副作用。
- 修改 shared shader 后 `just shader` 24 编译、7 复用，两个 binding crate 通过；
  Realtime/Offline raygen 的 SPIR-V 校验通过。既有条件 out-candidate 告警仍在；
  空白检查通过。未增加永久测试，未执行 GPU 画面或性能验收。
