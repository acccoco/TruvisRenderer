# B08-c2c：scene 层级与变换

> 历史说明：本文项目 hash、提交次数及“本报告所在提交”均按压缩前历史解释，实验引用保留为“压缩前证据基准”；第三方版本不变。当前分组见[提交压缩映射](commit-squash.md)。


基准：`refactor` 的 `1b33bcb0`。核对 GltfSceneReader、gltf/gltf-json 1.4.1 的 scene
与 Node validation、RawSceneInstanceData、AssetSystem 和 RenderInstanceTable。

## 发现与局部方案

- **P1：层级引用有效不保证森林合法。** 库不检查循环、多个 parent、重复 child/root
  或 child 被用作 scene root。原递归会重复发布实例，循环可直接造成不可展开的栈溢出。
  现在资源 IO 前验证整个 node 声明森林，允许同一 root 在不同 scenes 重用。
- **P1：合法深层级同样会耗尽调用栈。** 实例复制改为显式栈，并反转每次压入的 children，
  保持前序、兄弟顺序、primitive 顺序以及 parent * local 的世界变换累积。
- **P1：变换和静态载荷能力未封闭，已修复。** matrix/TRS 互斥与单位 quaternion
  没有检查，局部 shear/projective 和累计非有限值可进入 RawSceneData。GPU mirror 直接
  对 world transform 求逆，不能靠编辑器可选的 TransformTrs 分解阻止非法发布。选中 node
  的 skin 或非零 morph weights 当前也未被消费，不能当作已成功导入形变后的实例。
  现在在被选中 node 的局部变换求值/实例发布前拒绝这些输入；全零有效 morph weights
  保留基础网格，node weights 优先于 mesh defaults，并检查 target 数量与权重长度/有限性。

规范依据：[glTF Scenes、Nodes and Hierarchy、Transformations](https://registry.khronos.org/glTF/specs/2.0/glTF-2.0.html#scenes)
（页面 2.0.1，commit 8e798b02d254cea97659a333cfcb20875b62bdd4）。每个局部 matrix
必须可表示为 TRS，但不同 node 累积可产生 world shear，不能将二者混为一谈。

## 架构预检

检查和迭代留在 GltfSceneReader 私有 impl，无新的公共 API、依赖、线程或 scene owner。
复用库已验证的 JSON 引用和 owned RawSceneData；不建立通用 scene graph 框架。全局森林
预检为 O(nodes + children + scene roots)，visited 计数只用于证明无环，不缓存为运行状态。
临时内存仍随任务释放，不代表已解决总输入规模/队列预算。

局部 matrix 保留原值，以有限/仿射和缩放消除后的列正交性（1e-5 容差）检查 TRS 可表达性，
零列允许存在；不调用上层 World 的编辑器 TRS 分解，避免反向依赖，也不复制其完整分解器。
rotation 使用 glam 的单位 quaternion 容差。累计 world matrix 允许 shear，但须有限；
实际 mesh 实例必须通过当前 f32 determinant/inverse 的有限性检查，避免 downstream
直接 inverse 产生非有限 GPU 数据。该入口不能替代后续 B09/B12 对其他 World 写入路径的审阅。

零缩放是合法 glTF 数据，但当前 GPU instance 契约依赖逆矩阵，所以选中奇异 mesh 实例
明确报“不支持安全发布”，不是宣称格式违法。无 mesh 的 singular group 可以保留；空 group
的大缩放只要最终实例矩阵可正确求逆也允许。未选中节点的局部变换/skin 不会主动求值。

默认 scene 优先、无默认取第一个、空 scene 成功、无 scenes 失败的既有策略保留；glTF
允许无 scene 的实体库，但当前 SceneLoad API 没有独立库导入语义，不在本批扩展。所有
mesh/material 的复制范围保持原状，不将本批改成仅加载可达资源的优化。

## 验证与交接

`.temp/code-design/B08-c2c/fixtures.py` / `run.py` 使用真实文件和完整 Reader，request/result
外壳替代，依赖版本保持锁定。第一项 50 个案例在夹具断言/溢出开关两种配置下通过，
其中变换/形变病例暂保留旧期望。旧版常规对照为 47 个；循环和深层级不在同一进程执行。

旧版自循环与 10,000 层树分别在独立临时子进程验证，均退出为 Windows 0xC00000FD 并
输出 stack overflow 诊断；新版循环返回错误，10,000 层树成功产生叶实例。覆盖了重复
root/child、多父、child-as-root、未使用节点循环、层级检查先于缺失 buffer IO、默认场景
选择、跨 scene 共享 root、空场景、原有引用校验，以及前序和矩阵顺序的直接断言。

第二项完成后共 **56 个案例**在两种夹具配置下通过，旧版常规对照 53 个；另保留上述
两个独立进程的栈溢出证据。覆盖 matrix/TRS 冲突、零/非单位 quaternion、局部 shear/
projective、局部 f32 溢出、world 累计溢出、determinant/inverse 失效；负缩放、非均匀
缩放、单位误差容限、column-major、父子乘法和合法 world shear 的实际矩阵保持。
静态能力覆盖 active/inactive skin、默认零/非零 morph、node 覆盖、长度/多 primitive
target count 不一致、未使用 morph，以及存在有效 animation 时仍保留声明的静态姿态。
每个新版成功实例都检查了矩阵和逆矩阵有限性，没有将这些检查声称为 GPU 画面验收。

两项分别通过 `cargo build --offline --locked -p truvis-asset` 与
`cargo check --offline --locked -p truvis-world`。没有新增仓库单元测试，未运行 GPU。
