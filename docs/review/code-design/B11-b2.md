## 审阅结论与局部方案

- 正常路径中，current/previous 版本对按 FIF 记录，previous 来自上一主视图实际提交，
  不来自该 FIF 上次使用；scene_submitted=false 保留历史。此分工应保留。
- **P2，已修复并验证**：prepare_transform_uploads 在仍可能因容量/诊断失败时写入 pending
  uploads/history，且在调用方 flush/copy/barrier 前就标记待确认；局部失败会留下并未
  完整录制的确认记录。改为返回具体准备结果，成功录制后再移交给 table。
- **P2，已修复并验证**：commit/finish 使用 drain 逐条检查并修改，后项身份或版本不满足
  契约时，前项已经确认，其余记录随 unwind 丢失。改为先完整预检，再推进版本。
- scene pending revision 当前早于矩阵/TLAS/scene root 录制完成，调整到整段 scene
  上传录制成功后登记，仍只由 queue submit 成功后的 commit 确认。

准备结果属于既有 table 职责，携带当前 FIF、copy regions、上传版本和候选历史，不建立
通用事务或调度框架。保留 dirty、generation、稳定 slot 与全局 current/previous 历史。
GPU submit、TLAS 构建、shader ABI 和 pass 顺序保持；部分 command 必须由外层证明
未提交且撤销后才能重录。已录制未确认或 native submit 不确定时仍拒绝重入，退场交 B12。

## 修复结果与设计约束

`PreparedInstanceUpload` 是本次准备结果，持有 regions、FIF、版本对与候选历史；它没有
GPU 资源和自动提交/回滚行为。prepare_transform_uploads 现在只借用 table，stage
内容可能部分写入，但 uploaded_versions 和历史不变。完整结构上传显式强制写当前与
previous，不再先清除已确认的版本来触发写入。

RenderWorld 在实际 flush/copy/barrier helper 成功返回后，才调用 record_transform_uploads
移交该结果。table 用 Option 持有尚未确认的一次录制，包括没有矩阵 copy 的空结果；
这使未确认状态不再依赖 Vec 是否非空。Runtime 原有 submit→commit 顺序保持。

提交确认先核对 FIF、全部身份、current/previous 与候选历史版本，再修改任何副本；
成功后把候选历史移到主视图待确认集合。finish_rendered_frame(true) 同样先验证全部
身份/版本和 dirty 引用，再推进所有历史；false 只放弃本帧候选历史。错误 FIF、身份或
版本是违约输入，夹具主动构造以验证拒绝的完整性，不声称正常 Runtime 会产生这些输入。

scene pending revision 改在 TLAS/scene root 录制成功后登记。TLAS 或 root 失败发生在
矩阵 copy/barrier 之后，table 仍保留已录制状态并拒绝重入，防止把可能存在外层 GPU
工作的失败当作可随意重试的 CPU 错误。本批不新增 discard/reset API。

常规矩阵准备仍只遍历 dirty 身份，完整结构上传才遍历全部 Active；准备结果只保存
本帧变化，不复制 mesh GPU owner 或第二套场景。FIF 副本、上一实际主视图历史和 scene
revision 各有确认边界，保留这些职责，不增加通用状态机或兼容路径。

## 验证

`.temp/code-design/B11-b2/{run.py,mocks.rs,probe.rs}` 编译真实完整 RenderInstanceTable、
RenderData、resolver trait、FrameLabel 与生成 GPU Instance 类型；SceneReadView 和
资源 resolver 使用受控数据。16 类 × 前后两版 × debug assertions 开/关，共 64 次
运行符合预期：

- CPU 打包日志、第二个 slot 的 stage 越界、丢弃准备结果、稳定状态完整重写后的日志
  异常：修复版不留下待确认状态，不推进 uploaded_versions；旧版提前登记记录。
- 错误 FIF、第二项身份删除、current/history 版本变更：修复版先拒绝整批，原记录及
  所有副本版本保留；旧版可部分确认，或不拒绝错误 FIF/版本。
- 主视图确认的后项身份/版本和 dirty 引用违约：修复版保留所有旧历史和候选，旧版
  前项已推进、候选被 drain 丢弃。已录制未确认时，两版都拒绝正常非空状态的重入。
- 正常三 FIF 从 `(1,1)` 经 `(2,1)` 到 `(2,2)`、主视图未提交、空场景、完整记录重写
  和 Pending→Active 重新激活保持；再次激活的 previous=current，平移模型与 inverse
  字段数值正确，副本追平后退出 dirty。

`.temp/code-design/B11-b2/{run-chain.py,chain.rs}` 另编译实际 upload_render_data 和
flush_copy_regions_and_barrier，与真实 table 连接；结构表复制、容量、TLAS、root 和
RHI 用受控替身。11 类 × 两版 × 两种断言，共 44 次运行符合预期：

- raster/capacity/结构 copy、mapped、flush、copy、barrier、TLAS、root 的失败点和正常路径。
- flush/copy/barrier 失败后新版本不登记 pending upload，直接 commit 会拒绝；旧版已经
  登记。仍不得提交该部分 command，夹具没有把再次调用组件等同于 Runtime 自动恢复。
- TLAS/root 失败后已录制记录保留、重入被拒绝；新版本此时没有登记 scene pending
  revision，正常完整录制才登记。所有录制阶段都不直接推进 uploaded_scene_revisions。

`cargo check --offline --locked -p truvis-app`（包含 Runtime）与 `git diff --check`
通过，无新增项目编译警告。没有新增源码单元测试，没有执行真实 GPU copy、完整构建
或画面回归；夹具不证明 native submit 不确定时的恢复、ABI 布局或整体 Runtime 事务。
