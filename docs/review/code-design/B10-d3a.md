## 构造

- **P1，已修复：fallback distribution 的提交前失败遗漏目标 buffer。** 原先 new_ssbo
  后调用公开 transfer_data_sync，后者无法告诉外层 panic 是否发生在提交前，目标缺少
  安全回滚。新增 GfxStructuredBuffer::new_ssbo_with_data，复用 IndexBuffer 的既有
  try_transfer_data_sync / release 模式，仅明确未提交的 Err 回收目标。
- **P1，已修复：view/bindless 或后续 owner 初始化失败遗漏 fallback。** sky 复用
  GpuTextureStore::register_texture_binding 的安装回滚，后者仅扩展为 render_world 内可见。
  GpuSkyStore 先建立 fallback，再在显式边界内构造分布和 worker；后续失败时销毁已成功
  返回的 owner。清理诊断不能覆盖原始构造错误，也不能跳过另一项安全资源的回收。

不新增通用 rollback 框架、不改变资源 owner。RHI 新增一个类型化同步构造入口，已有
公开 API 不变；buffer usage、device-local 偏好、16-byte uniform entry、fallback 颜色
与采样语义保持。未改为 host-visible 常驻 buffer，未增加新的 GPU 同步方式。

**完成状态未知的边界保持：** try_transfer_data_sync 只将提交前失败返回 Err；submit/
wait panic 不转成可回滚结果。GpuSkyStore 只能回收已经成功返回的 fallback image，
不能释放尚未返回、完成状态未知的 distribution/staging。原生失败退场及 debug Drop
二次 panic 的已有缺口继续交 B12/B27，不以本批宣称可恢复或完全无资源遗留。

## 关闭

- **P2，已修复：叶子关闭已完成，组合状态仍未确认。** builder 原来在返回前记录 join
  错误，诊断 panic 时 builder 已关闭但 GpuSkyStore::worker_stopped 仍为 false。
  现在 builder 完成状态更新后返回原始 join Result，store 先确认 worker_stopped 再诊断。
  不新增 worker 重启，不改变 build 自然完成、pending 丢弃和 join 顺序。
- **P1，已修复：单项释放诊断中断剩余 sky 资源回收。** fallback 先撤销 SRV 并清空
  本地句柄，再调用 registry；active、retired 和常驻分布分别完成释放，保留首个异常到
  全部已知安全资源回收后传播。已释放句柄不会在重入时重复注销，不增加隐式 Drop release。
  此方法依然要求 upload timeline 和已发布资源的 graphics 使用均已结束。

最终 owner 夹具共 19 类 / 76 次新旧对照通过：除构造场景外，覆盖 fallback image、
active、两项 retired、常驻 buffer 的单项及组合释放诊断异常与重复关闭。新实现完成
全部释放，旧实现留有未释放后续项。native 释放由替身按真实叶子的“先释放后诊断”
顺序模拟；未注入 allocator abort，也不把不合法 SRV 身份伪装成普通诊断失败。

`.temp/code-design/B10-d3a/run-worker.py` 编译实际 builder 调度与 store stop_worker，
使用真实线程、channel、join 和 logger；只有 Alias 计算/payload 为受控替身。正常完成、
worker panic、关闭诊断 panic 在两种断言配置下对照，另 12 次运行通过。builder 与 store
关闭状态一致，CPU payload 已释放，重复关闭不再 join。合计 **22 类 / 88 次运行**。

最终 `cargo check --offline --locked -p truvis-app`（包含 Gfx/Runtime 依赖）与空白检查
通过，无新增警告。未运行真实 GPU、图像回归或完整构建；owner 夹具不启用 native Drop
断言，以观察旧版资源遗留，不能证明旧版完整程序可捕获这些 panic。未新增仓库单元测试。

## 交接

当前 RenderAssetSystem::new 直接串联多个 owner，后续构造失败时先前成功 owner 尚无
统一显式回收；destroy 先释放 material，再 stop worker/关闭 queue/释放 sky 与 texture/
mesh，前一项诊断可中断后续收尾。这些是当前源码确认的路径，尚未用组合夹具验证。

下一批 **B10-d3b：RenderAssetSystem 组合构造与关闭**。必须区分 queue 的等待失败与
已经完成释放后的诊断失败，不能 catch 后无条件销毁仍在飞的资源。Runtime 更外层的
失败退场继续 B12，跨 queue GPU 同步继续 B10-e，B26/B27 最终全局修改仍只提方案。
