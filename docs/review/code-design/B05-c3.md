## SBT 与 SoA 局部修复

- **P1，SBT 尺寸窄整数溢出。** region count 先转 u32、再乘 stride，handle 查询长度也用 u32 相乘。
  Release 可能截断或回绕，后续仍按原 group 列表拷贝。现在先用 checked u64 算术计算 region、
  总大小和查询长度，再约束 isize 可寻址范围；源 handle 切片的偏移和结束位置也检查溢出。
- **P1，SoA 与额外 UV 容量回绕。** 固定布局的乘法、对齐和加法，以及 mesh 两处额外 UV 尺寸
  原先未检查。现在布局自身检查偏移与 host 范围，新增同职责的 `extra_uv_bytes` 由两处分配复用。
  合法布局与零 UV 集仍保留一个 UV 槽的行为不变，不引入通用布局框架。
- **P2，SBT stride/address 契约不足。** 分配前检查对齐属性和 handle stride 上限；分配后检查非零
  base address、base alignment 和完整地址范围。失败沿已有未提交 buffer 回滚，不进入原始指针拷贝。

SBT 只承载 handle，不携带 user data。raygen 的 size 等于 stride，空 region 仍为零；miss/hit/callable
遵守 handle alignment 和 maxShaderGroupStride。规范依据见
[vkCmdTraceRaysKHR](https://docs.vulkan.org/refpages/latest/refpages/source/vkCmdTraceRaysKHR.html) 与
[VkStridedDeviceAddressRegionKHR](https://docs.vulkan.org/refpages/latest/refpages/source/VkStridedDeviceAddressRegionKHR.html)。
这些局部检查不证明 group 的 shader 类型、pipeline 身份或替换 inner buffer 后缓存 region 仍有效。

## 验证

`.temp/code-design/B05-c3/make_bounds.py/run_bounds.py` 引入实际 SBT 代码、SoA 布局方法与额外 UV 方法；
device、底层 buffer/VMA 采用替身。未执行 Vulkan，未分配巨型 buffer，也不验证真实 shader/GPU。

- 新版 debug assertions/overflow checks 开启和关闭各 10 组通过：正常布局/handle 重排、SoA 与 UV
  大小、超过 4 GiB 的 region 计算、region 溢出、stride 上限、零对齐、非法 group index、地址溢出、
  错位地址及超过 u32 的 handle 查询字节数。正常 SBT 仍为 192 字节，padding 与 region 偏移不变。
- 旧版关闭溢出检查时 SoA 和 region 的极端输入未拒绝；非法 stride/错位地址被 mock 接受。
  旧版开启断言时对应两组出现二次 panic/abort；这是夹具检测到不应成功后触发的清理诊断，
  不声称真实驱动会返回这些非法属性/地址。大 handle 查询用 mock 核对长度后返回错误，不做巨量分配。
- Gfx/Renderer 编译检查通过；未运行真实 GPU。

## AS 未提交构造修复

- **P1，storage/native AS/scratch 的交付缺口。** 叶子 new 原先在 native create 成功后才建立 owner，
  create/naming 失败会遗漏 storage；`new_blas_for_build` 的 scratch 创建失败也遗漏已创建 AS。
  现在空 handle 的 owner 先持有 storage，创建后立即记录 handle；可捕获失败由同一 impl 的私有
  release 回收 AS，再通过已有 buffer 无日志 release 回收 storage，最后传播原 panic。
- **P2，AS 数量窄化。** 两条 BLAS 入口在生成 Vulkan geometry 数组前检查 u32 范围；TLAS 在上传前
  拒绝空输入和超 u32 数量，查询 size 与 build range 使用同一计数。SceneTlas 已在调用前分支处理空场景。
  修正 `array_of_pointers(false)` 的颠倒注释，实际上传仍是连续 native instance record。

`.temp/code-design/B05-c3/make_as.py/run_as.py` 提取实际 new、new_blas_for_build、destroy、Drop 与新 release
方法；device、storage/scratch wrapper 使用替身。新版断言/溢出检查开关各 8 组通过：组合成功、叶子成功、
storage 失败、native create 失败、naming 失败、scratch 失败、AsRef 失败与正常销毁 logger panic。
各已创建资源的创建/释放事件配对，AS 先于 storage 释放，构造回滚不调用 logger。旧版三组创建失败在
debug 下 abort，无断言时保留未配对事件。计数预检由源码和编译复核，未构造超 u32 的真实 instance slice。
这些 mock 结果不证明真实 Vulkan/VMA 的错误返回行为，不覆盖 panic=abort、OOM 或 native 故障。
