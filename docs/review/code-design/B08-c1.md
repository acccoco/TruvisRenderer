## 发现与局部方案

- **P1：短 buffer 可被依赖库补零掩盖。** gltf::import_buffers 先调用
  Data::from_source_and_blob 补齐到 4 字节，再检查 buffer.byteLength；实际 1 字节但
  声明 4 字节的输入可能通过。Reader 直接读取文件/data URI/BIN 的原始字节，检查真实
  长度后仅保留声明范围，不再依赖已补齐的长度。
- **P1：bufferView 未限制在声明范围。** JSON validation 校验引用身份但不检查
  view offset+length 与 buffer.byteLength；当前 image slice 只受实际 Vec 长度保护，
  可读取文件额外字节或 GLB padding。加载阶段统一用 checked_add 验证非空 view 范围。
- **P2：URI 解码路径不一致。** image 的 base64 data URI 直接解码原文，未先处理
  合法 percent escape；buffer 相对路径由依赖库宽松解码，非法 UTF-8 还会 unwrap。
  将 data URI 与外部路径处理收敛到 Reader 私有方法，复用严格 percent_decode；
  buffer/image 同样返回可诊断错误，不以原始 URI 当本地文件名继续尝试。

规范依据：[glTF 2.0 的 URI 与 buffer 定义](https://registry.khronos.org/glTF/specs/2.0/glTF-2.0.html#uris)
（本次页面标记 2.0.1、commit 8e798b02d254cea97659a333cfcb20875b62bdd4），以及
[RFC 2397 的 data URI 语法](https://www.rfc-editor.org/rfc/rfc2397.html)。外部资源可比
声明更长，GLB padding 也允许存在，但都不是 view 的可读声明范围。

## 架构预检

修改仅属于 GltfSceneReader 的 CPU 输入职责。保留 gltf 的 JSON/GLB 结构解析与引用
身份验证；现有 percent_decode 复用，不引入 URI 框架、网络加载、兼容重试或新 owner。
RawTextureSource 继续保留 owned bytes 或已解码路径；AssetSystem 仍负责 canonicalize
与长期身份。类型布局、材质转换、线程、GPU 同步和 public API 不变，模块 README 同步。
