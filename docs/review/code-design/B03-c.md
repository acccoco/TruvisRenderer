## 修复前发现

- **P2，层级预检可绕过**：`ShaderIncludeDirective::parse` 只识别单行字面量，其它形式返回 None；`validate_sources` 只扫描固定扩展。ABI 中的宏 include、`#/**/include`、反斜杠续行，以及被 include 的 `.inc`/无扩展文件内 ABI→lib 引用，都被临时程序确认漏检。直接字面量 ABI→lib 会失败，说明约束意图存在但覆盖不全。depfile 是扁平文件集合，只能验证 package 可见范围，不能恢复每条依赖的源 layer，无法弥补此缺口。
- **P2，注释误判**：多行注释及续行单行注释内的伪 include 被当成真实依赖，误报层级错误。不能用更宽松的字符串匹配修补漏检。
- **P3，canonical 路径漏检**：`Path::components` 会规范化中间 `.` 和重复分隔符，`abi/fixture/./good.slangi`、`abi//fixture/good.slangi` 均通过现有预检，与路径规范不符。
- **P2，实际搜索顺序与预检不一致**：源文件目录下若有同名相对路径，Slang 优先读取该文件，预检却只查 include roots；非标准扩展使被遮蔽文件的依赖进一步漏检。真实编译的 depfile 已确认读取源目录下的影子文件。

处置：归属现有 dependency validator。先对注释/续行做词法处理，再要求 include/import 使用完整字面量路径；不实现宏求值。逐边检查已解析文件，不以其扩展名决定是否检查；用访问集合终止 include 环。路径按原始分段验证。复用现有 owner/layer 和 package 闭包，不改变 shader ABI、线程、资源生命周期或输出事务。同步更新 shader 设计说明及工具 README，最多两次提交。

## 第二项局部修复：layer 标注必须与路径一致

**P2，已修复并验证**：修复前 `ShaderManifest::validate_include_coverage` 只验证前缀至少两段，没有验证 `layer` 和第一段一致。临时加载程序确认 `abi/fixture` 标为 lib、`lib/fixture` 标为 abi、以及 `shared/fixture` 标为 abi 均被接受。前一种会让 ABI 源码在预检中直接获得 lib 权限，破坏分层约束。

修复归属 manifest 的既有 coverage 校验：依据 include root 相对路径检查第一段等于声明的 abi/lib，保留原有唯一搜索根和 owner 段检查。不引入项目特定 package 名字名单，不改 package 依赖图、公共字段或 shader ABI；错误配置在 runner 开始前失败。

第二提交为本报告所在提交。`manifest_probe.py before/after` 的五个场景确认合法 abi/lib 配置通过、两种反向标注及未知前缀均拒绝；23 个源码场景回归通过。最终工具 `cargo build --offline --locked`、`just shader`（compiled=0、skipped=31，随后重新生成/构建两层 binding）和空白检查通过。没有修改锁文件或增加依赖。

## 设计判断、范围与交接

源码预检与 depfile 不是重复实现：前者检查依赖声明的逐边 layer、owner 和路径语义，后者核实编译器实际读取的 package 文件集合。保留两者；不把 scanner 扩展成预处理器，也不建立新的依赖注册表。manifest 校验仍由已有 owner 承担，不把配置检查散落到 compiler wrapper。

本批检查了 dependency validator、runner 调用顺序、manifest coverage、四个 package 与编辑器搜索根，并复现实际 Slang 搜索/depfile 行为。以下边界未扩大为已验收：

- 当前没有真实 HLSL entry，本批未验证 DXC 对全部词法形式的行为；GLSL 现有源码通过预检，未新增 GPU 运行。
- 非标准扩展且未被引用的文本不作为初始源码扫描；进入字面量 include 链后必须检查。新编译器或新增依赖语法需补预检及夹具，不能把此 scanner 当成完整 Slang/C 语法分析器。
- 项目特定的 Engine/Renderer 依赖图由 manifest 显式表达并在本批对照设计；工具没有硬编码这些 package ID。编辑器根漂移仍需配置变更时同步复核。
- B03-a descriptor、B03-b 宿主/GPU 布局结论未受影响；本批不改变资源 owner、ABI 字段、pass 顺序或生命周期。B05/B06 的泛型字节转换与映射契约、B07/B15 的同步/缓存验证继续保留。
