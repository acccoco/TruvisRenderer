## 发现与局部修复

**P2，内部契约加强**：当前 MeshUploadQueue/RenderInstanceTable producer 保证 geometry、
metadata、materials 对齐与 primitive 连续编号，但 emissive 消费端用 debug assertion/zip
和缺失资源 sentinel 隐藏违反前提的快照。Release 截短材质数组时 base map 与 geometry
indirect 不再等长；缺失资源被当作非发光，错序 primitive 则不能保持 hit 直接寻址。
没有正常用户输入触发该偏差的复现证据，故障验证使用受控内部快照。

现于重建入口复用 RenderData::buffer_counts，并验证 metadata 外层与 geometry 对齐；
Active 材质缺失直接拒绝。累计 record 数量先 checked_add 并转换为 uint，再追加数据；
primitive_id 必须等于 submesh 内 record 顺序。最后核对 base map 总长度，不再静默
截短或用非发光标记覆盖坏快照。GPU 几何字段也采用显式整数转换。

这是既有 ready/索引契约的执行化，不增加公共 API、owner 或通用校验框架。只在 dirty
重建时增加检查，不修改 Alias 算法、光能权重、Shader ABI 或提交顺序。失败不推进
version 或 pending；CPU 向量可能已部分重建，dirty 保持，下一次局部尝试从 clear 开始。
这里不保证保留旧 CPU 表内容，也不提供 Runtime panic/command 自动恢复。

## 数据链核对

- MeshUploadQueue 按上传 index 的 chunks_exact(3) 顺序生成 metadata；当前 geometry
  输入先受完整三角形/索引数量约束。emissive 按 active instance/submesh 顺序生成
  base map，顺序与 geometry indirect 一致；共享 mesh 仍按各 instance 的 world
  transform 分别展开 record，稳定 instance slot 与 material slot 保留。
- 发光 submesh 的全部三角形保留 record，包括退化项，确保 base + primitive 可直接
  寻址。非发光或空 submesh 才写 u32::MAX sentinel。alias 只包含正且有限权重的
  record，因此 alias_count 可小于 record_count，不能拿前者给 record index 判界。
  shader 的 hit 路径先读 base + primitive 再检查身份，CPU 对齐约束不可省略。
- dirty rebuild 成功后推进内容 version；当前 FIF 上传后登记 pending，提交确认才
  更新 uploaded version 并清除 B11-d2a 的完整上传标记。其它 FIF 下次使用再补写。
  资源替换和数量转录已经由 B11-d2a/B11-b3 覆盖，不重复改变其状态协议。
- environment binding 是只读快照，不拥有资源。当前 GpuSkyStore 先完成 readiness/
  resolve 与诊断，再返回 binding/changed；真实图像 ready 而分布未发布时使用 uniform
  分布，身份变化撤下旧分布，禁用环境使 distribution_enabled=0。RenderWorld 立即保存
  changed 到 pending history；root 转录地址/维度/版本后，再填当前 sky brightness 和
  CPU sky revision。正常路径没有新增局部修复；外层失败退场继续交 B12。

## 验证

临时夹具位于 `.temp/code-design/B11-d2b/`，未新增源码单元测试。

- `run-map.py`：实际完整 emissive 模块、RenderData/resolver、FrameLabel 和生成 GPU
  类型；替换 buffer/command 及材质资源叶子。11 类前后各启用/关闭 debug assertions
  和 overflow checks，共 **44 次通过**。覆盖共享 mesh、两种 transform、稀疏 slot、
  三个 submesh、退化 record 保位、dark/empty、三 FIF 确认、变更后重建、resolver 异常，
  以及材质/metadata 缺失、数组截短、primitive 错序、slot 错序。
- 固定数据得到 6 个 record、4 个 alias、6 个 base map 项；验证 world position/area、
  身份/slot/padding、record select_pdf 与 alias 离散分布一致。只使用受控常量发光材质，
  这不是完整 MaterialClass、纹理发光或物理估计器验收；未分配数十亿 record 验证极限。
- `sky/run.py`：复用 B10-d2 的受控设施，重新提取当前 sky/queue 方法；uniform、发布、
  generation、readiness/resolve/切换诊断故障、环境启停共 8 类 × 2 配置，**16 次通过**。
  handle/shader 类型为 mock，不证明真实 ABI/native queue 同步。
- `root/run.py`：重新提取当前 upload_scene_buffer，使用真实生成 GpuScene 与 binding
  定义，核对全部根字段和 barrier 故障后不提前发布累计签名，**4 次通过**。这一层仍
  是受控 command 记录，环境 owner→RenderWorld 的交接次序另经当前源码核对。
- `cargo check --offline --locked -p truvis-app`（包含 Runtime）及空白检查通过。
  未运行 GPU、RT/raster 图像回归，也未进行完整 PDF/MIS/采样算法验收。
