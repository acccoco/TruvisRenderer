## helper 局部修复

- **P1，staging 准备失败遗漏。** 两个 buffer 同步上传入口原先分别分配、填写、提交，callback/
  flush/command 分配或录制失败会遗留 staging。现在类型化与 callback 上传共享同一流程；
  准备阶段持有 staging owner，失败无日志 release；录制失败先释放 command，再释放 staging。
- **P1，组合构造无法识别安全回滚阶段。** 现有 immediate 内增加 crate 私有 try_one_time_exec，
  只把提交前可捕获失败返回为 Err；submit/wait 的 panic 不捕获为 Err。公开 one_time_exec 复用该路径，
  保持原返回值和失败传播方式。不是通用 rollback registry，也不新建另一套 queue/command owner。
- **P2，成功销毁日志阻断外层交付。** 上传等待成功后的 staging release 不进入 logger；公开上传
  方法仍传播失败，crate 内目标构造可使用私有 try 入口，在明确未提交时回收自己的目标。

回调只填写映射内存，不自行提交、不保留指针；原始写入仍承担范围和初始化契约。NoUninit 类型化
输入按字节复制，统一 flush 一次；容量检查与空上传行为保持不变。完成状态未知时，不推断资源可释放。

## 直接组合构造修复

- **P1，目标与 staging 分别失去 owner。** image/index/SoA 构造改用提交前结果，在 Err 路径显式释放
  尚未交付目标。Image.transfer_data 在准备/录制失败时回收 staging；from_rgba8 将返回 staging 留在
  闭包外，使 command.end 失败仍可回收。单独使用 transfer_data 的调用方必须放弃失败的 command。
- **P1，AS 录制前失败仍遗漏组合资源。** TLAS 上传、BLAS/TLAS build 与 compact 的 command 分配/
  begin/end 失败沿 try 结果回收各自持有的资源；compact 前一次 build 已等待完成，可以回收两份 AS。
  仍不捕获 submit/wait panic 来释放这些对象。正常返回和既有输入屏障不变。
- structured buffer 只有直接 allocation 与映射访问，没有另一套同步上传构造；其底层 buffer 已覆盖。
  不新增 trait、公共错误类型、隐式 Drop release 或泛化生命周期框架。
