# B21-c：Desktop 特权命令、App 实例化/import 交接与关闭

> 历史说明：本文项目 hash、提交次数及“本报告所在提交”均按压缩前历史解释，实验引用保留为“压缩前证据基准”；第三方版本不变。当前分组见[提交压缩映射](commit-squash.md)。


基准 `74025fda`，`refactor`，本子批核对本地 HDRI 选择、Desktop command 私有队列、
`SceneInitializer` 的异步导入交接、Editor notification 恢复和完整关闭顺序。

## 已核对的不变量

- Tauri dialog 返回的 `PathBuf` 只经过 `DesktopCommandSender` 进入 RenderThread；通用 Editor DTO、
  WebView 和 bridge 不接触本机路径。扩展名在 dialog filter 后再次校验，`.hdr`/`.exr` 之外拒绝。
- Desktop queue 容量为 1，sender 使用 `try_send`，RenderThread 每 tick 最多消费一条。CPU 接受结果
  只表示 sky texture identity 已注册并绑定到 CPU scene，不代表 decode、GPU upload 或 distribution 完成。
- `DesktopCommandController` 在 RenderThread 计算 scene version 变化并由 `EditorController` 广播；
  通知丢失仍可由 Web 的 environment query 和 version polling 恢复。
- 关闭先禁止新桌面资源和 MCP 请求，再让 RenderThread 关闭各 receiver、清空未处理 reply，之后
  join MCP，最后停止 Editor notification task。重复 Close/Exit 是幂等的。

## 局部修复

`SceneInitializer::update` 在 `Failed`/`Ready` 终态分支一进入就清除 `pending_scene_import`，
再执行日志和实例化。此前清除动作位于日志之后；若日志发生 Rust unwind，或 Ready 实例化过程
发生诊断 unwind，下一帧可能再次消费同一结果。修复保留既有策略：实例化失败只保留已成功的前缀，
不回滚 CPU scene，也不重试。
