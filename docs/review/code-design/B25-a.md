## 发现与最小方案

**P2，已确认：动态 DPI 未进入渲染线程。** 修复前 standalone:147 忽略 `ScaleFactorChanged`，
embedded:388–390 只记录日志，公共 adapter 未映射该事件；三个 Renderer 只在 init 设置
ImGui 的 `hidpi_factor`，`init_font` 按该值烘焙字体。即使物理尺寸 resize，旧字体尺度也不会改变。
普通物理像素 resize 和固定 DPI 正常，不构成动态 DPI 支持的反证；实机视觉后果尚未验收。

本批复用现有 FIFO 传递 scale 事件，由 RenderLoop 在帧前合并，仅在最终 scale 改变时
建立 GPU idle 安全点。Renderer 独立回调只更新 GUI，Runtime 不知道字体或 ImGui，
不因为 DPI 改变重建 RT/DLSS target。ImGui 重建 atlas 与 image/view，失效旧 draw data/纹理映射，
旧 image 在 GPU idle 后释放。display/mouse/scene overlay 坐标仍用物理像素；不把 DPI 当相机变化。

处置：已完成必要的跨模块调用链审阅，准入本批修复；不是 B26/B27 的全局重构。

## 保留与证据边界

host 只管窗口/事件；RenderThreadControl 只传事件；RenderLoop 管安全点；具体 Renderer
管 UI 组合，ImGui 管字体。层间有不同职责，不据此认定冗余或过度抽象。
GPU idle 失败不继续销毁旧字体；普通 init/frame panic 的整体退场仍是既有 B27 待办。
键盘文字输入缺失、构造前缀回收与完整资源关闭不由本次 DPI 修复证明。

修复基准为本报告所在提交。新增 `InputEvent::ScaleFactorChanged` 和 Renderer 的独立 scale 回调，

Truvis 的 `ui_scale` 同步更新，面板 min size 与后续首次布局采用新比例；保留用户已经移动、调整的
窗口位置和大小，不强行复位。引擎物理像素坐标、场景 target、shader ABI 与线程边界保持不变。

- `cargo check --offline --locked -p truvis-app -p triangle-renderer -p shader-toy-renderer` 通过，
  覆盖 Runtime、RenderLoop、host、三个 Renderer、ImGui 与 App 编译。

  用 stub GPU 安全点/Renderer 验证最终值合并、松键保留、同值不 idle、返回原值时不重建及恢复初始 DPI。
  同一探针提取当前字体构建片段，链接实际 imgui 0.12.0 与项目 TTF，连续按 `1,2,1.25,1`

探针使用真实 CPU 方法和 ImGui，不调用 Vulkan；不证明旧 image 的实机退场或双显示器外观。
GPU 资源顺序依据源码：Loop 在 callback 前 wait idle；ImGui 发布新 handle 后调用 registry
释放旧 image 及其 views；下一 frame 才构建 draw data。字体读取/上传失败沿原 panic 策略退场，
不承诺可恢复事务。真实双显示器、child HWND、font Vulkan validation 仍需实机验收。
