## 确认并修复

**P2：不存在的 import ID 被当作加载失败。** `AssetSystem::scene_import_status` 原先对无匹配
record 返回 `LoadStatus::Failed`。因此能通过格式解码的伪造/错误 generation ID 会得到
`SceneImportStatus { status: "failed", error: None }`，调用方无法区分身份错误与真实导入失败。

查询改为返回 `Option<LoadStatus>`，World facade 保留该区别，Automation 对 `None` 返回已有的
`StaleObject`。SceneInitializer 对异常 `None` 先清除 pending 再输出诊断；有效 Loading/Ready/Failed
流程不变。修改了 Rust 查询返回类型并更新全部两个直接消费方，不新增 wire 字段或兼容入口。
没有改变 loader、import record 保留期、CPU/GPU ownership 或导入实例化策略。

## 设计判断与边界

- 独立 Automation/Editor inbox 保留必要的队列隔离，controller 不持有 World snapshot；
  App tick 先处理 Editor 再处理 Automation，跨 lane 不保证按实际提交时间排序。
- 每条写请求先在 RenderThread 检查 expected version，再在同一次同步调用中修改 World。
  该检查保护 CPU 当前版本，不保证跨多个请求的事务。未携带版本时不会拒绝旧草稿。
- 材质 patch 与查询复用 WorldSceneAdapter，未重复实现材质校验；transform 使用已有
  TransformTrs，最终由 World 拒绝非法矩阵。两个 controller 的预算循环形似，但当前没有必要
  为少量顺序代码引入通用调度框架。
- 16 条/500μs 是当前默认预算，时间限制在请求间检查。入队后放弃 reply 不取消 mutation；
  shutdown 关闭并清空 inbox，未处理 oneshot 关闭。HTTP 侧如何响应断连/取消交 B22-b。
- import 是资源加载，不创建 live instance；Ready 也不保证纹理解码或 GPU 可见。当前协议没有
  实例化命令，不能把工具名推断为完整“导入并显示”。Import record 保留期交 B26/B27 方案复核。
- Automation 当前不广播 notification，Web 依赖 scene version 轮询恢复；Automation notification
  类型/通道目前未消费，属于 B26 可收敛候选。资源加载完成后的版本覆盖与多入口 UI 恢复交 B23。
