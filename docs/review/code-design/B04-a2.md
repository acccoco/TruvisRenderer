## 范围与修复前发现

已读取 Assimp C API 的 mesh/instance/base header、module.cpp、SceneImporter/SceneData、base_type、生成 binding 与 `TruvixxSceneReader::copy_mesh/copy_instance`。沿 scene 加载、借用、Rust owned 数据复制到 guard 释放检查；材质/格式语义与完整 AssetSystem 消费留给 B08。

- **P2，复制接口约束缺口，已确认，已修复。** `module.cpp` 的五个 `truvixx_mesh_fill_*` 没有容量参数；`truvixx_instance_get_refs` 也只依赖调用方预分配，两条数组在写出前不检查配对长度。传入过小的真实 buffer 会越界，声明容量不足无法返回失败。当前 Rust 唯一 refs 消费者按查询数目准确分配，五个 fill 没有生产调用；这是接口防误用缺口，不是已观察到的生产越界。
- **P2，空引用复制前置不完整，已确认，已修复。** refs 对非空 out 无条件 memcpy，空 vector 的 data() 允许为 null；零字节复制不免除有效指针前置。Rust 的零 mesh 提前返回绕开此路径，但 raw C API 仍需定义空操作。
- **P2，typed view 的对象类型契约不足，已确认实现、后果未运行复现，已修复。** `SceneImporter::get_position/get_normal/get_tangent` 仅 static_assert 大小后将 aiVector3D 重解释成 TruvixxFloat3；布局相同不能建立不同 C++ 对象类型的合法访问。现有 Rust reader 按字段复制，先前正常 OBJ 探针通过，不据此宣称出现过数据损坏。

冗余：fill 与 borrowed getter 服务不同所有权需求，不能仅凭当前 fill 无调用就删除 API。重复的复制边界检查可收敛在现有 C API owner，避免多套空值/容量语义。过度抽象：raw binding 加局部 scene guard/reader 有明确职责，未发现需要再加通用 FFI 框架的理由。

## 局部方案与架构预检

第一提交为复制函数添加按输出元素计数的 capacity，float 输出改为现有 Float2/Float3 record 指针；容量不足或无效输入失败且不写输出。空数组成功且不调用 memcpy；缺失的可选 normal/tangent 仍失败。refs 的两个可选输出共用容量，全部前置检查完成后再写，空节点成功。Rust refs 调用传入实际分配数量。容量参数只能校验声明值，调用方仍负责指针、真实空间、对齐及不重叠。

第二提交在既有 MeshInfo 中持有 Float3 数组，逐字段转换；SceneImporter 在材质、mesh 和节点转换完成后释放原始 aiScene。借用视图有效至 scene free，不能并发销毁；Rust 仍先复制再释放。转换期间新增一份顶点属性存储，峰值内存增加，完成后不同时保留两套场景。依赖、线程、坐标/单位、GPU 契约不变，公开 POD 布局不变；copy API 参数变更需 native 和 binding 同步构建，不提供兼容层。

直接更新 C API header 与 `cxx/README.md`；此局部实现不改变上层 design 不变量。每项修复连同验证记录提交，总计不超过两次。
