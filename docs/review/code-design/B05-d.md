## 创建与元数据修复

- **P1，native 创建后失败失去 owner。** Surface naming 失败显式 destroy；swapchain 创建前先建立
  null owner，创建后立即记录 handle，naming/get_images 失败回收。旧 swapchain 参数由本次调用接管，
  预检/native 创建失败也显式回收，不依赖 Drop。Drop 与其他 RHI 统一为 debug 诊断，不隐式 native release。
- **P1，surface 能力预检不完整。** 除原 format/mode 外，验证 graphics family 可 present、非零 extent、
  所需 COLOR_ATTACHMENT|TRANSFER_DST usage、OPAQUE alpha、layer 与合法 image count 范围；
  min+1 使用饱和计算，避免 u32 回绕。请求必须是具体 format；只接受当前普通 present mode 契约，
  不用 fallback 或共享 present mode 隐式改变用途。
- **P2，外部 image metadata 丢失。** swapchain 的 create 和 image_infos 共用 usage 定义，
  from_external 接收真实 usage/flags，由唯一调用方 Presenter 传入；native image 仍归 WSI，
  wrapper 销毁不释放 native image。没有增加平行 descriptor/资源 owner。

替换接口要求调用方先结束旧链 GPU/WSI 使用并释放 views/wrappers；本地 catch 不能证明该前置。
调用 native create 时 oldSwapchain 即使在新建失败时也会退役，不能恢复为可 acquire 的旧链。
依据：[VkSwapchainCreateInfoKHR](https://docs.vulkan.org/refpages/latest/refpages/source/VkSwapchainCreateInfoKHR.html)。

## Acquire/present 局部修复

- **P1，未 acquire 或重复 present 仍可进入 native。** 当前 image index 改为 Option，仅成功 acquire
  后持有；禁止覆盖在手 image。成功/suboptimal/out-of-date present 后清空，getter 只允许在手状态。
  present 改为可变借用，唯一调用方 Presenter 同步调整，没有新增平行状态管理器。
- **P1，WSI 同步输入缺少校验。** acquire 至少提供 semaphore/fence；acquire/present 拒绝 timeline
  semaphore，present queue family 必须是已核实支持 surface 的 graphics family。
  handle 存活、同设备来源、未完成信号/等待与 fence 状态仍由 owner 保证。
- **P2，有限超时被当作致命错误。** TIMEOUT/NOT_READY 返回 NotReady，没有 current image，
  不触发 resize；Runtime 现有 Acquired 分支会跳过本次 target，成功帧策略不变。

依据：[vkAcquireNextImageKHR](https://docs.vulkan.org/refpages/latest/refpages/source/vkAcquireNextImageKHR.html)
与 [vkQueuePresentKHR](https://docs.vulkan.org/refpages/latest/refpages/source/vkQueuePresentKHR.html)。
OutOfDate present 仍入队等待并释放 acquisition；其他 native 错误保持 fail-fast，不宣称可恢复或已完成 GPU 工作。

`.temp/code-design/B05-d/make_acquire.py/run_acquire.py` 引入实际 swapchain 源码和 semaphore 的
binary_handle 方法，其余 queue/device/同步 handle 为替身。以 `40ecf624` 为状态修复前基准，
新旧版在断言开关下各运行 17 组；新版全部通过。覆盖正常/suboptimal/fence-only acquire、
超时/NOT_READY/out-of-date 后重试、native 错误、无同步对象/timeline、重复 acquire、未 acquire
或重复 present、错误 family、present suboptimal/out-of-date/fatal error。验证调用次数和状态；
旧版可观察超时 panic，以及无效调用进入 native。旧版 present-before 的 panic 来自桩校验，
不是旧 wrapper 的防护。没有真实窗口、GPU 或同步验证层验收。

最终 `cargo check --offline --locked -p truvis-gfx -p truvis-renderer` 与
`cargo build --offline --locked -p truvis-gfx -p truvis-render-runtime` 通过；提交前空白检查通过。

## 剩余范围与交接

B05-d 完成叶子创建、metadata 和单 image acquire/present 首轮；B05 仍部分完成。
下一批 **B05-d2** 沿 SwapchainPresenter 检查组合构造、重建与 present semaphore 生命周期：

- 初始化在 view/后续 semaphore 创建失败时缺少完整 owner 回收；image 先登记、view 成功后才记录
  handle 的顺序也会遗失当前登记项。先记录所有权，再进行可失败步骤。
- 重建没有按新 image 数量重建 render_complete_semaphores；数量增长可能越界。
  处理该问题前必须确认旧代 presentation 完成，不能只更换 vector 后立即销毁旧 semaphore。
- 当前 device.wait_idle 不能独自证明所有 presentation 已完成，需核对现有扩展/能力和 owner
  退场策略，参考 [Swapchain semaphore reuse](https://docs.vulkan.org/guide/latest/swapchain_semaphore_reuse.html)。
  同时追踪零尺寸、重建失败后的状态与 views/registry 清理顺序。
