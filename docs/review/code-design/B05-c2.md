## 本轮发现与修复

- **P1，叶子创建后 naming 失败遗漏释放。** DescriptorPool、DescriptorSetLayout、PipelineLayout、
  ShaderModule 在命名失败时进入未显式释放的 Drop；debug 下可能二次 panic，关闭断言则泄漏。
  使用现有 catch/destroy/resume 模式回收未交付对象；名称/路径的宿主转换放到 native 创建前。
- **P1，descriptor set 的回滚受 pool flags 限制。** 名称 NUL 现在在 allocate 前拒绝；native naming
  失败时只对带 FREE_DESCRIPTOR_SET 的 pool 尝试单独 free。无此标志或 free 返回错误时保留原错误，
  已分配容量由 pool owner 在整体销毁时回收，不 reset pool、不撤销其他 set。依据
  [Vulkan free descriptor set 规则](https://docs.vulkan.org/refpages/latest/refpages/source/vkFreeDescriptorSets.html)。
  GlobalDescriptorSets 当前带 FREE，SHARC pool 不带；不能为了统一回滚强行修改后者的分配策略。
- **P1，graphics 组合创建失败。** 已加载的 shader cache、创建后的 pipeline 和传入的最后一个 layout
  owner 可能在失败 unwind 时遗漏释放。现在先建立空 native handle 的局部 pipeline owner，catch 中
  完成创建/naming，始终显式释放临时 cache；失败再走 pipeline.destroy，只在 layout 无其他 Rc 时释放。
  native 失败输出数组逐个过滤 null 后回收，遵循 [pipeline 创建规则](https://docs.vulkan.org/spec/latest/chapters/pipelines.html#pipelines-multiple)。
  正常路径的 stage、固定功能状态与 layout 参数保持不变。compute/RT 的独立实现列入下一子批。

## 设计判断与边界

typed layout 关联 Rust 声明，cursor 检查 binding 内写入；B03-a 已验证 payload 数量与实际 shader 声明。
这不保证 raw set/layout/image 的 device、存活期、descriptor pool 容量、设备 limits 或更新时的 GPU 安全点。
上述 owner 契约仍需 Runtime/bindless/pass 批次继续审阅，不通过新注册表或反射框架替代。

DescriptorPoolCreateInfo 的私有 raw pointer 指向自己拥有且不再修改的 Vec，Rc 保持其存储；本轮未发现
移动此 wrapper 会移动 Vec 堆缓冲。持久保存 native 投影有冗余，但没有据此判定悬垂，不单独扩大重构。
pool 可以分配不同 layout，已修正文档中“必须相同”的错误限制。

GfxPipelineLayout 由 Rc 共享，显式 destroy 仍可使现存 Rc 的 native handle 失效；Rc 不替代 GPU 完成或
唯一销毁权。GfxRenderingInfo 的 CLEAR/STORE、单 layer 与固定布局属于当前便捷路径，不能覆盖任意
RenderGraph pass 契约。真实 attachment 格式、深度/模板使用、stage 与 device features 留给对应 pass。
