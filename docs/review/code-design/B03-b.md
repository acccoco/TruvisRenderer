## 修复前发现与处置

1. **P2：Shader binding 暴露无法链接的构造函数。** `slang_base.hpp` 的 `float4(float,float,float,float)` 仅供 C++ 解析 Slang 初始化表达式，没有 native 实现。默认 bindgen 却生成 `Float4::new` 和外部符号。实际编译调用该函数的最小程序，链接报 `undefined symbol: float4::float4`；仓库调用方均用字段初始化或 `From<glam::Vec4>`。本批在 `BindingGenerator::generate` 限制输出为 types/vars，保留 allowlist、namespace 和基础类型复用；不引入 native 构造实现。状态：已修复并验证。修复后同一非法调用在编译阶段报 E0599，字段初始化和 `From` 程序成功链接并运行；38 个类型修复前后的完整布局 JSON 一致，C++ static_assert 通过。删除的生成 API 原本不可链接，无仓库使用点。
2. **P2：ImGui vertex layout 的字段来源与上传类型分离。** `GuiMesh::fill_vertex_buffer` 上传 `imgui::DrawVert`，layout 和初始容量却取自没有 `repr(C)` 的私有 `ImGuiVertex` 镜像。当前数值相同不能约束以后类型变化。已删除该未实例化的镜像，直接对 `DrawVert` 求 size/offset；颜色字段使用其实际 `col: [u8; 4]`。状态：已修复并验证。临时程序包含实际 layout/trait 源文件，针对锁定的 imgui 0.12.0 `DrawVert` 验证 20/4、offset 0/8/16、attribute 格式与容量；SPIR-V vertex entry 的 location 0/1/2 对应 float2/float2/float4。未观察或验证实际画面变化。
3. **P3：布局说明偏离事实。** `PerFrameData` 的 padding 注释声称保持 16 字节对齐，实际宿主 size/align 为 456/8；ShaderToy 手写 GLSL push constant 投影缺少例外原因和布局验证说明。已修正这两处，并把 `SharcTargets::new` 的过期 push descriptor 注释改为实际 regular set。只修正说明，不为满足错误注释改变布局。状态：已修复并验证对应静态布局/绑定事实。

## 已确认的边界

- Engine allowlist 显式列出基础向量/矩阵和 `engine::*`；Renderer 仅生成 `renderer::*`，通过 namespace 导入 Engine 基础类型；两者均关闭递归 allowlist。SHARC 的两个 shader-only record 被 `__SLANG__` 隔离，CPU 仅按不透明记录分配/清零，无第二份 Rust 字段定义。
- `host_layouts.py` 编译实际生成类型，取得全部字段 offset/size、结构 size/align；再用实际两个 C++ 聚合 header 的 `static_assert` 对照。38 个类型均无隐式字段间/尾部 padding。
- `spirv_layouts.py` 对当前 31 个 SPIR-V 执行 `spirv-val --uniform-buffer-standard-layout`；按 namespace 匹配所有带 Offset 的共享结构，27 个类型的全部成员 offset/名称/字段字节数一致（跨产物和不同投影共 1517 次成员检查），12 类共享 record 的 ArrayStride 等于宿主 size。未把宿主向量 align=4 当成所有 Vulkan 布局模型的对齐规则。
- PerFrame/GpuScene 使用 scalar layout；device-address record 检查自然布局及 pointer ArrayStride；pass push constants 按各自 SPIR-V offset 和 Rust range 核对。全部生成结构的主机结果和 GPU 覆盖清单见下表；矩阵解释和 vertex input 另行核对，不能只靠结构名称匹配。

上述 28 个类型加上两种 shader-only SHARC record，覆盖两个 owner ABI 目录中的全部 30 个 struct 声明。基础 C++ 投影另有 10 个类型：Float/Int/Uint 的 2/3/4 分量向量分别为 8/12/16，align 均为 4；Float4x4 为 64/4。基础类型没有一一对应的 SPIR-V struct：标量/向量作为字段检查字节数，Geometry 的 float2/float3 指针实际 stride 为 8/12，矩阵另查下述主序。没有遗漏但声称已验证的共享结构。

- **矩阵**：`From<glam::Mat4>` 按 x/y/z/w axis 写 col0–3，编译器显式传 `-matrix-layout-column-major`。CPU 非对称矩阵探针确认列投影及乘法结果；实际 ImGui SPIR-V 的 ortho load 使用 `RowMajor + MatrixStride 16`，随后是 `OpVectorTimesMatrix`，与 Slang 的 `mul(ortho, vector)` 配套。不能仅看 RowMajor 字样就改主序。此处验证为宿主执行与静态指令链对照，没有 GPU sentinel/readback 实验。
- **Viewport vertex**：其结构没有 memory-block Offset 装饰，已改用真实 `ViewportOverlayVertexLayout` 的 size_of/offset_of 源码与 vertex entry 对照：location 0/1 均为 float4，32 字节步长。ImGui 则使用外部 imgui crate 的 canonical `DrawVert`，无需增加 Slang 同形字段副本。
- **SHARC**：实际 SPIR-V 中 `SharcAccumulationData` 是 offset 0 的 uint4、stride 16；`SharcPackedData` 字段 offset 0/8/12、stride 16；hash runtime array stride 8。与 `SharcTargets` 的 16/8 字节分配常量一致。CPU 不读取这些记录，保留不透明分配；缓存同步、清零时序、容量和算法正确性留给 B07/B15。
- **ShaderToy**：独立 GLSL package 不依赖 Engine/Renderer ABI，保留现有手写投影。临时程序从当前 Rust 源码提取结构声明并编译，size/align 为 48/16，offset 为 0/16/24/28/32/36/40；两个阶段 SPIR-V 的八个成员 offset 为 0/16/24/28/32/36/40/44，与 Rust 尾部 `[f32; 2]` 一致。实际 crate 也通过 Cargo 检查。未引入第三套通用生成器。

## 上传、readback 与设计判断

- `RenderRuntime::prepare` 构造 PerFrameData、显式初始化 padding；`PerFrameGpuData` 以该生成类型分配单元素 UBO 并按字节更新。`RenderWorld` 的 scene 根亦直接构造 GpuScene 并更新 typed buffer。
- Geometry 表直接写生成结构，device address 来自 vertex/index buffer；Instance 使用生成结构和 offset_of 计算局部上传区间。MaterialTexture/PbrMaterial 的构造、light/sky 表及 raycast 的映射写入/readback 均使用 Engine 生成类型，未发现另一份手写字段镜像。检查覆盖类型来源、字段赋值、记录步长与上传范围；没有把资产数值语义、slot 失效或跨帧同步提前验收。
- Renderer 的 compute wrapper 以同一个泛型 `P` 决定 pipeline push range 和上传字节；RT、raster、outline、resolve、ImGui 的直接 range 也使用其生成类型 size_of。该复用承担真实投影职责，本批没有删除 wrapper 的依据；`P: Sized` 的字节安全边界仍需后续审阅。
- 冗余集中在 ImGui 无约束镜像，已去除；两层 binding 共用 generator、Renderer 复用 Engine 基础类型，有明确 owner 与单一字段来源，应保留。没有证据支持本批合并 crate 或创建新的 ABI 注册框架。
