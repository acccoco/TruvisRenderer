## Origin 校验

**P2，已复现并修复：接口接受任意 Origin。** 固定 Host 不能代替 Origin 校验。
RMCP 默认空 Origin allowlist 表示不检查；原生客户端边界下应显式调用
`enforce_origin_validation()`，拒绝所有携带 Origin 的请求，包括 `null`，无 Origin 客户端保持可用。
不增加认证、CORS、代理或远程访问能力。本地其他进程仍可访问。

临时 HTTP 探针 `.temp/code-design/B22-b/` 编译当前完整 `mcp_server.rs`，使用真实 RMCP、
Axum 和 TCP socket，CPU receiver 用受控响应代替 World，不启动 GPU。修复前外部 Origin 与
`null` 都返回 HTTP 200；修复后均返回 403。无 Origin 的两种 2025 initialize、tools/list、
tools/call、resources/read 通过；错误 Host 返回 403，未知版本返回 400。
`cargo check --offline --locked -p truvis-app` 和 `git diff --check` 通过。

## 关闭排空

原实现对不完整 Content-Length 请求体使用无期限 graceful shutdown。实际保持 socket 打开时，
停止接收并关闭 Automation receiver 后，join 仍在等待；三秒观察期后关闭该 socket，join 才返回。
**P1，已修复：慢请求体可使桌面关闭无期限等待。** `McpServer::run` 在 cancellation 后给
graceful drain 两秒窗口，超时返回，由专属 runtime 销毁剩余连接任务。正常在途请求仍有机会
取得 RenderThread reply；不保证超时或断连后错误已送达客户端，也不回滚已经执行的 CPU mutation。
此限制不约束 RenderThread/GPU 的关闭耗时。两秒是当前实现值，不是协议不变量。

## HTTP 与 schema 证据

`python .temp/code-design/B22-b/http_probe.py after` 对完整当前 server 的真实 TCP 流程验证：

- 两种 2025 initialize 协商，以及 2026 discovery/tools/list 均成功；2026 的 metadata 和
  `Mcp-Method` 按 RMCP 要求提供。最初探针漏带该 header 时收到 400，修正探针后通过。
- tools/list 返回 8 个工具；scene summary 返回受控 scene version；业务错误产生 structured
  `isError`，schema 类型错误产生工具错误。resources/read 的 summary 和未知 URI 行为通过。
- 完整 MaterialPatch 示例覆盖所有顶层字段、Transmission、AlphaMask(1.5) 和 texture mapping，
  HTTP schema 接受后可转成 bridge MaterialPatch；回传字段集合和 coverage 值一致。
  这是代表性往返，不是所有字段组合的穷举或生成 schema 等价证明。
- 错误 Host、外部 Origin 和 `null` 均为 403，未知协议为 400；无 Origin 的原生请求可用。
- 第二个 server 对已占用端口明确启动失败；不改用其他端口。
- 客户端保持不完整 body 连接，关闭约 2 秒返回；修复前保持连接三秒仍等待，关闭 socket 才返回。

## 设计判断与交接

HTTP 参数结构和 bridge MaterialPatch 是两份声明，当前 JSON 转录没有发现本例字段丢失；
双份维护和无失败分支的 `version` Result wrapper 交 B26 复核，不引入通用 schema 框架。
资源分页 URI 没有 expected version，每页响应仍带版本；需要一致分页时应使用带版本参数的
list tool，不能直接拼接资源查询为事务。HTTP 原生客户端和版本协商是明确能力边界，不能当作
无用兼容设施删除。

RMCP 当前实现对 JSON reply 等待期间断连会取消 handler，但 Automation inbox 不撤回请求，
执行语义沿用 B22-a 的放弃 reply 探针；本批未做每个断连时刻的网络竞态穷举。CPU receiver
是受控 fixture，不证明真实 GPU 或 Tauri E2E。协议 malformed-body、大包和 HTTP/2 细分场景
未逐个运行；body 字节上限由 RMCP 默认 4 MiB 提供。
