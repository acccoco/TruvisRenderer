## 两组局部修复

1. **P2，roll 与视图不一致**：camera_right/up 包含 YXZ roll，但 get_view_matrix 用
   世界 up 重建姿态，丢弃 roll。设置非零 roll 后，局部右移不再对应画面右方。
   view 使用同一旋转后的 up；保留世界 Y-Up、右手系、投影深度与 Q/E 世界方向移动。
   当前场景和交互不写非零 roll，因此这是公开 Camera 状态的契约修复，不声称已发现
   默认场景画面故障。
2. **P2，普通 update 仍创建 pivot 查询**：Triangle/ShaderToy 使用普通 update，
   未实现相机 after_prepare；旧开关只禁用 pan/wheel，中键仍创建无人消费的 pivot，
   并通过提前 return 阻断键盘移动。普通 update 应只做键盘/右键控制；所有锚点导航
   由接入同步查询的 update_with_wheel_zoom 路径启用。

架构预检：修改归现有 Camera/CameraController，复用旋转与 clear 方法；无新增 owner、
trait、线程、依赖方向或 GPU 契约。相机视图仍经 RenderView 值快照进入 Runtime。
两个行为各自提交、同步 renderer-kit README；不更新 docs/summary。

## 已读边界与待处理问题

- 主体 update 在交互后固定 frame_view；render_frame_input、Offline 签名和 overlay
  使用该值，after_prepare 的相机改动下一帧进入快照。通过调用链与值快照实验核对，
  没有把同步查询完成错误等同于当前帧视图已经更新。sample 不消费 Runtime scene，
  相机只供诊断；本次没有增加其 GPU 查询能力。
- 屏幕射线拒绝非法像素位置/viewport，投影裁剪 near；命中锚点检查有限性与距离，
  wheel 对单次输入检查有限性并限制指数。这些局部检查不代表 Camera 状态整体有效。
- **P2，输入边界缺口（后续 B14-b2 已修复）**：本报告基准的 update_impl 在 viewport 为零时直接除法
  写入 NaN asp；rotate_camera 对非有限鼠标 delta 直接更新角度，污染相机。Camera
  public 字段与 render_view 之间也没有完整有限性/投影域约束。`run.py numeric`
  对零 viewport、NaN 鼠标、非法相机位置做 3 类 × 前后版本 × 两配置，**12 次复现**。
  当前主 Renderer 拦截零 extent、场景只写有限常量；未证明真实 Winit 输入会产生 NaN。
  后续应区分外部输入拒绝与程序写入非法相机状态的失败契约，不静默替换成默认相机。
- **P3，冗余状态（后续 B14-b2 已清理）**：WheelZoomState.distance 只初始化/写入，实际更新总是
  从 anchor_ws 与 camera.position 重新计算距离；保留两份无益。pivot/pan 的 distance
  则参与反解相机位置，不能一并删除。
