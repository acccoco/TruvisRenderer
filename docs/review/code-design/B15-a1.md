# B15-a1：输出格式与 graphics pipeline 重建

> 历史说明：本文项目 hash、提交次数及“本报告所在提交”均按压缩前历史解释，实验引用保留为“压缩前证据基准”；第三方版本不变。当前分组见[提交压缩映射](commit-squash.md)。


基准 `f8705444`，`refactor`，初始工作区干净。读取 Realtime/Offline 生命周期和
compute/present 入口、OfflineTargets/shared targets，定向追踪 ResolvePass、GuiPass、
两个 sample pass 与 resize 调用，以及 viewport/selection outline 的既有格式重建。

## 已确认问题与局部方案

**P1，格式变化后继续使用旧 pipeline**：ResolvePass 创建时把 present color format
写入 attachment 配置；两个主子系统的 on_resize 只重建 target。ImGui 只更新 display
size；Triangle/ShaderToy subsystem 使用默认空 resize。四类 pass 均可能继续持有
旧格式 pipeline。普通尺寸变化不触发此问题；未在真实窗口复现设备格式切换。

架构预检：格式与对应 pipeline 一起归现有 pass owner，不下沉成 Runtime 重建框架。
沿用 ViewportOverlay/SelectionOutline 的“创建替代对象→交换→销毁旧对象”模式，
从既有 GPU idle 后 resize hook 传入当前 present format。同格式不重建，格式变化
不替换 scene、长期 UI 数据或 shader ABI；依赖方向与提交线程不变。Resolve 由两个
子系统复用同一入口；UI/sample 各保持自己的 pass 类型，不为几行流程建立通用 trait。

两组提交：第一组 Resolve 主视图路径；第二组 ImGui 与 sample 同类修复。相关文档随组更新。
构造失败保留旧 owner 只指交换尚未发生；不承诺新构造内部的 Vulkan 部分资源已回滚。

## 后续已定位问题

- OfflineAccumState.take_next_sample_batch 在图构造阶段推进 sample_count；Realtime
  的 restir_last_* 同样先于 record/submit 更新，SDR 也有图构造时状态推进。不能把
  “加入 graph”当成实际提交证据，B15-a2/B15-b 定向处理。
- Realtime previous_frame_label 在取模前对完整 frame_id 加 COUNT-1，极大帧号可能
  溢出；计数极值、Offline 饱和样本与 shader 分母由 B15-a2 一起核对。
  后续 [B15-a2](B15-a2.md) 已修复 Offline/Realtime 的提交确认和两处计数边界；
  SDR 图构造状态仍待 B15-b，不属于该修复的完成范围。
- shared target 创建后的 layout transition、view 注册，以及多 target destroy 的失败
  路径仍需 B15-a3 审阅；不能通过普通 Drop 假设释放完成。
- ImGui DPI/输入和其他 UI 契约仍归 B24，本批仅覆盖格式相关 pipeline 生命周期。

第一组 `cc56502c`。`.temp/code-design/B15-a1/run.py resolve` 提取实际 rebuild_for_format 与两个
on_resize 方法，替换底层 pass 创建/销毁及 target 为事件记录器。相同格式、改变、
重复 resize、切回、构造失败、销毁失败，共 6 类 × 两个 owner × 前后版本 ×
debug/overflow 两配置，**48 次通过**。同格式无新建，改变时先新建后销毁，构造失败
不交换旧对象；销毁失败会传播且新对象已安装。此实验不证明 Vulkan 构造内部回滚或
实际 GPU 格式切换。App 编译和空白检查通过。

第二组为本报告所在提交。`run-ui.py` 提取 Gui/Triangle/ShaderToy 的实际重建方法与
resize hook（旧 sample 使用 trait 的空默认行为）；同上六类加未初始化，共 7 类 ×
三个 owner × 前后版本 × 两配置，**84 次通过**。还验证 ImGui display size 始终更新、
未初始化 owner 不凭空创建 pipeline。字段保存的格式与 new 的 attachment 参数一致，
编译覆盖两个 sample 的 resize 转发和所有调用签名。

第二组 `cargo check --offline --locked -p truvis-app -p triangle-renderer -p shader-toy-renderer`
及空白检查通过。未新增源码单元测试；方法级替身不代表真实 Vulkan 创建/销毁失败或
窗口/GPU 验收，也未测试格式变化的显示色彩结果。无 shader/ABI 修改，不重建 shader。

## 结论与交接

本子批完成四类 graphics pass 的格式跟随；ViewportOverlay/SelectionOutline 已有
同类重建，未重复改写。格式变化只替换 pipeline 及其配套 layout；字体/mesh、scene
及当前 shader 语义保持原有 owner。这里的 resize 前置仍是 Runtime 的 GPU idle，
不解决 B12 的 WSI 跨代 present 完成凭据问题。

下一批 **B15-a2**：先复核 Offline/Realtime 在图构造阶段提前推进状态的真实影响，
再处理提交确认和计数边界；SDR 状态由 B15-b 配套处理。B15-a3 继续 target/native
部分创建与释放失败；B15 整体未完成，B26/B27 最终全局修改仍不实施。
