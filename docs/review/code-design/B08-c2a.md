# B08-c2a：glTF 几何与 accessor 输入边界

> 历史说明：本文项目 hash、提交次数及“本报告所在提交”均按压缩前历史解释，实验引用保留为“压缩前证据基准”；第三方版本不变。当前分组见[提交压缩映射](commit-squash.md)。


基准：`refactor` 的 `a65eb17e`，工作区干净。本批读取 GltfSceneReader、SubmeshData、
锁定的 gltf/gltf-json 1.4.1 的 mesh Reader、accessor iterator、sparse 与 JSON validation。
范围是实际消费的 primitive 几何数据到 owned CPU mesh；层级、材质与几何着色语义另批处理。

## 发现与局部修复

- **P1：声明损坏与属性缺失混淆。** reader 返回 None 也可能表示 accessor 范围越界。
  原实现将短 indices/NORMAL/TANGENT 静默转换为顺序索引、生成法线或零切线，掩盖输入错误。
  现在先校验声明；默认生成只用于 primitive 未声明的可选属性，已声明但解码失败直接报错。
- **P1：typed iterator 的前置条件未落实。** JSON validation 不检查本 Reader 需要的所有
  component/dimension/normalized 组合、count、stride、对齐和字节跨度；库中部分断言仅为
  debug_assert，范围算术存在 unchecked 加乘和 count-1。实际旧版夹具可触发 panic，关闭
  夹具溢出检查时部分 overflow 输入还会被接受。现在在数组分配/迭代前执行 checked 范围计算，
  校验被消费的属性类型及顶点数量一致性，count 限于 1..=u32::MAX。
- **P1：sparse 覆盖不检查索引序列。** 原库迭代器可静默忽略倒序、重复或越界项，使错误
  payload 成为有效 RawSceneData。现在检查 sparse count、两个 view 的范围/对齐、禁止的
  stride/target，并用原始索引宽度检查严格递增及上界；实际覆盖仍由库实现。
- **P2：转录到 u32 后丢失原索引类型的 restart 约束。** 当顶点数足够大时，u8 的 255
  或 u16 的 65535 可通过 SubmeshData 的普通范围校验。现在按原 component type 拒绝这些值。

规范依据：[glTF accessor、Data Alignment、Geometry](https://registry.khronos.org/glTF/specs/2.0/glTF-2.0.html#accessors)
（本次页面 2.0.1，commit 8e798b02d254cea97659a333cfcb20875b62bdd4）。不是新增通用格式
验证器：库已有的引用、枚举、POSITION min/max 存在性等检查继续复用；输出端复用
SubmeshData 的有限值、非零法线、数组长度、三角索引数量与索引范围检查。

## 架构与不变量

所有新增检查属于 GltfSceneReader 私有 impl，读取它已有的 document/buffers，不引入
public API、全局状态或兼容层。load_buffers 已证明 view 在真实 buffer 声明范围内，
accessor 预检继续证明元素在 view 内；跨层职责不变，worker 只返回 owned CPU 数据。
没有改变坐标系、线程 owner、GPU 生命周期、RenderGraph 或 Shader ABI。

交错属性、末元素无尾部 padding、normalized U8/U16 UV、U8/U16/U32 indices、dense/zero
sparse base 均保留。sparse values 使用紧密布局，不能错误套用 dense vertex byteStride。
字节范围检查先于 typed iterator；缺失数据的既有生成算法保持，由下一子批核对其语义。
模块 README 同步输入约束与已知偏差，不修改 design 的全局职责或 docs/summary。

## 边界与下一批

- 这不是完整 glTF validator；没有比较 min/max 元数据与真实数据，也未扩展消费 COLOR、
  JOINTS、WEIGHTS、morph targets 或动画。未消费字段的语义仍待后续格式批核对。
- u32 count 限制保护现有顶点寻址与库 sparse 游标，不构成 CPU 内存/工作量预算。多个
  primitive 的累计大小、sparse 展开分配与队列背压仍交 B13/B27，不承诺 OOM 可恢复。
- **B08-c2b：几何生成与着色属性语义**。静态代码确认当前缺 normal 时累积平滑法线，
  而规范要求 flat normals 并忽略已有 tangent；当前还未约束输入 tangent 的方向/w 语义。
  先核对顶点拆分、UV/tangent owner、下游切线生成与退化面处理，再决定局部修复，不在本批
  静默改变三角拓扑或着色。该偏差已写入模块说明，不能因 accessor 校验而宣称几何合规。
  **续接状态**：B08-c2b 已修复缺失法线的 flat 展开与 tangent 丢弃，并校验实际使用的
  authored frame；上文保留本批基准事实，最终状态见 [B08-c2b](B08-c2b.md)。

后续继续 scene 层级、材质、Assimp 和脚本；B08 父项保持部分完成，最终全局修改不实施。
