# B12-b1：Runtime 已知安全构造阶段的组合回收

> 历史说明：本文项目 hash、提交次数及“本报告所在提交”均按压缩前历史解释，实验引用保留为“压缩前证据基准”；第三方版本不变。当前分组见[提交压缩映射](commit-squash.md)。


基准 `27535318`，分支 `refactor`，工作区干净。读取 Runtime new/destroy、Gfx root、
GameWorld/AssetSystem、registry/binding/command/FIF owner，以及 RenderWorld/AssetSystem
构造和关闭。启动组合不是统一的未提交事务：RenderWorld 内部会同步上传 fallback。

确认 Runtime 当前任何后项失败都会跳过前项显式回收。分两个已知安全阶段修复：
RenderWorld 构造之前尚无 GPU 提交；RenderWorld 已成功返回后 fallback 同步完成、
scene/asset 上传队列为空，RayCastService/FIF/command 创建不提交 GPU work。

RenderWorld 自身异常不能用一个 catch 判断叶子是否发生未知提交，也不能证明所有
native child 都已回收。本批不在这个边界调用 Gfx::destroy；保留现有错误传播，不能
宣称整个启动失败链已闭合。该分类/回收契约缺口交 B12-b2/c 与 B27，最终全局修改不做。

架构预检：私有 RenderRuntimeInit 只持有尚未交付的 Option owner，不保留 Gfx context，
不实现 native Drop；成功移交给原有 Runtime 字段，失败仅在上述安全阶段按依赖顺序
显式回收。复用原有 destroy，不改变公共 phase、线程、pass 顺序或 GPU ABI；同步 Runtime README。


## 修复结果

本报告所在提交修改 `render_runtime.rs::new`，引入仅在启动期间存在的
`RenderRuntimeInit`：每个已成功返回的 owner 立即存入 Option，成功后移入原 Runtime
字段。失败回收由同一初始化 owner 承担，先查询服务/CPU world/RenderWorld，再释放
FIF、command allocator、registry、timeline 和 binding，最后 Gfx；Gfx 本身创建失败
仍由其现有构造边界处理。没有改变正常 Runtime destroy 或 Renderer/窗口生命周期。

这是确认的 P1 组合回收缺口：缺失默认 sky 路径、后续 service/FIF 分配或第 N 个
command 分配失败，原来没有显式回收已成功的前项。叶子即使完成自身回滚，也不能
替外层释放这些已交付 sibling。当前默认文件存在不构成保留该失败行为的理由。

`render_world_constructing` 仅在进入 RenderWorld 构造前置位，成功返回后清除；异常
分类不足时不进入新回滚。此时保持既有 unwind/Drop 行为，debug 仍可能因未显式释放
触发二次 panic/abort，release 也没有完整资源回收保证。本批没有新增“保留到进程结束”
机制，也未把 fail-stop 描述为安全恢复。未知 leaf native owner 和 root 的退场需相关
owner 一起确认，不能在此用 device idle 成功或简单 catch 推导所有 child 已释放。

初始化候选与正式 Runtime 有相应资源字段，但作用不同：前者表达允许缺项的构造状态，
后者只接收完整对象；这是显式回收所需状态，不再增加泛型 guard、注册表或兼容路径。
正常 destroy 与构造 rollback 的调用相似，但同步前提不同，本批不合并为一个通用关闭函数。

## 验证

`.temp/code-design/B12-b1/run.py` 提取实际 Runtime struct/new/get_depth_format/destroy
及初始化 owner，使用真实 FrameLabel/FrameRenderState；子 owner 为受控账本，按创建
边界模拟交付。37 类 × 前后两版本 × debug/overflow 两配置，**148 次通过**。

- 正常构造检查初始 frame id=1、timeline=0、400×400 占位 extent、无 Presenter、三个
  command，再经实际 destroy 调用次序验证 root 最后回收。
- 覆盖 root、depth 查询、timeline、registry、command allocator、timing、binding、
  CPU world、资源路径/import/sky assignment、raycast、FIF 和三个 command 创建失败；
  各失败点另注入释放后的诊断异常，确认已交付候选全部回收且原始错误保持。
- RenderWorld 普通异常及模拟未知提交均确认没有进入新 root 回收；这只是边界保护验证，
  不是已修复这两种失败。mock 不执行真实子 owner Drop/abort，也不证明任意 native
  release/SDK shutdown 失败后仍能回收；各叶子自身保证仍以对应批次及实现为准。
- `cargo check --offline --locked -p truvis-app` 和空白检查通过；未运行 GPU/设备丢失、
  loader 线程阻塞或真实窗口退出。只格式化新增 owner 和修改后的 new，不整理其它代码。
