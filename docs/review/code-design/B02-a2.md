## 补查证据与边界

已复核 CMake public target/export header、runtime sidecar helper、Assimp/Streamline module、Rust runner/packager/manifest，以及本机 vcpkg `applocal.ps1`、Assimp imported target 和 CMake 4.2 自带 runtime dependency 文档。

- Assimp imported target 没有间接 `INTERFACE_LINK_LIBRARIES`；vcpkg app-local 在构建后递归检查 DLL，并按时间戳复制。不能把输出目录的存在性当作当前版本的来源。
- 临时 CMake 探针从 vcpkg 的 Debug Assimp DLL 出发，`file(GET_RUNTIME_DEPENDENCIES)` 找到 kubazip、minizip、poly2tri、pugixml、zlibd1 五项，路径均在当前 vcpkg 安装目录。系统 DLL 排除，不硬编码这五个文件名。
- native SHARED 及其 import library 由当前 CMake target 声明；内部 STATIC/PDB 不属于 Rust runtime 部署契约。显式动态加载的 Streamline sidecar 仍由 module 声明，不能从 import table 推断。
- 当前 Rust 边遍历边覆盖输出：后面的 required 缺失、目标重名或旧清单非法会在部分覆盖后才失败；首次部署的部分新文件也不会写入旧 manifest，后续切换方案可能遗留无主产物。

## 本轮处置

1. **产物归属（P2，已确认，已修复并验证）**：CMake 在 native 构建成功后生成完整 runtime plan，内容为 public target 输出、target 声明的 DLL 依赖及其递归依赖、显式 sidecar。Rust 只消费完整 plan，删除目录扫描。plan 升为版本 2，不读取旧版 fallback；CMake 仍不调用 Cargo。
2. **部署失败（P2，已确认，预检与重试所有权已修复并验证）**：先统一验证源文件、目标冲突、旧清单边界，再写入“旧托管集合 ∪ 本轮计划集合”作为重试所有权；复制和清理全部成功才缩减为当前集合。缺输入/冲突/非法清单不得先覆盖已有输出。状态文件通过同目录临时文件替换，避免直接截断旧清单。
3. **目标仅改变大小写时误清理（P2，补查确认，已修复并验证）**：旧清单和新集合原先按字符串大小写比较，Windows 上可能把刚覆盖的同一文件当成旧文件删除。现以目标文件名的大小写不敏感身份判定是否仍被计划使用；夹具覆盖该变化。

多文件部署不是事务：IO 失败时输出可能混合，命令必须失败，修复原因后重跑才能使用；本轮只收敛确定性前置错误和可重试托管状态，不引入通用事务框架、后台恢复或并发部署。进程崩溃/断电的持久化保证不作承诺。

实现位于现有 `TruvisCxx.cmake`、新增的构建期执行体 `TruvisRuntimePlan.cmake` 和原 Rust packager/deployment impl；删除 `CmakeOutputScanner`，没有新增通用构建或事务框架。相关 CXX README、CMake README 和 native 设计边界已同步，按两个职责批次提交：
