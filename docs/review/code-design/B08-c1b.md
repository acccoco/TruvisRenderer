## 发现与局部方案

- **P1：版本字符串没有语义检查。** asset.version/minVersion 只是 String，当前可导入
  3.0、要求 2.1 或格式不合法的文档。当前 Reader 只处理 2.x；无 minVersion 时接受
  2.x 的 minor 更新，有 minVersion 时必须满足当前 2.0 能力且不能大于 version。
  版本严格按十进制 major.minor 解析，不引入 semver 库或版本适配层。
- **P1：库功能开关不等于 Reader 能力。** KHR_lights_punctual 被 Cargo 启用，但 Reader
  没有灯光导入，RawSceneData 也无灯光字段；必需灯光扩展现在会被静默丢失。使用 Reader
  的显式必需扩展入口列表，拒绝没有消费路径的声明；不在本批扩展 scene/GPU 灯光模型。
- **P2：扩展声明关系未验证。** 依赖库只检查 required 名称是否启用，不检查 required
  是 used 的子集，也不检查重复项。本地入口在资源 IO 前拒绝这些矛盾声明。

规范依据：[glTF 2.0 版本规则](https://registry.khronos.org/glTF/specs/2.0/glTF-2.0.html#asset)
与[扩展声明](https://registry.khronos.org/glTF/specs/2.0/glTF-2.0.html#specifying-extensions)
（本次页面 2.0.1，commit 8e798b02d254cea97659a333cfcb20875b62bdd4）。GLB header 的
版本只描述容器，JSON 中的版本仍需检查；minor 更新本身不是拒绝同 major 文件的理由。

## 架构预检与范围

检查属于 GltfSceneReader 私有方法，位于 JSON/GLB 解析之后、buffer IO 和 CPU 数据复制
之前。复用 document.as_json 和 extensions 迭代器；不新增 public API、owner、线程、
资源类型、Shader ABI 或全局注册表。模块 README 同步当前输入契约。

当前有转录入口的四个名称是 KHR_texture_transform、KHR_materials_transmission、
KHR_materials_ior、KHR_materials_emissive_strength；这不是全部字段或 GPU 行为的合规
证明。已发现 transmission 只读取 factor，不读取 transmissionTexture；Surface 的 IOR
不保存在 MaterialClass，rough BTDF 仍未实现（现有设计已明确）。这些不能以名称检查
掩盖，转交 B08 材质子批与 B15 核对，不能宣称完整扩展验收。

未知 optional 扩展可被忽略，已实现的 optional 路径保持；必需灯光扩展失败不等于删除
World 现有灯光能力。导出脚本可写 glTF 灯光也不代表 Reader 已消费，脚本子批继续核对。
