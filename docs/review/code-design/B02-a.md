## 发现与处置

### 同大小旧时间戳会阻止内容更新（P2；已确认；已修复并验证）

- 修复前 `main.rs` 的 `CxxBuildFileHelper::needs_copy`（544–563 行）只比较长度和 `source_modified > destination_modified`。
- 切换分支、工具链或恢复缓存后，新源文件可能同大小而时间更早；此时旧 DLL/import library 会被误认为最新。时间戳能加速部分判断，但不能证明内容相同。
- 最小修复：在现有文件 helper 内按长度和实际字节判断是否相同；有界缓冲比较，避免将大 SDK DLL 整体加载进内存。没有找到可直接复用的内容比较 helper，不新增全局工具层。
- 验证：临时源代码探针覆盖同大小不同内容、时间更早/相同、相同内容、新目标和不同长度。

### 旧部署清单的词法前缀校验允许越界删除（P2；已确认；已修复并验证）

- 修复前 `CargoRuntimeDeployment::remove_stale_previous_outputs`（458–475 行）拼接 manifest 字符串后只检查 `starts_with(cargo_output_dir)`。
- `build/debug/../victim.dll` 能通过词法前缀检查；实际删除指向 profile 外。正常生成的 manifest 不含此路径，触发需损坏或被修改的本地清单；现有代码已明确试图拒绝越界，因此应补齐该约束。
- 最小修复：拒绝非普通相对路径分量，仅接受 profile 根或其 `examples/` 的直接文件，并在删除前验证规范化父目录位于规范化 profile 内；先校验全部旧记录，再删除。保持只清理由 manifest 托管且本轮不再使用的文件。
- 验证：全部在 `.temp/` 夹具内验证正常清理、`..`、绝对路径、任意子目录、指向夹具外层的目录 junction；拒绝时不得删除早先合法记录。

### Triangle / ShaderToy 未声明 native 前置条件（P2；B00 转入；已修复并验证）

- `justfile` 的两个 recipe 只有 `shader` 和 Cargo run；其 gfx 依赖最终进入 `truvis-vk-binding/build.rs`，需要 CMake 发布 Vulkan include roots/export header，链接并加载 `truvixx-vk-capi`。
- 已构建工作区的缓存掩盖缺口；最小修复是复用现有 `cxx-debug`，与 Cornell 入口一致，不改变 sample 的 Rust 分层或 shader package 依赖。
- 验证：两个 recipe 的 dry run 顺序与对应 sample 编译；完全干净环境和 GPU 启动需要另行验收。

### 扫描输出目录会重新托管已移除 target（P2；已确认；已在 B02-a2 修复并验证）

- `CmakeOutputScanner::native_artifacts`（修复前 274–300 行）扫描输出目录内全部 `.dll/.pdb/.lib`，再与显式 runtime plan 合并；旧 manifest 清理无法移除本轮又被扫描纳入的旧产物。
- 本机已存在直接反例：master 无 NR target，但 Debug/Release 输出中仍有 `truvixx-dlss-nr-capi`，部署 manifest 中也有旧 NR、gfx 与内部 STATIC 产物。未执行清理或改变这些文件。
- 不能只按三个 public target 名称过滤：Assimp 的 DLL 及 kubazip/minizip/poly2tri/pugixml/zlib 等间接依赖由 vcpkg `applocal.ps1` 在构建后复制；本机 `assimpTargets.cmake` 没有 `INTERFACE_LINK_LIBRARIES`，单靠 target graph 可能遗漏运行依赖。
- 续接：以当前 public SHARED target 和显式 sidecar 为根，核对 vcpkg app-local/runtime dependency 收集方式，形成准确的当前产物集合；然后替换整目录扫描。不得写死当前第三方 DLL 名单或加兼容扫描 fallback。需验证 Debug/Release、target 移除、第三方依赖变化与干净构建。

### 部署失败可能留下混合版本（P2；已确认；B02-a2 已修复预检与重试，事务回滚暂不实施）

- `CxxRuntimePackager::deploy` 先复制 native 输出，再遍历 sidecar；后面的 required 缺失、重名或复制失败可发生在部分输出已覆盖之后，旧 manifest 未更新。命令确实返回失败，不是成功误报，但磁盘内容不具备整体回滚保证。
- 本轮不承诺事务发布。与当前产物集合一起续查：先做完整输入与目标验证，再界定 IO 失败后的恢复和托管记录策略；不要把预检查等同于磁盘故障可回滚。
