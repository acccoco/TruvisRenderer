基准 `5b14171c`，`refactor`，初始工作区干净。复核 InputManager 全部方法、Truvis
on_input/cancel_interaction/update/after_prepare/resize 与 CameraController 的 pending/
active 状态和 clear 方法；承接 B13-c 的输入消费与失焦交接。

## 已确认问题与两组局部方案

1. **P1，帧边沿被重复事件清除**：InputManager::process_event 直接将 just_pressed/
   just_released 赋值为本次状态是否变化；Pressed→Pressed 或 Released→Released
   会擦除本帧之前已有的真实边沿。begin_frame 或显式 reset 才清零边沿；重复状态不能取消
   已观察的变化，也不能移动已记录的按下坐标。保持最后 pressed 状态与真实新按下
   时的坐标更新，不增加事件历史或双击策略。
2. **P1，交互取消不覆盖相机状态**：Truvis cancel_interaction 清理 input/gizmo/click
   probe，却不清理 Controller 的 pivot/pan/wheel pending 和 active 状态。无 acquired
   image 帧在 update 创建查询后跳过 after_prepare，下一帧失焦会停止相机 update，
   但旧 pending 仍可被 after_prepare 执行；wheel 结果甚至可修改已失焦相机。
   通过 Controller 的统一取消入口复用已有 clear_middle_button_control/clear_wheel_zoom，
   接入 Renderer 既有取消函数，不重置 Camera 位置或 temporal 历史。

架构预检：边沿属于 InputManager 的帧内状态；导航锚点归 CameraController，Renderer
只发出取消意图。复用现有 clear 方法，不增加 Runtime 能力、查询 epoch、异步线程或
通用事件框架。现有 raycast 同步且同线程执行，不需要处理跨线程迟到结果。两组分别
提交，相关 README 同步；不修改 docs/summary。
