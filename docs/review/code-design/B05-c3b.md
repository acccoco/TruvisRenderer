## 输入约束修复

- **P1，native range 数组长度未校验。** command 原先直接传给 ash；ash 外层数组检查不能保证每次
  build 的 range 数量。现在进入 native 前断言 ranges.len 等于 geometryCount，避免 native 越界读取。
- **P1，连续 instance buffer 对齐不足。** 原先只请求 buffer 的默认 8 字节对齐，改为明确请求 16。
  scratch 仍沿用设备要求，不依赖 VMA 分配顺序碰巧满足。
- **P2，AS 数量只检查表示宽度。** GfxResourceCtx 借用 root 已查询的 AS properties，替代单独复制
  scratch alignment；BLAS 预检 geometry 数和全部 primitive 总数，TLAS 预检 instance 设备上限。
  没有引入另一份能力注册表或运行期设备查询。
- **P1，RtGeometry 窄化和容量契约。** index count 不能截断；maxVertex 先减一再转 u32，拒绝空顶点。
  投影时检查完整三角形、当前 SoA/index buffer 容量、非零地址、4 字节对齐和地址范围不溢出。
  当前 CPU 校验已有属性长度/有限值/索引值检查，继续复用，不重新遍历 GPU 数据。

规范依据：[AS build 命令](https://docs.vulkan.org/refpages/latest/refpages/source/vkCmdBuildAccelerationStructuresKHR.html)、
[triangle record](https://docs.vulkan.org/refpages/latest/refpages/source/VkAccelerationStructureGeometryTrianglesDataKHR.html)、
[AS 设备属性](https://docs.vulkan.org/refpages/latest/refpages/source/VkPhysicalDeviceAccelerationStructurePropertiesKHR.html)。
这里只覆盖当前路径可证明的局部条件，不把 safe wrapper 等同于完整 Vulkan validation。

## 同步构建阶段修复

- **P1，已知安全阶段的组合资源遗漏。** BLAS 复用 new_blas_for_build 的 AS/scratch 交付，query 创建/
  reset 失败回收未提交对象；首次 build 等待完成后，query 读取或 compact AS 分配/naming 失败也回收
  初始 AS、scratch 和 query。TLAS 上传完成后，size 查询、AS/scratch 创建失败回收 instance buffer
  与已创建 AS。catch 不包住 one_time_exec，避免把失败的 submit/wait 当成已完成。
- **P2，临时资源诊断可阻断交付。** 成功等待后的临时释放采用已有无日志 release，AS 的私有方法
  改名为 release_idle，表达适用条件；最终公开 owner 仍由调用方显式 destroy，不依赖 Drop 释放。
- **P1，TLAS 输入缺少内存依赖。** instance 上传 copy 与后续 build 使用同一 immediate queue；
  原先只有 host wait，没有 device 写到 build 输入的可见性屏障。现在在 build 前录制
  TRANSFER/TRANSFER_WRITE → ACCELERATION_STRUCTURE_BUILD_KHR/SHADER_READ。
  与已有 mesh 上传的输入读取语义一致，不改变 queue/thread，也没有新建 RenderGraph pass。
  依据见 [同步规范](https://docs.vulkan.org/spec/latest/chapters/synchronization.html)；完成等待与内存可见性是不同条件。

保留显式 owner、窄 Ctx 和分段回收，未增加通用事务/回滚框架。同步 BLAS 的 geometry 描述会分别供尺寸
查询和录制使用，未以消除所有重复投影为理由改变公开 BLAS 输入或引入缓存 owner。
