# B16-a：DLSS feature 登记与释放失败

> 历史说明：本文项目 hash、提交次数及“本报告所在提交”均按压缩前历史解释，实验引用保留为“压缩前证据基准”；第三方版本不变。当前分组见[提交压缩映射](commit-squash.md)。


基准 `35b5067c`，`refactor`。覆盖 `TruvisDlssState`、Renderer 的调用时机及 native
free wrapper；不把本批入口核对当成整个 B16 完成。

## 确认的问题

- **P2：快照被当成 feature 分配证据。** snapshot 无条件写待释放 feature，但无 TLAS
  的 graph 不加入 DLSS pass。随后切换模式/resize 会释放未出现的 SDK viewport。
  固定 SDK 的 SR/RR 插件在找不到 viewport 时返回 eErrorInvalidParameter，不能只把
  原来的 warning 升级为致命错误而不修正登记时机。
- **P1：释放失败仍丢失归属并继续重配置。** release_feature 在 SDK 调用前 take owner，
  错误仅记录 warning，reconfigure 继续 set_options/reset；可能随后重建旧 feature 引用的 target。
  FFI 错误还可能来自部分执行后的 C++ 异常，不能推断完整回滚或自动重试安全。

## 局部处理

第一组提交将 snapshot 改为纯读取；只有含场景的 Realtime graph 在 begin 后、execute 前
登记可能创建的 feature。无场景/native/Offline 不建立虚假释放责任；录制中失败仍保留保守记录。
不在成功 submit 后才登记，否则 evaluate 已分配但提交失败的路径会丢失 owner。

第一组提交 `43d5a095`；第二组为本报告所在提交。

第二组用 `Unused / Recorded / ReleaseFailed` 表达互斥阶段。只有 free 返回成功才清空记录；
失败保存 feature 与原始 StreamlineError，reconfigure 直接返回，不执行 options/reset。
后续 release/shutdown 返回同一错误而不再次调用 SDK，begin_recording 拒绝覆盖失败状态。
shutdown 通过 Renderer 既有 expect 阶段出口传播，阻止继续销毁其后 target。没有新增重试、
fallback 或全局 cleanup 框架；不改变 SDK/C ABI、pass 顺序或 GPU idle 前置。

第一组验证：`cargo check --offline --locked -p truvis-app` 与 `git diff --check` 通过。
`.temp/code-design/B16-a/recording.py` 抽取真实 snapshot/begin_recording，使用 CPU mock
覆盖 native/SR/RR × 有无场景 × Realtime/Offline 的 12 种组合，在修复前后、debug assertions
开/关共 48 组检查中验证登记差异，并核对实际调用处位于 compute execute 前且受条件约束。
夹具不执行完整 graph 或真实 SDK，不能证明 GPU 生命周期安全。

第二组验证：`.temp/code-design/B16-a/release.py` 抽取真实 release_feature/reconfigure/shutdown
与修改后 begin_recording。无 feature/SR/RR × 新配置开关 × free 成败 × set_options 成败
共 24 种组合，在修改前后、debug assertions 开/关执行，共 96 组通过。确认失败保留原始
错误、停止 options/reset、重复 reconfigure/shutdown 不再次 free、失败状态拒绝再次录制；
正常无资源和成功释放路径保持可用。mock wait_idle 不证明真实 GPU 完成。
`cargo check --offline --locked -p truvis-app` 通过；修改文件 rustfmt 与空白检查通过。
未运行 GPU、真实 SDK free 故障注入或完整画面回归。

## 审阅保留与交接

- requested 保留用户选择，effective 受 SR/RR capability 和 Realtime/Offline 约束；内部尺寸
  改变交给 Runtime resize，同尺寸模式变化在 update idle 后重配置。没有证据支持新增一份
  pending 配置或通用 feature trait；保留单个 state owner 和显式 SR/RR 适配。
- release 错误后的 effective 仍可能是待切换配置，不能用它宣称 SDK 已配置成功；生产 hook
  立即传播错误并停止该路径，未实现恢复。记录的 feature 归属独立保留，不随 effective 覆盖。
- 登记是保守的：graph execute 在 SDK 前失败可能尚未创建 viewport；SDK 返回错误也可能在
  创建 viewport 前失败。本批不把所有 InvalidParameter 都吞成成功。后续退出收到此类错误
  仍停止；若要恢复必须先区分阶段，不能把错误码当作完整回滚证明。
- Renderer shutdown 仍可能因更早的 Client hook 失败而未进入 DLSS，Runtime/线程的后续
  unwind、Drop 诊断与 SDK shutdown 失败政策尚未闭合。本批没有声称“错误后可安全回收全部资源”。
  此项交 B16 后续生命周期收尾；需要全局错误模型的部分只进入 B27 方案。
- **下一批 B16-b**：当前 SR/RR evaluate 返回 Failed 后 graph 仍继续 SDR，输入仍选择 DLSS
  output，存在消费失败/过期输出的明确缺口；B15-a5 只保护 debug preview，未修主显示。
  必须结合 SDK 可能部分录制的命令、图像状态和历史确认决定处理方式，不仅替换 source handle。
  同时核对 reset、extent、MV/jitter 与 packed RR guide 契约。B16 总体保持部分完成。

后续 [B16-b](B16-b.md) 已通过 adapter 中止失败 graph 修复主显示入口，并完成上述时间状态与
资源契约复核；SDK/外层退出与初始化的剩余边界继续交 B16-c。
