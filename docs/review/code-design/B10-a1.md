# B10-a1：共享上传时间线的错误观察与关闭等待

> 历史说明：本文项目 hash、提交次数及“本报告所在提交”均按压缩前历史解释，实验引用保留为“压缩前证据基准”；第三方版本不变。当前分组见[提交压缩映射](commit-squash.md)。


基准 `f9ec6f99`。范围为 GpuAssetUploadQueue 的 poll 查询、shutdown 等待门槛和 pending
owner 保留，追踪 GfxSemaphore::wait_timeline 与 RenderAssetSystem 调用顺序。

## 发现与局部修复

- **P2：timeline 查询错误被吞掉。** `unwrap_or(0)` 将设备错误与未完成混为一谈，后续
  prepare 持续等待且无法观察原错误。改为带上下文的 expect，沿用现有 RHI 错误传播方式；
  查询成功前不弹出 pending，也不发布资源。
- **P1：shutdown 在等待前取走 owner。** wait 的 timeout/设备错误会 panic，局部 semaphore
  和 pool 随 unwind 丢失，queue 字段为空但 pending 还在；再次 shutdown 可误标为 destroyed。
  改为先借用 semaphore 等待，确认成功后才 take 并清理，失败不释放仍可能被 GPU 引用的对象。

保持现有单渲染线程、显式销毁、FIFO 和共享 timeline 结构；不新增重试线程、兼容 API 或
错误吞噬。上层若继续 unwind，原有 Drop 断言和 Runtime 退出策略仍适用；本修复不承诺
device-lost 后继续渲染，不替上层选择重试或终止。同步模块 README，未改 GPU ABI。

## 验证与交接

`.temp/code-design/B10-a1/{run.py,mocks.rs,main.rs}` 编译原始/修改后的实际 pending 类型、
queue 字段、poll、shutdown 与 Drop；排除本轮未覆盖的构造/提交方法和 Tracy instrumentation，
用受控 RHI 替身注入 counter 查询错误、wait timeout/设备错误并记录释放调用。

新旧版本在 debug assertions/overflow checks 同开、同关时各运行 10 类场景：空/部分/全部
完成、查询错误、单纹理/混合 texture+sky 等待超时、直接再次关闭、等待设备错误、空关闭、
重复关闭。旧版查询错误返回空完成集合；等待失败丢失 semaphore/pool，再次关闭误标销毁
且 pending 残留。新版错误可观察、失败不释放或移出任何 owner；模拟完成后恢复 poll 或
再次关闭，command/staging/image/distribution/semaphore/pool 各释放一次。正常 FIFO 与
typed completion metadata 保持原行为。

替身把叶子 Drop 断言改为记录丢失，以观察旧状态而不使测试进程二次 panic；实际 debug
运行可能在 unwind 中触发断言终止。模拟错误消除仅用于验证 owner 保留，不证明真实设备
丢失可恢复。未运行 GPU，不覆盖 native driver 同步、已完成对象释放时的 logger panic、
构造/提交失败或跨 queue 可见性。
