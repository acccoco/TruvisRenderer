## P1：旧语义缓存没有失效入口（已修复）

原实现只在 SharcTargets 创建时清零。scene scale 直接参与 hash 的坐标解释，却没有
同步清理；同一 world-space key 的材质、transform、光照或环境改变也会继续使用旧
resolved 数据。Resolve 的 32 帧混合和 64 个维护帧淘汰不等同于语义失效，Off 下还会
冻结历史。该结论来自创建/建图/录制链，不以编译或未执行的画面对比作证。

RealtimeRenderSubsystem 复用同帧 RenderSceneAccumSignature 的六个版本，并加入
scene scale 与 sky/emissive/analytic NEE 配置。有效 scale 先断言有限且为正，再用 bits
参与相等比较；这只是签名入口约束，不是任意世界坐标或极端正 scale 的数值支持证明。
版本来源已追到 RenderWorld prepare：TLAS revision 是语义版本，不随普通 FIF 轮转
递增；appearance 覆盖 active instance 的 transform、material binding 与外观变化。

签名作为既有 RealtimeFrameCommit 的一部分，仅 queue submit 正常返回后确认。丢弃
图不推进历史；已提交 Off / 无 TLAS 帧置空，重新启用冷启动。Update↔On 继续复用；
相机、resize、FIF、DLSS、debug 和 SDR 不进入签名。资源重新 init 清除 CPU 签名。

RT pass 借用 descriptor 对应的三个 live buffer handle，在 Update 前同一 command
buffer 中 fill 0：RT read/write + CLEAR transfer-write → CLEAR transfer-write，
fill 后复用入口 barrier 发布到 RT。两个快照仍在 Snapshot 全量覆盖。没有新增
shader phase、ABI 字段、descriptor、队列、Engine 能力或 CPU wait；两个 Rust pass
参数结构增加 sharc_reset，现有唯一构造链同步转发。资源 owner 与销毁责任不变。

代价是失效时全表写 160 MiB；首次启用保守清理一次，即使初始化已经清零。连续动画
可能每帧失效并降低 cache 收益；未测量性能。保持正确失效优先，不引入局部脏区框架。

## Query 结论与参考边界

重新核对 RTXGI v2.7.0 父 commit `19b9be9e58ce2bbb6470b9444fa87e93a2dc4c4e` 与
SHARC 子库 `0b9f58bbc8c41736042d4da964830a247e424a00` 的 docs/Integration.md、
SharcCommon.h。沿用非 primary、段长/voxel 和 roughness² cone 守卫；本地额外拒绝
当前 delta 与上一段 delta，纯 emission 在 query 前退出。

Query 的 sample threshold=0，成功时直接返回 resolved 反射 radiance；本地 demodulation
与 separate-emissive 宏关闭。主路径先计本地 emission，再将缓存乘 path throughput，
命中立即 break，不重复 NEE 或 BSDF continuation。未发现此接线中的重复 emission
或权重遗漏；缓存本身的方向压缩、法线分桶、anti-firefly 与固定深度仍是近似，不宣称无偏。

## 验证

临时材料位于 `.temp/code-design/B20-b3/`，无永久单元测试。

- `check-history.py` 抽取实际签名构造、建图判定与提交函数，28 项通过：六个 scene
  版本、三个采样配置、scale、丢弃候选、Off/无 TLAS 与恢复、Update↔On、非法 scale。
  另核对 init 和 owner→graph adapter→pass 的 reset 接线；场景版本生产仍以源码追踪为证。
- `check-paths.py` 抽取实际 Rust 维护块，30 组 mode/reset/capacity 通过；Off 不写、
  reset 恰好先清三个 live buffer、依赖范围正确，随后 Update→Snapshot→Resolve，
  全表 extent 覆盖容量，最后 phase=None。没有以重写的控制逻辑替代待测录制块。
- 实际 should_query 的 1200 组有限输入与独立 double oracle 一致；实际
  SharcGetCachedRadiance 在 mock hash/voxel 下的 24 组结果正确。额外静态核对
  emission→query→NEE 顺序和 throughput/break。mock 不包含实际 hash、fp16 舍入、
  GPU path、非有限输入或 glossy 画面误差，后者不由这些计数证明。
- `check-sync.py` 提取两侧实际 barrier scope，以 compute 模拟 RT 访问。RTX 4060 /
  API 1.4.351 / SDK 1.4.335.0 上，故意移除清理前依赖的 init/reuse 各产生一条
  WRITE_AFTER_WRITE / WRITE_AFTER_READ；完整依赖均零诊断且 submit/wait 完成。
  缺陷命令只录制后丢弃；shader-access heuristic 仅在探针子进程启用。
- `cargo check -p renderer-render-passes -p renderer-rendering -p truvis-renderer` 通过。
  shader 与 GPU ABI 未改，保留 B20-b2 的 shader/SPIR-V 验证记录；未重复完整构建，
  未运行完整 SHARC 场景画面或性能验收。`git diff --check` 通过。
