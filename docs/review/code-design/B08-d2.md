# B08-d2：Assimp 材质转录

> 历史说明：本文项目 hash、提交次数及“本报告所在提交”均按压缩前历史解释，实验引用保留为“压缩前证据基准”；第三方版本不变。当前分组见[提交压缩映射](commit-squash.md)。


基准：`refactor` 的 `e587fd84`。B08-d2 收敛到 native→Rust 的材质范围；几何容量、
静态形变、FBX 坐标/单位及 importer 构造继续交 B08-d3，不将这些未验收项标记为完成。

依据：`cxx/vcpkg.json` 固定 Assimp 5.4.3，实际安装 ConfigVersion 同为 5.4.3；已核对
vcpkg 源码 `v5.4.3-ee50b368a2.clean` 的 ObjFileImporter、FBXConverter、MaterialSystem、
material.h，以及 [上游 v5.4.3 material.h](https://raw.githubusercontent.com/assimp/assimp/v5.4.3/include/assimp/material.h)。
OBJ 的 Pm 与 FBX 的 Maya metallic 均写 metallicFactor，reflectivity 是另一个属性。
本批不更改 OpenPBR/现有 BSDF，目标是保留输入已表达且现有 CPU 类型可承载的字段。

## 标量与发光，已修复

- **P1：metallic 使用了错误属性。** native 原先只读 REFLECTIVITY，丢失真正的
  METALLIC_FACTOR；现在只读后者，无此值保持原有 0。未增加 reflectivity 的兼容推断。
- **P2：PBR base color 与 emission intensity 被遗漏。** 现在优先 BASE_COLOR，缺省
  才读 COLOR_DIFFUSE；强度有限非负，乘 emission RGB 一次。不是把两个颜色重复相乘。
- **P1：带 emission 的材质丢失散射类别。** Rust 原先优先构造专用 Emissive；现在保持
  opacity 决定的既有 Surface/Transmission 分类，把颜色放入已有 emissive_factor。
- **P2：非法输入被 clamp 隐藏或延后失败。** 在类别构造前检查有限 base color、有限
  非负 emission 及 [0,1] metallic/roughness/opacity。HDR emission 继续允许；不扩展
  通用 World 材质校验，也不更改其它 importer 的契约。

owner 仍为 SceneImporter 的私有转录与 TruvixxSceneReader；native 材质转换返回 bool，
失败保留 last_error，经现有 C API/guard 释放。公共 ABI、线程、依赖和 GPU 数据形状不变。
opacity < 0.99 → Transmission、固定默认 IOR、Opaque coverage 仍是项目近似，交 B17；
本次不得据此声称透明度、折射、specular/glossiness 或 OpenPBR 模型已正确实现。

验证临时文件位于 `.temp/code-design/B08-d2/`：

- `material.cpp` / `native.py` 分别编译基准与当前实际 SceneImporter，链接实际 Assimp DLL。
  16 个案例覆盖缺省、diffuse/base 优先级、独立/同时存在的 reflectivity/metallic、零/
  单位/HDR/负/NaN/Inf emission intensity、opacity/roughness 和真实 Pm/Pr/Ke OBJ。
- `run.py` 编译基准与当前完整 Rust Reader，18 个可控 FFI 输入验证类别、数值拒绝、HDR
  emission 与 guard 释放；真实 OBJ 验证实际 native→Reader 数据。两个 Reader 版本均链接
  当前 native DLL，native 的新旧差异由前一条独立验证，不能将两层混为旧版完整链路。
- 新旧 Reader 的夹具断言/溢出检查同开、同关均通过。依赖/native 使用 Debug 构建，
  不称为完整 Release 验证。`just cxx-debug`、asset 构建及 world 检查通过；未运行 GPU。

标量修复提交：`f32c4dfa`。GpuMaterialStore 与 emissive light table 均读取
`emissive_factor + class.emissive_radiance()`，MaterialAccess 和 raygen path state 消费合并后
的 emission；已静态核对，未据此宣称 GPU 画面或能量正确性通过。

## 纹理引用，已修复

**P1：embedded key/槽参数被丢弃，仍作为外部路径发布。** native 原先直接拼目录，
只取第一层 DIFFUSE/NORMALS。当前颜色槽优先 BASE_COLOR，缺省时 DIFFUSE；消费槽必须
单层、UV mapping/UV0、identity transform、repeat、multiply、blend=1、无额外 flags。
不满足时返回带材质名的失败。空路径/内部 NUL 失败，`*index` 和 aiScene 识别的具名
embedded texture 均失败，避免后续把内嵌资源误作缺失磁盘文件。

保持现有局部 lambda 和路径型 C ABI，不新增动态 ABI、纹理解码路径或通用能力注册表。
这些输入可能是合法 Assimp 材质；失败表示当前路径不能保留它们的含义。普通 repeat 外部
路径仍按 UTF-8 返回绝对路径，文件存在性与长期身份继续由 AssetSystem 处理。

纹理修复提交：**本报告所在提交**，为本批第二个提交。

- `texture.cpp` / `texture-native.py` 对比 `f32c4dfa` 与当前实际 SceneImporter，55 个
  native 案例通过：DIFFUSE/BASE_COLOR/NORMALS 各覆盖默认/显式 identity、内嵌索引、
  空路径、多层、UV1、非 UV 映射、clamp/mirror、blend/op、平移/缩放/旋转/NaN 和 flags；
  另验具名 embedded、base/diffuse 优先级、真实 repeat/clamp OBJ。受控 aiMaterial
  验证转录边界，不冒充所有文件格式都能产生每种属性。
- `real-texture.py` 经实际部署的 C API DLL，5 个文件案例验证 repeat、clamp、embedded、
  external 和 PBR OBJ；失败返回非空可查询句柄、is_loaded=false、明确错误，均对称 free。
  embedded glTF 含有效 PNG 字节，但只验证引用分类，没有执行像素解码/GPU 上传。
- 最终 `just cxx-debug` 与 `cargo check --offline --locked -p truvis-asset -p truvis-world`
  通过；空白检查通过。完整 Rust Reader 的验证已在第一提交执行，第二提交未修改 Rust。

## 范围与后续

B08-d2 材质约定范围已扫描并完成上述局部修复。当前仍只支持颜色/normal 外部贴图，
未消费 emission、metal/roughness、opacity 等其它贴图类型，也不保留独立 IOR、doubleSided、
完整 shading model；相应能力需要 native payload、CPU 材质和 GPU 消费配套，交 B17，
不能以本次入口检查充当完整 Assimp/PBR 合规证明。

下一批 **B08-d3：native 几何、静态场景与生命周期**，继续检查极端计数、生成法线/切线、
UV0 缺失却补零、多 UV/顶点色、skin/morph/动画、相机/灯光、FBX 坐标/单位以及 importer
重复创建。最终全局修改不实施；B08 父项仍部分完成。
