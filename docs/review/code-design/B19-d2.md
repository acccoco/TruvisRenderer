## P2：历史坐标缺少实际采样 jitter 差

primary ray 使用 `pixel + .5 + jitter_current`，共享 MV 是同一点的无 jitter 投影
`previous_pixel - current_pixel`。历史数组索引须为
`pixel + MV + jitter_current - jitter_previous`，旧代码只有 `pixel + MV`；相邻搜索
可能弥补但不能保证命中。previous jitter 必须对应被引用的实际提交帧，不能由 frame_id
重算，或取已被 reconfigure 重置的 DLSS 序列索引。

架构预检：RealtimeRenderSubsystem 复用既有 RealtimeFrameCommit 保存当前
DlssFrameSnapshot 的 sampling_jitter_offset；只有 submit 返回后推进，连续性/reset
检查无效时差值归零。Realtime RT pass 通过自己的 push constant 传差值，使用尾部
预留的八字节，保持总长 64 字节与此前字段 offset。不增加 Engine ABI、持久资源或
线程，不改变共享 MV、DLSS constants 或资源 owner。同步 temporal-state/sampling design。
第一项修复已实施并验证，提交为 `d203ebbd`。

临时证据在 `.temp/code-design/B19-d2/`：

- `check-jitter-state.py` 抽取实际 signature、建图捕获段和 finish_rendered_frame；8,192
  组 jitter/mode/连续帧/版本/reset/无 TLAS 来源组合，错误差值 168 → 0。另验证首次帧、
  丢弃候选不推进、提交捕获值及无 TLAS 提交切断历史。

  565,056 → 0，其中静态零 MV 错误 14,904 → 0，O0/O2 一致。使用可精确表示的二进制

## P1：current history-bearing 图像丢弃布局未表达上一帧读取

三 FIF 下，帧 N 写槽 N%3，N+1 将该槽作为 history 读取，N+3 再覆盖。CPU 等待的是
N 完成，不单独保证 N+1 已完成。current temporal/surface 以 UNDEFINED_TOP 导入，
其 UNDEFINED→GENERAL 转换的 source scope 未表达额外 history 读取。pass 内 PATH
之后的 phase barrier 无法追溯约束此前 layout transition；不能依赖另一张 history
图像的 broad barrier 替当前图像定义完整布局契约。

现复用现有 RT storage read/write 状态导入 current temporal/surface，保留 GENERAL
布局并明确同 queue 上的先前 RT 读取/写入。initial/final 不跨帧作为 history，保持原策略。
无需增加 host wait、queue 或通用 graph 状态框架；owner、descriptor 和资源数量不变。
第二项修复与本报告所在提交一致，sampling design 同步说明。

依据 [Vulkan Synchronization and Cache Control 的 layout transition 契约](https://docs.vulkan.org/spec/latest/chapters/synchronization.html#synchronization-image-layout-transitions)，
布局转换必须在旧布局访问完成之后；它本身可能访问内存，不能把“之后的 shader 被等待”
当作转换已正确受约束。2026-10-29 核对并用本地 SDK 1.4.335.0 / validation layer 验证：

- `check-sync.cpp` 在 NVIDIA GeForce RTX 4060（API 1.4.351）构造最小 image→buffer
  读取，再用同一次 vkCmdPipelineBarrier2 对 A 丢弃布局、对 B 设置 broad GENERAL
  依赖。旧范围得到一次 `SYNC-HAZARD-WRITE-AFTER-READ`，明确定位 A 的 layout
  transition；故意有缺陷的命令只录制后丢弃，不提交。
- A 保持 GENERAL 并包含先前访问后，validation errors=0，queue submit/wait 完成。
  探针用 TRANSFER 读写复现同类依赖，没有运行实际 TraceRays 或测量画面/性能；不能将
  这次通过扩大解释为全项目 GPU 同步验证。
- `check-graph.py` 编译实际 RenderGraph 源码，提取修复前后六组 ReSTIR import 状态，
  并检查 helper 四个通道都传递该状态。24 个实际生成的前置 barrier 中，current
  temporal/surface 八个 plane 的完整历史来源范围由 0/8 → 8/8；initial/final 和 history
  状态不变。999 个帧号的 previous slot 映射一致。mock 资源不执行 Vulkan。
  夹具最初假定 barrier 顺序等于声明顺序，断言失败；改按 graph handle 对应检查，
  不改变生产 graph 的遍历方式。
- `cargo check -p renderer-rendering -p truvis-renderer` 和空白检查通过；第二项不改 shader，
  保留第一项实际 shader 构建与布局证据，不重复完整构建。

## 留存边界

资源版本由各 owner 产生，shader 比较 sky/emissive/analytic 三类值。u32 light revision
饱和后停止区分编辑是 [B09-c](B09-c.md) 已交 B27 的全局容量问题；本批补查 emissive
与 sky distribution 同样使用 saturating_add，不能以改一个 ReSTIR predicate 修复 producer
停止上传/区分身份的问题。必须连同版本生成、对账、上传和失效统一制定耗尽策略。

CPU 配置签名、scene 版本、连续 frame_id 和显式 reset 共同拒绝旧历史；本批与 c3b
夹具覆盖首次、无 TLAS 来源、跳帧和配置/reset 组合。实际建图无 TLAS 时只清屏，commit
的 frame_id=None；submit 后才确认，未提交不推进 jitter/连续帧。Off/InitialOnly→Temporal
因 mode 签名不同拒绝旧槽；resize 在重建前请求 reset，场景失效由 after_prepare 合并，
只有含场景的 Realtime submit 后消费 reset。shader history_valid=0 时不进入 history 搜索。

每帧 current/history 绑定不同 FIF 槽，history 只用 temporal；spatial 不跨帧回灌。
RT pass 的 PATH→TEMPORAL→SPATIAL→FINAL 之间有 RT read/write image barrier；mode
决定省略的阶段，InitialOnly final 直接选 initial。descriptor 每 FIF 一份，CPU 等待该 slot
旧提交后更新；下一帧读取 history 使用下一帧自己的 descriptor，不延长旧 descriptor 的引用。
这些是源码与局部 recorder 证据，不代表完整 GPU 调度/画面验收。
