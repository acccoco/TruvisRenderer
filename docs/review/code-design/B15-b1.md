## 修复前发现

- **本批修复**：contribute 在建图时更新 initialized、last_mode、pending_snap。
  丢弃 graph 或 compile/record/submit 失败时，CPU 已宣称初始化或首次曝光适应完成。
  正常失败仍终止 RenderThread，不能据此宣称已复现下一帧错误画面；状态契约偏差确定。
  按 B15-a2 模式返回私有字段的提交候选，queue submit 正常返回后才消费。
- **本批修复**：SdrResources 依次销毁 histogram/exposure/lut，首个释放日志异常会
  跳过后续 target。沿 B15-a3 的已知安全清理契约完成组内释放，再传播首错。
- **后续审阅**：LUT 上传额外 barrier 的说明仍称通用 helper 只可见于 fragment，
  但当前 GfxImage::transfer_data 已以 ALL_COMMANDS/SHADER_READ 结束；需核对冗余 barrier。
  LUT 上传、AutoExposurePass 三 kernel 和 SdrResources 的组合构造失败仍需分阶段判断。

## 架构边界

显示历史仍由 SdrPostProcess 独占，固定大小 image 不随 FIF 或 resize 重建。
使用同次 render 的栈上候选，不新增全局事务、跨帧 pending owner 或通用状态框架。
无输入的已提交清屏可确认模式变化并保留 pending snap，但不初始化或更新曝光 image。
锁定/非 Final 不消费 pending snap；Offline 仍即时测光，Manual 不启用自动测光。
queue submit 返回不是 GPU 完成；不改变 pass 顺序、barrier、算法、ABI 或线程边界。

首组 `335ab29c`。SdrFrameCommit 字段私有、非 Copy/Clone，contribute 改为只借用
owner；Renderer 保存本次候选，submit 返回后先确认 SDR，再确认主视图并通知 DLSS。
候选只能配对同 owner/同次 render；这不是跨 owner 的全局原子提交或异常恢复机制。

`.temp/code-design/B15-b1/run-state.py` 编译实际 contribute 与状态类型，用 CPU graph
记录器对照：丢弃首帧/重试、正常连续帧、无输入丢弃/提交、锁定、非 Final、Manual→Auto、
模式切换丢弃、Offline 连续测光与锁定切换，10 类 × 前后版本 × debug 开关，**40 次通过**。
旧版建图即推进，新版只在确认后更新；检查 pass 顺序、初始化 import 状态及 instant 参数。

`run-submit.py` 提取实际 Renderer submit 尾部，替换 queue/state owner：Realtime/Offline、
有场景/清屏、成功/失败、debug 开关，共 **16 次通过**。失败只有 submit 事件；成功为
submit→SDR→主视图→DLSS，保留 scene_submitted 返回与 ReSTIR reset 条件。
这不模拟 GPU 内容、未知提交结果或提交后 logger/DLSS 异常的全局恢复。
App 编译、空白检查通过；未执行 GPU 验收，未新增源码单元测试。

第二组为本报告所在提交。三张 target 在原释放顺序上延后诊断传播；三个 pass 的
native pipeline/layout 先释放，再处理 target。`run-release.py` 提取实际 SdrResources
字段与 destroy，对替身的 histogram/exposure/lut 逐个和同时注入释放诊断，含正常路径，
5 类 × 前后版本 × debug 开关，**20 次通过**。旧版在首错截断，新版完成全部调用并
保留首错。替身只检验 owner 调用顺序，不模拟 native release 或 Drop 二次 panic。
底层 target 清空 handle/完整释放的契约沿用 B15-a3；App 编译和空白检查通过。

本批共 76 次 CPU 状态/顺序检查。没有 shader/ABI 变化，未做 GPU 验收。
