## 范围与边界

实际读取 descriptor macro/trait、GfxDescriptorSetLayout/Set、GfxDescriptorCursor/WriteDescriptorSet、GlobalDescriptorSets、ComputePass，全部生产 derive 声明和 Slang `vk::binding`。两层 binding build.rs、聚合 header、基础转换用于确认职责，结构内存布局留给 B03-b；include 预检留给 B03-c。

Rust layout 描述 CPU 侧 descriptor type/count/stage/flags，Slang owner 描述 shader 可见资源；宏没有反射 shader，也不能凭 derive 证明两端一致。当前是需要联动维护的两份投影，不能为了减少重复在本批另建反射框架。set 0/1/2 属于 Runtime 全局 sampler、bindless SRV、frame/scene；pass-local set 由 ABI 的 set 常量与 pipeline layout 组合决定。

## 发现及本批处置

### P2：非法宏属性被静默接受（已修复并验证）

临时 rustc 夹具确认：字符串 binding、list 形式 descriptor_type、非字符串 stage、重复 binding、重复属性、缺少 binding 均可编译；部分结果丢失字段或退回默认 UNIFORM_BUFFER/stage。`VERTEX|FRAGMENT` 因只按带空格的 ` | ` 切分而编译失败。

本批修复：现有 proc macro 入口解析到单个职责明确的字段配置 struct；显式错误不再使用默认值，默认值只用于真正省略的可选属性。每个字段要求 binding，重复属性/编号和生成方法名冲突在派生阶段报错；flags/stage 按 `|` 分隔并裁剪空白。保留现有 getter/trait API 和可引用生成 ABI 的 count 表达式，layout 列表复用 getter 的同一份配置，不增加 attribute 兼容语法或自动 shader 反射。修正 trait 中不存在的 `shader_layout` 示例，以及把纹理写成 dynamic uniform buffer 的示例偏差。

### P2：descriptor 写入数量和 payload 契约缺失（已修复并验证）

两元素加速结构夹具产生 `VkWriteDescriptorSet.descriptorCount = 1`，但 pNext 的 `accelerationStructureCount = 2`。现有生产 TLAS 调用都传单元素，尚无实际画面错误证据；这是公共数组写入能力的确定性错误。

同一夹具确认 `write_image` 可向 ACCELERATION_STRUCTURE_KHR binding 写入 image payload，cursor 也允许越过自身 binding 容量。前者会把 descriptor type 与实际读取数组分离，后者违反 cursor“对应 binding”的局部契约。

本批修复：在已有 GfxWriteDescriptorSet 检查支持的 descriptor type 与唯一非空 payload，数量从对应数组取得；cursor 在构造时检查非空与单 binding 范围。不扩展到 texel buffer/inline uniform 等未承载的类型，不允许 cursor 隐式跨 binding 写入。`to_vk_type` 经全仓调用搜索确认只在 with_writes 内使用后收为私有，避免暴露缺少 acceleration pNext 的基础投影；这是本批唯一 API 可见性收窄。pNext 数组继续由同步回调作用域持有；资源 handle 有效性与 GPU 使用期仍属于调用方。

依据：[VkWriteDescriptorSet](https://docs.vulkan.org/refpages/latest/refpages/source/VkWriteDescriptorSet.html) 的类型/数量与 consecutive binding 规则，以及 [VkWriteDescriptorSetAccelerationStructureKHR](https://docs.vulkan.org/refpages/latest/refpages/source/VkWriteDescriptorSetAccelerationStructureKHR.html)。Vulkan 本身允许满足条件的连续 binding 写入，本项目 cursor 的范围更窄，不能把本地约束误写为 Vulkan 全局限制。

### P3：descriptor 说明与实现不一致（已修复并验证）

SHARC ABI 注释称其为第二个 push set，但 Rust 使用 flags 为空的 regular set，持久 buffer 在创建时写入。修正为 set 3 push、set 4 regular 的当前契约，并纠正资源属于 Renderer 的说明；不改 Slang 字段、binding 或管线顺序。GFX 注释不再宣称泛型关联即可证明布局正确。

## 对照结果与保留项

| 范围 | layout / binding 数 | 结论 |
|---|---:|---|
| Runtime 全局 sampler/SRV/frame+scene | 3 / 4 | set 0/1/2 顺序一致；sampler 数量使用生成枚举，SRV 固定容量 1024，shader 两者为 runtime array |
| Engine raycast | 1 / 3 | set 3，TLAS + 两个 storage buffer 一致 |
| Realtime RT 与 SHARC | 2 / 35 | set 3 的 32 个 binding 与 set 4 的三个 storage buffer 一致 |
| Offline RT 与 ImGui | 2 / 3 | 各自 set 3 资源类型与数量一致 |
| SDR/resolve/image clear/exposure/accum/outline | 6 / 12 | 各自 set 3，storage/sampled image 声明一致 |

从实际 Rust 声明编译出的 metadata 对照 Slang 声明，再解析 31 个现有 SPIR-V 的资源 type、DescriptorSet、Binding、数组形状及 OpEntryPoint 使用阶段，97 处资源使用全部匹配；57 个声明 binding 均至少有一处产物覆盖。runtime array 只确认宿主有正容量，不把 SPIR-V 反射当作运行时索引不越界的证明。

保留现有宏与 trait 分工、getter 的 OnceLock 和类型化 layout：它们分别服务派生、稳定 metadata 与调用方类型关联，没有证据需要引入新的反射注册表。Rust/Slang 手工 descriptor 声明存在联动成本，当前未发现两端 drift；全局是否合并生成机制交 B26。descriptor pool/slot 退役和 shader 实际 image 格式/资源状态分别交 B06、相关 pass 批次。
