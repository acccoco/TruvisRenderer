## 已确认问题与本批方案

### 清理边界与整批预检不足（P1，临时夹具已复现）

`managed_output_from_manifest` 只做词法 starts_with；输出下 junction 指向别处时，旧 manifest 的 `escape/victim.spv` 会删除根外文件。临时 victim 与 junction 均在 `.temp/code-design/B02-b3/`，没有操作项目外数据。

`remove_stale_outputs` 边校验边删；旧清单先有合法 stale，后有 `../victim.spv` 时，构建报错但 stale 已删除。`remove_stale_depfiles` 和空目录清理忽略 WalkDir 错误，也未先检查整棵目录的链接边界。

`collect_tasks` 未检查目的地身份。两个 package 的 output_prefix 分别为 `fixture`/`FIXTURE`、同名 entry 时，Windows 实际写同一个 SPIR-V；夹具返回成功且覆盖旧文件。`.state` 亦可作为普通 output_prefix，与构建器自己的状态命名空间混用。目录占位目前可能被空目录清理静默移除，不适合当作任务输出预检。

方案：在任何删除/编译/状态发布前，验证全部当前输出、正式/临时 depfile、状态路径和历史受管输出；按平台大小写身份检查冲突及文件/目录前缀冲突，拒绝保留目录与非 SPIR-V 历史输出。配置输出根是可信物理根，其内部拒绝 symlink/reparse point，包括 junction；先完整枚举清理计划，再执行。不是针对并发恶意替换目录的沙箱。

### 失败的新产物失去归属（P1，已复现）

`run` 只在全部任务成功后保存 manifest。已有成功状态后新增 `new.slang` 与会失败的 `bad.slang`；new 成功、bad 失败时，new 不在旧 manifest。删除这两个 entry 再重跑，旧实现返回成功却留下 `new.slang.spv`。

方案：状态同时承载成功缓存与产物归属。发生输出工作前，先保存未完成状态和旧/新输出并集；失败后继续保留归属，下一次不能复用未完成缓存。全部编译、清理成功后才缩为当前输出并标记完成。只增强重试，不保留旧版本输出，不承诺多文件原子回滚。

### 状态覆盖写可能损坏唯一恢复依据（P1，静态确认；发布失败边界已验证）

`ShaderBuildManifest::write_if_changed` 直接 `fs::write` 覆盖 JSON；写入中断或磁盘失败可留下无法解析的状态。Windows 夹具在允许读写、禁止删除的文件句柄下证明旧实现仍直接改写原文件。方案沿用项目既有的同目录临时文件 + rename 发布；临时文件用独占创建，避免覆盖链接到其他文件的旧临时 inode。发布失败保留原 JSON；不宣称覆盖断电持久性。

## 设计判断与验证边界

冗余：Shader 与 CXX 都需要预检/归属，但受管产物、输入与失败策略不同，复用模式而不新增通用部署框架。过度抽象：保留 runner、layout、manifest，增加明确的清理计划承载整批预检结果；不新增任意插件、兼容 API 或全局错误模型。严密性：以“先预检、先记归属、成功后发布缓存”闭合失败链。

修复前七个场景见 `.temp/code-design/B02-b3/results-before.json`、`probe.py`；假 compiler 只验证进程/文件状态。实际 Shader/GPU 正确性不能由这些夹具证明。

## 修复与验证

三个问题均已局部修复并完成对应验证，本报告所在提交为修复基准：

- `ShaderBuildLayout::check_output_path/output_key` 检查文件类型、每层链接与物理祖先，Windows 身份不区分大小写；当前目的地和旧归属都经过同一边界检查。`ShaderOutputPlan` 收集整批任务和清理文件，重复或文件/目录前缀冲突先报错。只把配置输出根视为可信根；不跟随根内 junction。
- 状态 v8 包含 `completed` 与 `managed_outputs`。输出工作开始前先写未完成状态和旧/新并集；编译后执行已经预检的清理，最后写当前成功集合。中途失败时保留并集，下一次全量重验任务。v6/v7 仍只提供已经确认同根语义的历史归属，不复用其缓存。
- 状态写入先独占创建同目录临时文件，写完关闭后 rename；旧临时文件先 unlink，避免覆盖 hardlink 指向的数据。不是原地 truncate JSON，也不提供断电事务保证。
- 没有改变 Shader public API、参数、ABI、Rayon 调度或业务渲染；工具 README 和设计约束同步更新。B02-b1/b2 的历史状态断言已注明被替代的范围。
