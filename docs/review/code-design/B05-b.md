# B05-b：GPU resource owner

> 历史说明：本文项目 hash、提交次数及“本报告所在提交”均按压缩前历史解释，实验引用保留为“压缩前证据基准”；第三方版本不变。当前分组见[提交压缩映射](commit-squash.md)。


基准：`refactor` 的 `20be07e6`，工作区干净。首轮读取 buffer、image、view、sampler、VMA naming、special buffers、vertex layout，以及直接上传/映射调用方。本轮 B05-b1 只闭合主机映射和 index 上传；B05-b2 接续叶子构造失败、image/view/sampler，SBT 与 acceleration 的组合构造随 B05-c 检查。

## 已确认问题与本轮范围

- **P1，主机映射访问缺少边界。** `resources/buffer.rs::transfer_data_by_mmap/transfer` 不检查容量，后者通过共享引用直接产生 `&mut T`，未检查对齐；`special_buffers/structured_buffer.rs::mapped_slice/mapped_slice_ref` 对任意 T 构造引用，未证明字节已初始化、T 任意位模式有效或实际分配足够。`DerefMut` 还允许替换 inner buffer，因此检查不能只依赖构造时的元素计数。Runtime 的 scene/light/material/raycast 使用这些接口，不能仅以当前数据通常对齐为反证。本轮收紧类型、独占借用、实际容量和对齐检查；不重设跨层 GPU 同步/同 allocator 生命周期模型。
- **P1，index 上传类型错配。** `special_buffers/index_buffer.rs::new_with_data` 为 `T` 分配，却固定接受 `&[u32]`；u16 specialization 上传字节数是容量两倍。当前没有该便捷入口调用方，但公开泛型接口可直接触发。应使用 `&[T]`，并在分配前检查数量乘法溢出。

## 后续已定位项（处置见续接报告）

- **P1，叶子构造失败回收。** buffer 在 VMA 分配后 map/debug naming 失败泄漏；image/view 在 wrapper 创建后 naming panic 会再触发 Drop assertion；sampler 在 naming 后才交付 wrapper。特殊 buffer 的重复 naming、SBT 查询/flush、上传闭包和 one-time helper 也有失败组合。B05-b2 先闭合直接叶子构造，GPU work 提交后的回收必须交 B05-c 证明完成条件，不能简单 catch 后立即释放。
  后续状态：直接构造回收与重复 naming 已由 [B05-b2](B05-b2.md) 修复验证；组合上传收尾仍交 B05-c。
- **P1，view 描述投影错误。** `image_view.rs::new` 忽略 `view_desc.layer`，固定创建 layer 0/count 1，而缓存描述仍保留调用方的范围。B05-b2 修复并验证 native create info。
- **P2，格式表终点遗漏。** `image.rs::pixel_size_in_bytes` 把本应包含终点的枚举范围写成半开；仅单独补 RGBA16F，BGR/BGRA sRGB、RGB16F 仍落入 unsupported。B05-b2 已修复并对照本地 Vulkan registry 验证；view layer、尺寸/字节数与 concurrent family 投影也已修复，见 [续接报告](B05-b2.md)。
- buffer `destroy_mut` 留下 device address，特殊 wrapper 仍可获取过期地址；view 不借用 image，销毁接收任意 ctx；raw handle/Rc 不证明 native owner 存活。这些是已确认的 API 约束缺口，不代表已在真实 GPU 复现。局部失效状态在 B05-b2 复核，跨层 owner/safe API 设计交 B26/B27，只提出方案。
  后续状态：GfxBuffer 的地址与容量现随显式 release 撤销；SBT region 等上层派生快照仍需 owner 回收，不能由底层 handle 清空推出全部引用已失效。
- SBT 的 u32 乘法/求和、shader handle 查询失败、SoA 布局算术和手工写入、sampler 能力上限、external image 的 usage 描述仍需后续核对；不因阅读到这些文件就标成已闭合。

## 保留理由

special buffer 的 usage/对齐/元素数封装有具体作用，不按“薄包装”删除；VMA copied debug name helper 的短暂 CString 借用与复制契约有必要。显式 destroy 和 typed Ctx 保持既有设计，不引入通用 guard、隐藏 Drop release 或兼容接口。
