## 证据与修复前发现

项目 SDK 为 2.14.1；上游 tag v2.14.1 的 peeled commit 为 `2122257e0fce486f91b385aa63b9a09b0a34b363`。读取该版本 [sl.cpp](https://github.com/NVIDIA-RTX/Streamline/blob/2122257e0fce486f91b385aa63b9a09b0a34b363/source/core/sl.api/sl.cpp)、log.cpp、pluginManager.cpp、exception.h，下载副本仅在 `.temp/code-design/B04-c2/sdk/`。公开源码解释相应版本的状态路径，不冒充已对发布 DLL 注入故障。

1. **P1，SDK 失败后直接卸载不安全，已修复状态缺口、未复现真实 SDK 崩溃。** slInit 先创建带 worker 的日志设施，错误返回没有统一清理；slShutdown 可在 log::destroyInterface 前返回错误。修复前 wrapper 不区分已加载/已初始化，init 或 shutdown 失败仍 reset/FreeLibrary。最小修复是区分初始化成功，失败后禁用 feature 入口、清空 callback 并保留 DLL 引用至进程退出，拒绝再次 init；仅成功 shutdown 释放。不得把失败当作已完成 SDK/GPU 回收。
2. **P2，重复 init 改坏原 callback，已复现并修复。** 修复前 native init 在检查已有 module 前覆盖 g_rust_log_callback，失败再置空；原 runtime 仍在却丢失日志入口。Rust OnceLock 当前阻止第二个 runtime 到达这里，raw C API 仍不应破坏已有状态。模块存在时提前返回 InvalidState，不改 callback。
3. **P1，异步 callback 与清空的普通指针读写缺少同步，已修复源码风险。** SDK 日志来自 worker；失败路径不能证明 worker 已停。改为 atomic 函数指针，调用时只读取一次。Rust callback 地址和 OnceLock state 在进程内持续有效，因此已经取到的回调即使遇到 Rust receiver 退出也只会投递失败，不访问已释放的 Rust owner。该措施不把 init/shutdown/feature API 变为可并发调用。
4. **P2，路径身份未固定且可被 NUL 截断，已复现并修复。** 修复前 public InitInfo 接受相对路径，native 首次 LoadLibraryW 与后来 vulkan_loader_path 交给 ash 时可能处于不同 cwd；UTF-16 helper 不拒绝内嵌 NUL。应在目录创建、安装一次性日志桥之前校验并固定 plugin/log 绝对路径，后续只返回固定的 loader 路径；默认 executable 路径解析失败不能静默转到 `.`。

## 保留与架构预检

Rust 的 OnceLock 保持“单次 runtime 尝试”策略：并发第二次安装失败；线程 spawn 失败后 sender 指向已断开的 receiver，初始化立即失败，不增加重试设施。正常关闭中先 SDK shutdown，再 poison pill/join 日志线程；logger 自身阻塞或 panic 时不承诺必然完整 flush。no_mangle/public 的必要性注释有冗余，但本批不为此更改导出符号。

修改分别归属 native SlApi/日志转发与 Rust InitInfo/runtime。复用已有 owner、std::atomic 和 std::path::absolute；不增加全局锁、句柄注册表、兼容层或新的资源 owner。ABI 字段不变；native API 仍须由宿主串行调用，callback 不得回调 SDK。失败后保留引用是明确的终止状态，代价是进程退出前不回收 SDK 模块/可能残留资源；不支持继续渲染或同进程恢复。实际 GPU 退场仍由 B16 复核。

两个提交分别收敛 native 生命周期与路径身份；直接同步 binding README、runtime header 和 crate 入口的过期说明。临时探针放 `.temp/code-design/B04-c2/`，不新增仓库单元测试。
