## P1：物理 light-side key 重连遗漏 Jacobian

initial 用 solid-angle proposal 产生 reservoir，存储的 weight 是输出 surface 上的
solid-angle inverse PDF；emissive key 保存 barycentric，矩形保存局部 UV，point/spot
保存固定半径 sphere 的表面法线。这些 key 在不同 surface 上连接的是同一光源点，
方向到该点的立体角测度却不同。旧 combine 直接使用 `t_current * W_source * M_source`，
校正也直接累加 source target，最终仍按当前立体角着色；缺少完整的测度变换。

HDRI key 保存固定世界方向，重连映射为恒等。point/spot 当前是半径 .005m 的有限球面，
并不是可以忽略面积 Jacobian 的 delta point light。重新查询当前 proposal PDF 只用于
候选有效性和 MIS，不能自行把存储的旧 inverse PDF 转换到当前立体角。

令 `J_x=abs(n_light·(-ω_x))/distance_x²=dω_x/dA`（单面光源只接受正余弦），则：

```text
raw = Σ t_current(y_s) * W_source(y_s) * M_source * J_current(y_s)/J_source(y_s)
a_source(y) = t_source(y) * J_source(y)/J_current(y)
W_current(y) = raw * a_selected_source(y) / [t_current(y) * Σ M_source*a_source(y)]
```

此式可由共同面积域的 target `t_x*J_x`、inverse PDF `W_x/J_x` 推导，再将最终权重
转换回当前立体角。J 比依赖具体 winner，不能用 source 的旧 winner 为另一 selected
key 校正，也不能只在 raw 或 final 单独补一个距离平方比。

## 参考与架构预检

RTXDI 配置 v3.0.0，父仓库 `274141af082050c9d0ad6e01a2e591d0d66b7955`，
Rtxdi 子库 `a14e079c727ed8c4fd3173bd2aea8244c9d9f6d6`。
FullSample `LightingPasses/RtxdiApplicationBridge/RAB_LightInfo.hlsli` 用 UV 重建
PolymorphicLight sample；`RAB_LightSampling.hlsli::RAB_GetLightSampleTargetPdfForSurface`
把反射贡献除以 conditional solidAnglePdf，initial 的 light selection 与其配套。
球面 UV 随 surface 重新生成可见锥样本，并非本项目保存的同一球面点。因此不能直接
照抄一个 target/PDF 除法；本批保留现有 light-side identity 与采样策略。

修改归 RtLightCandidate / RtRestirDI：候选增加 shader 局部 light_cos，已有 builders
提供未偏移连接的余弦；RtRestirJacobian 持有转换比例的尾数/指数，服务竞争和校正。
复用 RtRestirNormalization 管理分子与分母的缩放，不新增通用数值框架或 free helper。
initial、final shade、storage target/weight 的单位不变；没有共享 ABI、资源 owner、
线程、pass 顺序或生命周期变化。同步 sampling design；不更新 summary。

竞争从 source 重建同一 key 后计算 J_current/J_source；校正从当前 winner 重建各 source
后计算反向比例。新增重建会增加几何/灯光查询成本，未做性能测量；它不增加额外 visibility
ray。zero target 仍按 B19-c2a 保留 M；无 winner 不重建候选。合法零项不因 Jacobian 无意义
而污染校正；正 target 对应非法比例时不能伪造权重。数值失败保留既有拒绝边界。

## 验证

证据在 `.temp/code-design/B19-c3a/`；没有新增永久测试。CPU 转录实际 shader 函数，
矩阵、资源、surface 与 visibility 使用 mock，不能代替 GPU 或完整场景结果。

- `check-jacobian.py` 抽取实际 RtRestirJacobian、normalization、combine、temporal/spatial、
  target 查询和 finalize。五类 key、七组距离尺度、三组 target 尺度、absent/zero/winner、
  两种 history M、16 seeds 和两个 phase 共 60,480 例；独立 double 参考计算完整公式。
  错误权重/有效性 19,248 → 0，winner 不符 1,032 → 0，M 不符 3,840 → 0，最大相对误差
  2.68e-7。3,840 例最终权重不可表示，修复后按既有规则清空；不能称为正常有效输出。
  极端距离是局部算术压力输入，不声称实际光源 builder 支持该全部范围。
- 576 组距离/余弦比对 double，最大相对误差 6.0e-8；9 项非法输入拒绝、HDRI 恒等通过。
  比例本身可超出 float，但尾数/指数在后续约分后仍能得到有限权重。
- `check-solid-angle.py` 使用真实 initial、temporal、RNG、stream/finalize，以均匀面积
  proposal mock 一个半宽 .25 的矩形，两个 surface 距光面 1 与 .5，常数角域贡献为 1。
  每池八次 proposal，65,536 次实验；解析立体角 `4*atan(.25²/sqrt(1+2*.25²))=0.235430023788`。
  initial 均值 0.235441844108；旧复用 0.520365802634，修复后 0.235289898904，相对误差
  0.0005952（验收阈值 .005）。这是对独立解析积分的检验，不只是镜像实现公式；兼容性
  搜索被 mock，不证明真实场景中的具体像素会接受这一 source。
- `check-builders.py` 实际 sphere sample/reconstruct 的 13,312 例与 area 的 540 例中
  380 个可用候选通过既有 PDF/重建检查；矩形 light_cos 对照几何余弦，两次同 surface
  sphere key 重建的 J 比恒为 1。emissive 两处 light_cos 与既有 PDF 的绝对余弦由源码核对，
  未新增其端到端 GPU 验证；spot 沿用 sphere 结果，只调 radiance。
- B19-c2b 的 17,280 个观察方向组合，以及 B19-c2a 的 2,592/10,368 个组合和 152 项边界
  在恒等 Jacobian 下再次通过。上述全部 CPU 检查 O0/O2 一致。
- `just shader`：24 编译、7 复用、两个 binding crate 通过；Realtime/Offline raygen 均通过
  `spirv-val --uniform-buffer-standard-layout`。无 GPU 图像、性能、FTZ/subnormal 验收。

球面 builder 检查最初把“初始采样 → key 再归一化”也要求为严格恒等，触发断言；量化后
其 cosine 最大差 4.48e-5，J 比相对 1 最大差 1.75e-4。实际重连的两端均从 key 重建，
同 surface 重建重复性通过；但初始采样/存储 key 的有限精度误差并未被本修复消除。
既有远处 sphere CDF 误差仍可达 .02613，此处不通过放宽物理域或修改 PDF 掩盖它。
