# B08-a：Asset 加载任务与完成边界

> 历史说明：本文项目 hash、提交次数及“本报告所在提交”均按压缩前历史解释，实验引用保留为“压缩前证据基准”；第三方版本不变。当前分组见[提交压缩映射](commit-squash.md)。


基准：`refactor` 的 `4b0c4cd3`，工作区干净。读取 Asset service/worker、load handle/desc、
三个 loader 的任务入口，追踪 GameWorld→AssetSystem 的请求、完成消费、删除和销毁。
本批不展开 glTF/Assimp 格式、材质转换或 GPU 上传。

## 审阅发现与局部方案

- **P1：scene 任务的 panic 边界不完整。** 两种 scene loader 只捕获 reader 调用，入口
  info 与失败 error 日志在外；worker 直接 spawn，未设置 Rayon panic handler。
  可 panic 的 logger 会使场景任务没有 completion，并进入 Rayon 默认 abort 路径。
  将捕获统一移到 worker 的整个 scene 分派，沿用 texture 的处理方式，转换为对应
  SceneFailure；删除 loader 内重复捕获。C++ 异常仍由既有 C API 边界处理。
- **P1：诊断可跳过任务退出等待。** worker Drop 在 WaitGroup.wait 前写日志；logger
  panic 会跳过 wait。删除 Drop 中非必要日志，保留唯一的任务等待，不增加错误吞噬框架。
- **P2：请求记录发布早于可失败诊断。** service 在插入 SlotMap 后记录请求日志；日志
  panic 时记录已存在但任务尚未排队。先诊断，再登记与派发，避免本地遗留孤立记录。
- **P2：没有生产者的事件队列。** pending_events 仅初始化和 pop，仓库无写入路径。
  移除该字段与 drain；真实 completion 仍由 worker channel 交付。

依赖事实：Cargo.lock 固定 rayon-core 1.13.0、crossbeam-utils 0.8.21；本地依赖源码
registry.rs 的 catch_unwind 未配置 handler 时由 AbortIfPanic 终止，WaitGroup 的 wait
消耗 owner 引用并等待所有 task clone 释放。以上不涵盖 panic=abort、panic hook 再次
panic、恶意 panic payload 的 Drop 或进程终止。

## 架构与保留理由

worker 唯一拥有 pool/channel/等待；service 唯一拥有短期请求 SlotMap；AssetSystem
消费 owned payload 并分配长期身份。改动不新增 helper 框架、owner 或线程，不涉及 GPU。
load handle 与长期 handle 分离是必要边界，不因都是 SlotMap key 就合并。

service 每次请求独立分配 handle，完成时 remove 后只交付一次；不存在取消 API。
AssetSystem 的 texture_loads 将短期 handle 映射到长期 generational handle，完成时
先移除映射，再检查长期 membership；删除后晚到结果不会复活旧纹理。scene import
当前没有删除/取消接口，scene_loads remove 后发布状态；不为假想取消添加兼容逻辑。

worker Drop 等待已排队任务，不保证轮询或发布结果；未消费 completion 随 owner 丢弃。
channel/任务队列无界，也无取消和文件读取超时；阻塞 IO 会延长 shutdown。此为现状，
背压、预算及关闭策略交 B13/B27，不在本批引入调度系统。

## 验证与交接

worker 的完整任务捕获与销毁等待、service 登记顺序与空队列清理均已修复。
`.temp/code-design/B08-a/run.py` 对照 `4b0c4cd3` 与当前源码，编译实际 worker/service、

函数或 catch 边界。service 只附加只读记录数查询，业务路径保持原样。

16 类 worker/事件场景在断言开/关下均通过新旧对照：glTF/混合大小写 GLB/Assimp 分派、
两种 reader 返回错误与 panic、入口与失败日志 panic、texture 成功/失败/panic、正常与
诊断异常的 Drop。旧版四类 scene 诊断 panic 逃逸且没有事件，新版均返回失败；旧版
Drop 日志 panic 跳过被门闩阻塞的任务，新版等待释放后返回。成功场景追加 20 次请求，
核验 handle generation 变化且完成事件不重放。另两类 service 请求日志夹具验证 scene 与
texture 请求：日志 panic 后旧版遗留一个没有 task 的记录，新版记录数为零；合计 18 类。
