## 已确认的局部问题

**P1：RR 的 delta specular albedo 与路径反射权重不一致。** `compute_rr_albedo` 不接收 IOR
或观察方向，对所有材质使用 metallic 与固定 F0=0.1024 的插值。实际 delta transmission
使用 `RtDielectricInterface` 的精确 Fresnel/TIR，reflection 不乘 base color 或 metallic；
delta specular 使用随角度变化的 Schlick。IOR=1.5 的正入射透明面反射率为 0.04，当前 guide
却为 0.1024，金属度还会错误影响透明面的 guide。

最小修复：GBuffer writer 接收原 primary surface 与 ray direction，分别复用现有
`RtDielectricInterface::evaluate` 和 `RtMaterialSampler::sample_perfect_reflection`。
两种 delta 的 diffuse guide 保持零；粗糙材质继续保持已有近似，不能把 delta 的精确权重
套给 GGX 积分。raygen 正常与 debug 首次命中两条入口都必须传递相同 primary ray。

架构预检：guide 仍归 `RtGBufferWriter`，材质模型归现有 material sampler/interface；
只增加 Renderer lib 对同层材质 helper 的依赖，无反向 owner 依赖或新增抽象。
不改变 CPU/shared ABI、图像格式、资源/线程、pass 顺序或路径采样状态。验证使用临时
数值夹具、shader 构建与 SPIR-V 校验；GPU 图像质量单独保留未验证状态。

第一组修复为 `900eeb87`。删除 RtGBufferData 中只为旧 RR 路径保留的 material_type 副本，
RR 直接消费原 surface；GBuffer 图像打包、miss 写入、motion 和 hit distance 均保持原样。

`.temp/code-design/B17-b2/check-material.py` 抽取真实 interface、perfect reflection、GBuffer
guide、SpecularBrdf 和 eval_brdf，做 C++ float 适配（不执行 GPU），O0/O2 禁用 FP contraction：
6 IOR×6 入射角×出入两侧×3 metallic×3 opacity 共 648 组，与独立 double Fresnel 比较；
修复前 guide 全部存在不匹配，修复后最大误差 1.50e-6。18 组镜面测试的角度失配由 15 降到 0；
18 组 rough/fallback 保持旧近似。IOR 匹配、TIR、正入射和掠射均在覆盖范围内，但不覆盖极大 IOR。
`just shader` 成功（24 编译、7 复用、两个 binding crate 通过）；Realtime raygen 通过
`spirv-val --uniform-buffer-standard-layout`，空白检查通过。未做 GPU 图像回归。

白炉探针用实际 eval_brdf、r=1、NoV=1 和 200000 个半球极角中点：白色非金属积分
1.03145186182，白色金属为 0.306852816717。前者证明直接叠加 Lambert 与 specular 会增能；
后者是当前单次 GGX 未补偿多次散射的明显损失。这不是通过修复 RR guide 就能解决的问题。

## 默认 Surface F0：已修复（P1）

`MaterialClass::DEFAULT_IOR=1.5`，glTF validator 只接受非 Transmission 的默认 IOR；自定义值
被明确拒绝。Surface 的 ABI ior=1 是无独立参数时的占位，不能视作真实界面折射率。
先前的 reflectance=0.8→F0=0.1024 与已支持的默认模型不一致。

第二组为本报告所在提交：在现有 `RtMaterialSampler` 内集中 `surface_f0`，按默认 IOR=1.5
得到 dielectric F0=0.04，再与 base color 按 metallic 混合。perfect reflection、rough BRDF
和 rough RR guide 共用该方法；PDF 不依赖颜色，改为给 SpecularBrdf 传零 F0，去掉 glossy
sampling 分支中完全未使用的 F0 计算。没有新增参数类型、兼容开关或额外材质框架。

调用链已复核：Realtime/Offline/SHARC 的 sample_next 进入同一 sampler；NEE 和 ReSTIR
重连经 direct-light helper 使用同一个 eval_brdf。ReSTIR key 保存的 base color/metallic 足够
表达当前固定 IOR 模型，因此不改变 key 图像；以后支持自定义 Surface IOR 时仍必须扩展 key。
rough transmission 仍按既有 Surface fallback 求值，不借此次 F0 修改假装已经支持粗糙 BTDF。
透明 delta 的真实 IOR 与 Fresnel 不受第二组修改影响。
既有非金属及 rough transmission fallback 的高光会随 F0 降低而减弱，这是修复的预期外观变化；
纯金属 F0 仍为 base color。旧累积图像不用于证明新模型外观通过。

证据来源：OpenPBR v1.1.1，`f8d6d947dfae4c9b599965a86c22826ea7a8dbfb` 的
[Specular IOR / Glossy-diffuse / Microfacet model](https://github.com/AcademySoftwareFoundation/OpenPBR/blob/f8d6d947dfae4c9b599965a86c22826ea7a8dbfb/index.html)
给出默认 IOR、正入射反射率和层组合目标；这是修复默认 F0 的依据，不代表已实现完整模型。
RR 参考 Streamline v2.14.1 固定源码
[ProgrammingGuideDLSS_RR.md §4.1.2/4.2.1](https://github.com/NVIDIA-RTX/Streamline/blob/2122257e0fce486f91b385aa63b9a09b0a34b363/docs/ProgrammingGuideDLSS_RR.md)。
本地文档 SHA-256 为 `6298e42ee84a664ff67b62adc2b6de465e7b0421ec9927c809a915760ebe354b`，
与 B16-b 核对的官方文件相同。SDK 给出观察角度/roughness 相关近似；delta 下积分反射权重
等于其 Fresnel 是本次模型推导，直接复用项目求值，并未把该修改宣称为 SDK 图像验收。

第二组 O0/O2 数值复核：648 组透明面和 18 组镜面继续通过；18 组 rough/fallback 验证新的
统一 F0；45 组混合 PDF 与独立 NDF+cosine 参考相符，修复前后均通过。
同一白炉条件下非金属能量变为 **1.01230634189**，金属仍为 **0.306852816717**。
`just shader` 再次成功（24 编译、7 复用、两个 binding crate 通过），Realtime/Offline raygen
均通过 `spirv-val --uniform-buffer-standard-layout`。无共享 ABI/host 代码改动，未重跑完整应用或 GPU。
