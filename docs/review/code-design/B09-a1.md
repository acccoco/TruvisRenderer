## 发现（修复前）

- **P1，已复现并修复：Failed 记录永久命中去重。**
  `AssetSystem::register_texture_source`（基准 388 行）只在 `is_new` 时排队；
  `AssetStore::find_or_insert_texture`（162 行）对任何 live handle 返回 false。
  文件解码失败后，即使修好文件，再次 import 仍返回 Failed；被 material/sky 引用的
  handle 又不能直接删除。应保留同一长期 handle，显式重复请求时允许 Failed → Loading；
  Loading/Ready 继续复用，不引入定时重试或已成功内容的热重载。
- **P2，已复现并修复：请求诊断异常留下无 task 的 Loading 记录。**
  当前先向 AssetStore 插入，再调用 request_texture。B08-a 已使 service 在日志成功后
  登记 task，但上层 record 仍可能先发布。应在请求返回后才发布/重置长期 texture 记录；
  请求异常时保持原 Failed 诊断，或不创建新记录。

## 保留与边界

去重 key 为 canonical source + color space；loader handle 与长期资源 handle 有不同
生命周期，保留这两个身份。AssetSystem/AssetStore 的 owner 分工与只读 SceneReadView
有职责依据，本范围未发现需要统一成通用 registry 的过度抽象。唯一无必要状态是私有
register_texture_source 的 optional desc：所有生产调用均传 Some，可收紧成必需请求。

GpuTextureStore 在尚未上传且 CPU bytes Ready 时提交，没有缓存 CPU Failed 为永久
GPU failure；同 handle 从 Failed 恢复不需要改变 GPU 身份。此为当前源码证据，GPU 实际
画面仍须后续验证。场景导入失败后部分登记、事件消费期间 logger panic 的批次丢失继续
B09-a2，不把本次请求顺序修复扩大宣称为整个 world 的事务。

## 修复与验证

`register_texture_source` 先检查 key 对应的 live 状态，Loading/Ready 返回 no-op；新建或
Failed 重试先调用现有 request_texture，再登记/重置记录并建立 load → texture 映射。
Failed 重试保留原 handle、清空旧 bytes/error 并进入 Loading；私有 bool 现在表达是否
开始任务，GameWorld 据此在实际请求时推进 scene version。移除私有 desc 的 Option，
所有 file/embedded 入口统一必须提供请求参数。没有新 scheduler、公共 API 或 GPU 改动。

临时验证位于 `.temp/code-design/B09-a1/`，不新增仓库单元测试：

- `run.py/probe.rs` 编译基准 `b40b0c74` 和工作区的实际 world 源码快照，追加仅调用公开
  GameWorld API 的可执行入口；使用实际 truvis-asset、Rayon、image 解码和 glTF Reader，
  不替换 loader。对照各 7 个流程：失败后修复 PNG（同时绑定 material 与 sky）、Loading/
  Ready 去重和颜色空间分离、删除后晚到结果、新请求诊断 panic、重试诊断 panic、缺失
  路径、重新导入含 embedded PNG 的真实 glTF。
- 旧版 file/embedded 修复后仍 Failed，新版同 handle 进入 Loading 并最终 Ready；PNG
  实际像素正确。材质引用/材质 revision 和 sky handle 保留；重试排队的 scene version
  增加一次，重复请求不增加。Ready 后改坏源文件再 import，仍保留原 bytes，不热重载。
- 注入的 logger 只在 `Request load texture` 处 panic。旧版新请求留下一个永久 Loading
  记录，新版记录数仍为零且再次请求成功；新版重试入口 panic 时原 Failed/error/version
  不变。临时夹具捕获 unwind，不把进程 abort/OOM 当作可恢复路径。
- 删除 Loading 后重新导入使用新 generation，晚到旧 completion 不复活旧 handle。
  embedded 案例通过实际 scene load 进入 register_scene_texture，复用同一 source identity；
  不将此成功案例扩大为完整 scene ingest 原子性验证。
- `cargo build --offline --locked -p truvis-world` 新旧基准均通过。最终使用各自源码快照
  编译对照，避免 Cargo 同名 rlib 被增量构建覆盖后误把新版当作旧版。未运行 GPU。
- `cargo test --offline --locked -p truvis-world --lib` 现有 4 个测试通过，覆盖原有资源
  反向引用、实例材质数量和删除依赖；空白检查通过。
