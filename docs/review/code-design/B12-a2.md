## 提交与读回（P1，已确认并局部修复）

`25c37ead` 修改 `ray_cast/mod.rs::cast_sync`、`destroy_mut` 与 `pending_command`。录制、
submit-info 和 reset 在未提交边界内，失败释放本次 command 并保留原始异常；进入
queue.submit 前移交 command，只在 fence.wait 正常返回后取走。没有额外布尔状态或
重试框架；空查询和无 TLAS 分支也先拒绝未完成状态，不能掩盖上次失败。

当前 GfxCommandBuffer 是可 clone 的 handle/Rc wrapper，native 分配由 pool 持有；
旧录制失败路径的 command 未立即释放，会积留到 pool 销毁。关闭中的 pending alias
只在调用方已经 device idle 时取走，native command 随 pool 释放。submit 内部主机
分配失败同样按未知提交保守处理，不据此尝试 fence.wait 重试或假定 signal 已发出。

正常链已核对：Runtime prepare 的 graphics submit 和资源 wait/barrier先于 Loop 的
ray_cast_phase；查询同 graphics queue 排序，trace 写 hit → transfer copy → host read
屏障后提交 fence，等待成功后 free command、invalidate readback、转换 CPU identity。
prepare 已提交不等于 CPU 已观察到 GPU 完成，相关服务注释已纠正。输入/映射错误沿
anyhow::Result 返回；Renderer::cast_single_ray 转为文字错误。native submit/wait panic
不在该 Result 内，外层 RenderThread catch 不能证明 Runtime/Vulkan 清理已执行，交 B12-b/c。

`.temp/code-design/B12-a2/run-submit.py` 使用实际完整 service（含输入/上传/转换方法）
和生成 GPU 类型，模拟 RHI、pass、scene view 与 slot 记录。25 类前后各两种 debug/
overflow 配置，共 **100 次通过**：覆盖空/无 TLAS、按序 miss/hit、错误 slot/submesh、
map/flush、command 创建/录制/屏障/copy/end/submit-info/reset、回滚释放诊断、submit
前后异常、wait 失败，以及完成后的 free/invalidate/read 失败。检查原始异常保留、
未知提交不释放/不读回/不复用、成功等待后才读回、已知 idle 关闭 pool 回收命令。

fixture 的 submit 前后注入只是受控状态，不证明真实设备错误的 native 返回语义；slot
记录为 mock，真实映射依据 B11-c。`cargo check --offline --locked -p truvis-app` 通过，
未执行 GPU、device-lost、真实 fence 超时或窗口退出验收。


## 输入与派发前置（P2，已确认并修复）

`validate_rays` 原来只检查方向各分量有限及平方长度是否过小；`f32::MAX` 等有限分量
的平方可能成为 infinity，仍能到达 raygen 的 normalize。受控输入证明旧校验接受、
新校验拒绝；实际 GPU 对这类输入的结果未验证，不声称复现了画面错误。保持原有最小
平方长度阈值和合法非单位方向的 shader 归一化，未替调用者改变 t 范围。

同时核对 `RayCastPass::trace` 固定使用 `[ray_count, 1, 1]`。旧代码仅受 u32 限制，未查
设备的总 invocation 上限和 X 维度上限。依据 2026-10-29 查阅的官方
[vkCmdTraceRaysKHR 约束](https://docs.vulkan.org/refpages/latest/refpages/source/vkCmdTraceRaysKHR.html)
（VUID width-03638、width-03641），取 `maxRayDispatchInvocationCount` 与
`maxComputeWorkGroupCount[0] * maxComputeWorkGroupSize[0]` 的较小值。乘积用 u64，
避免属性乘法溢出；此方法只描述单维 dispatch，不能替代多维乘积约束。

新增的只读 `GfxDeviceInfoCtx::max_ray_dispatch_width` 复用已缓存设备属性，保持私有
physical-device 字段边界，不发起新的 native 查询；RayCastService 在创建时保存值。
这是窄化的 Gfx 查询 API 扩展，原调用签名、线程、所有权及 shader ABI 均不变。
超限请求在无 TLAS 分支和资源扩容之前返回输入错误，避免构造不合法 GPU dispatch。
当前 Renderer 唯一调用者每次只传一条 ray；批量接口的边界缺口不是已复现的主流程故障。

`run-input.py` 使用完整真实 service、真实生成 GPU 类型及提取的实际 Gfx 上限方法，
仅设备属性/RHI 为模拟值。25 类 × 前后两版本 × 两配置，**100 次通过**，覆盖输入
NaN/inf、零/过小/合法非单位方向、方向平方/求和溢出、t 范围、两个设备约束的恰好上限
与越界、大属性乘积。失败请求未访问或分配查询资源；没有用大内存分配模拟极限。
提交夹具又全部通过（100 次），App 编译及空白检查通过。未运行真实 GPU/validation，
不覆盖 SBT/native pipeline/device-lost 的硬件验收，也不验证全部 shader 数值行为。
