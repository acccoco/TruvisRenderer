## 发现与处置

**P2，已修复并验证：局部对账失败丢失候选或通知。** 基准 `prepare_render_data`
在首次完整扫描前就置 initialized，候选及 update result 均在栈上。reconcile/register/
activate 日志、resolver 或快照打包中断时，初始候选可能不再重建，已改变的 Active 状态
下次成为 no-op，`active_set_changed` 等通知不能交付。后果是漏实例或下游 TLAS、scene
buffer、emissive/history 未获得必要的失效提示。实际外层不保证恢复，因此本项不宣称
当前完整应用必然继续运行并显示旧画面；受控重入可稳定复现局部契约缺口。

修复位置：`RenderInstanceTable::prepare_render_data`、`sync_scene_instances`
（当前约 275、369 行）。table 用现有 IndexSet 持有已接管身份，整批成功后清空；失败
保留原顺序，下一次重新读取 CPU 最终状态。已产生的四类变化标记由 table 累积，直到
完整 RenderData/反查快照成功返回才取走。没有第二份 CPU scene 或事件重放队列。

**P2，已修复并验证：单个身份先推进 source/state，后续失败使变化无法重新计算。**
基准 transform/source revision 已更新后才 checked_add、查询 resolver 或记录日志；
此时异常可能吞掉 transform/material/any-hit 变化。现在先完成依赖查询、版本检查、
source clone 和诊断，再提交该身份的镜像及变化标记。正常 ready gate、Pending/Active
切换和 previous=current 的重新激活规则保持不变。计数上界以受控注入验证，不声称
实际运行会自然达到 u64 上限；OOM/abort 不属于可展开异常保障。

**P2，已修复并验证：slot 回收在 drain 中记录日志，异常会丢失其余记录。** 基准
`reclaim_retired_slots` 的 Drain 在 unwind 时丢弃剩余 slot，既包含到期项也包含未到期项。
现在先完成诊断，再用 retain 转移到期项，维持 FIF 延迟边界；register/retire 的诊断
同样先于 slot 所有权变化。稳定 slot、generation 检查与延迟时长没有改变。

## 设计判断

保留 MaterialSlotResolver/MeshRenderResolver：它们把只读 GPU readiness 和资源 owner
隔离，instance table 不应直接持有 texture/mesh/material manager。RenderData 借用 mesh
几何并紧凑打包，稳定 instance slot 则服务 TLAS、GPU buffer 与拾取反查；两种索引职责
不同，不因重复存储若干字段而合并。source revision、transform version、FIF 上传版本
和上一主视图提交历史也有不同确认时点，本轮没有证据支持删掉这些边界。

新增状态只归现有 RenderInstanceTable；不新增 free helper、通用事务框架、公共 API、
线程或 GPU 同步机制。通知保留的终点是该 table 成功返回，**不覆盖调用者之后的失败**。
相关设计理念及不变量保持，模块 README 说明局部失败边界。

## 验证

`.temp/code-design/B11-a1/{run.py,mocks.rs,probe.rs}` 编译实际完整 instance table、
RenderData、resolver trait、FrameLabel 和 Instance 数据定义；使用真实 slotmap/indexmap、
glam 和生成的 GPU Instance 类型。SceneReadView、材质/mesh 数据由受控替身提供，
logger/resolver 注入可展开 panic；没有创建 Vulkan 对象或调用 GPU。

基准/修复后 × debug assertions 开/关，共 **14 类、56 次运行通过各自预期**：

- 首次 reconcile、register、activate、第二个实例 activate、打包 resolve 异常：旧版
  丢候选或变化标记；修复后不重新传入候选也能完整交付，随后 no-op 不重复通知。
- transform 日志、material resolver、版本上界：修复后保留旧 source/revision，重入
  正确交付 transform、material binding 和 any-hit 变化；旧版标记丢失。
- retire/deactivate 日志与混合到期 slot 的第二条回收日志异常：修复后通知不丢失，
  三个 slot 最终各回收一次，未到期项保持；旧版回收集合有两项丢失。
- 正常两实例共享 mesh、material/transform 修改、依赖未就绪与重新激活保持。
  同 CPU slot 的不同 generation 删除/创建不会使用旧 GPU slot；跨过 FIF 后再复用，
  stale handle 的 selection 无效，反查记录归新身份。
- 正常 FIF 写入、无主视图提交保留历史、主视图提交推进历史、各副本最终追平后退出
  dirty 集合，两版一致。此项只验证正常历史语义，不覆盖失败 command 的重新录制。

`cargo check --offline --locked -p truvis-render-runtime`、`-p truvis-app` 和
`git diff --check` 通过，无新增项目编译警告。首次扩展探针误用生成类型的 Default，
改为仅在临时夹具中初始化全零数值记录后通过；未修改 shader ABI 或生成绑定。
未运行完整构建或 GPU/图像回归；本批修改是 CPU 对账与通知保留，不据此宣称整帧恢复。
