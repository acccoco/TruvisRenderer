## 已确认的问题与修改边界

- **P1：公共 CPU 入口可绕过参数域。** glTF、Assimp 和 Editor 各自检查 metallic/roughness，
  但 `GameWorld::register_material/update_material` 最终调用的 `MaterialData::validate` 只检查
  二者有限性，也未约束 base RGB 非负及 alpha 范围。GPU material store 原样投影这些数值。
  roughness 同时作为 diffuse 概率；roughness=2 会得到负的 specular 混合权重，metallic 越界
  也会产生负 diffuse 或错误的 F0 插值。此处应拒绝非法输入，不能依赖 UI 滑块或导入格式。
- **P1：贴图组合重新越界。** `texture_loader` 保留最高 65504 的有限 HDR RGB，MR 槽没有
  格式限制；`MaterialAccess::evaluate` 直接把通道与合法 factor 相乘。比如 factor=0.5、
  HDR G=4 得到 roughness=2。不能在通用 HDR loader 截断 RGB，否则会破坏发光/天空数据。

归属：已有 `MaterialData::validate` 与 `MaterialAccess::evaluate`；CPU 材质仍归 AssetStore，
GPU store 只是投影。公共签名、共享 ABI、线程、资源、RenderGraph 顺序均保持不变。
CPU 注册/编辑失败须发生在记录、依赖和 revision 改动之前；shader 在解释 MR 通道时限制
最终组合值，不修改通用纹理 bytes，也不复制一套 Renderer 专属校验。

## 修复与证据

修复和报告合为本报告所在提交。`MaterialData::validate` 现在拒绝越界 metallic/roughness、
base alpha 和负 RGB；`contains` 同时拒绝 NaN/Infinity。RGB 不新增上界，保留 Editor 既有
HDR 输入语义，也没有改 alpha cutoff 可大于 1 的契约。MR 组合使用 saturate，限制的是
factor*channel 的乘积；例如 0.5*4→1，而不是先把纹理 4 截到 1 再乘因子得到 0.5。
ABI 只更新过期字段注释，字段、offset、stride 均未改变。

调用链复核：GameWorld 注册经 AssetSystem/AssetStore 的依赖校验，更新先查 scene UV 引用、
再进入相同参数校验；失败在 insert、依赖变更和 revision 提交之前。scene ingest 的
`prepare_scene_material` 同样调用该 validate。Editor 的预校验保留用于字段级报错；它不是
唯一安全边界。glTF 和 Assimp 的既有合法范围未扩大，样例中的显式标量也落在该范围内。

临时验证位于 `.temp/code-design/B17-b1/`，未新增仓库单元测试：

- `world.rs/world.py` 链接修复前后实际构建的 truvis-world 库，执行 30 组非法材质的
  validate/register/update。其中 12 组有限越界值在基准被接受，修复后拒绝；18 组非有限值
  始终拒绝。拒绝时验证材质内容、material revision、scene version 和登记数量不变。
  27 组合法边界/中间值及 HDR base RGB=4 的注册、更新和 no-op 版本行为通过。
  探针自身 debug assertions 开/关均执行；依赖库为 dev 构建，不据此称为 Release 全库验证。
- `mr.py` 抽取真实 `MaterialAccess::evaluate`，仅适配 C++ 语法并 mock 纹理/UV/法线输入。
  4×4 组因子、6×6 组纹理通道（含 2 与 65504）共 576 组；修复前 176 组越界，修复后为零。
  [0,1] 贴图的结果保持原乘积，HDR base color/emission 均保持原值。它未执行真实纹理过滤或 GPU。
- `cargo build --offline --locked -p truvis-world` 与 `cargo check --offline --locked -p truvis-app` 通过。
- `just shader` 通过：29 个编译、2 个复用，两个 binding crate 成功。
  Realtime/Offline closest-hit 与 Phong pixel shader 通过
  `spirv-val --uniform-buffer-standard-layout`。无布局变更，不新增 ABI 迁移。
- 空白检查通过。修改的 Rust 条件块符合 rustfmt；文件整体仍有两处既有格式差异
  （光学参数条件、UV 错误构造），已与基准对照，未整理无关代码。

## 保留与下一步

本批只证明公共 CPU 参数域和有限采样值的组合域。标准 HDR loader 会清理非有限 texel；
`TextureBytes::new` 本身只验形状，不能将本次 saturate 视为任意手工 NaN payload 的通用修复。
未进行 GPU 场景运行、HDR MR 图像回归或能量白炉验收；正常合法 LDR 输入按公式保持不变，
此前越界的 HDR MR 外观会改变，正是本次修复的行为。

下一批 **B17-b2**：复核 Surface 固定 F0=0.1024 与目标 IOR=1.5/F0=0.04、Lambert 叠加
specular 的能量偏差，以及 CPU/导入→主路径→ReSTIR key→RR guide 的统一修改边界。
尤其 `RtDielectricInterface` 已按 Transmission IOR 计算 Fresnel，但 RR guide 仍用 Surface
固定 F0；应先区分可局部纠正的 guide 与需要统一设计的模型演进。HDR base RGB、rough BTDF
和后续法线审阅仍须保留自己的语义边界。B17 父项保持进行中。
