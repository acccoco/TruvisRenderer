## P1：配置切换未拒绝完整历史池

CPU history 只记录 ReSTIR mode、连续帧和场景版本，未记录 sky sampling mode 与两类 NEE
开关。这些 common settings 的 UI 修改不保证触发 Runtime history invalidation。旧 shader
在重建候选时拒绝 class mask 不匹配的 key，却已允许其 reservoir 进入 source 集合：零 target
无法阻止旧 M 参与计数与校正。零估计池没有 winner key，单独加强 key 检查仍不足。

修复归 RealtimeRenderSubsystem 的既有提交确认链：增加私有 RestirDiHistorySettings，捕获
mode、sky strategy、emissive/analytic 开关；RealtimeFrameCommit 保存录制时快照，submit
返回后才提交该签名。无 TLAS 帧仍切断连续帧，SDR 参数不进入采样签名。shader 在
reservoir_pool_reusable 接受有效 winner 前复用 sample_key_matches_current_class_mask，
不让被拒绝池贡献 M。零估计池继续依赖 CPU 配置签名与三类资源版本，不能伪造 winner。

架构预检：owner、依赖方向、线程、共享 ABI、资源数量和 pass 顺序不变；复用原有 commit
与 shader predicate，不引入通用配置框架。同步 temporal-state 与 sampling design。

验证证据位于 `.temp/code-design/B19-c3b/`，没有新增永久测试：

- `check-settings.py` 抽取真实 Rust signature、history predicate、commit 构造与确认函数，
  用最小 owner/enum mock 遍历 32×32 配置及版本、reset、连续帧组合，共 12,288 例；
  错误接受 168 → 0。另检查首次帧、未提交候选、捕获后修改配置、SDR-only、无 TLAS 与
  u64 连续帧溢出边界；只证明局部确认逻辑，不代替 queue submit 集成验收。
- `check-class-mask.py` 抽取 shader class-mask predicate、pool predicate 与 combine；
  四种 mask、absent/zero/winner、三类版本变化、年龄共 576 例，错误接受/错误 M 均 24 → 0，
  O0/O2 一致。zero pool 不带 class mask 是有意保留，跨配置拒绝由前项 CPU 检查覆盖。
- `cargo check -p renderer-rendering -p truvis-renderer` 通过；`just shader` 24 编译、7 复用，
  两个 binding crate 通过；Realtime/Offline raygen 均通过 standard-uniform-layout SPIR-V 校验。

## P2：final shade 重复计算同一 BRDF/MIS

shade_final_reservoir 先调用 candidate_target 判零，再调用 shade_reservoir_candidate；两者
重复执行 eval_candidate_target_contribution。后者只有这个生产调用方。现将未加权 RGB
的零 target 判断移入 shade helper，保留权重/贡献有限性检查；不以加权 RGB 判零，以免
改变极小正贡献乘权重后下溢为零的既有 valid 语义。职责仍归 RtDirectLighting / RtRestirDI，
不改变 visibility、共享 ABI、资源、依赖和阶段顺序，sampling design 同步说明。

`check-final.py` 抽取修改前后真实 shade_final_reservoir、target、eval、shade helper 与 MIS，
mock BRDF、资源读取和 visibility，覆盖两类 MIS 路径、PDF/BRDF/weight 的零值、负值、
极值、NaN/Inf 与 surface/key/winner/visibility 状态，共 18,816 例。输出 valid、light_kind、
RGB 和 visibility 调用次数全部一致，O0/O2 均通过。正常正贡献样本 BRDF 调用 2 → 1；
单独验证正贡献乘极小权重下溢后仍 valid。不是完整材质模型或 GPU 性能测试。
第二次 `just shader` 仍为 24 编译、7 复用，两个 binding crate 和两个 raygen SPIR-V 校验通过。
编译仍有既有的条件 out-candidate 初始化告警：target_at_surface 先赋值，只有返回正 target
才进入 Jacobian 读取分支；本批没有改动这条分支，不宣称编译零告警。

## 已核对的接入与限制

- analytic table 按 scene light_revision 对账并发布数量与版本；emissive dirty rebuild 推进
  version，sky distribution 发布自身 version。reservoir 对三类版本逐一检查，包含 zero pool。
  这里核对版本消费与直接生产者；跨 FIF 上传、失败确认和版本耗尽策略继续由 B19-d 复核。
- PATH depth=0 的合格非 delta、非纯 EMISSIVE surface 创建 initial 并跳过普通 NEE；其余
  primary 清空 initial 并走适用路径，secondary 使用普通 NEE。SHARC query 排除 depth=0。
  RealtimeRtPass 当前 spp=1，按 mode 执行 PATH、可选 TEMPORAL/SPATIAL、一次 FINAL。
- final 从对应 mode 的 reservoir 重建当前 surface 候选，再查当前 TLAS visibility；统一
  RayQuery 对 non-opaque triangle 使用 MaterialOpacity alpha test。正常输出只加一次
  final contribution；非 ReSTIR debug 不被覆盖。未发现此链重复加 NEE 或复用历史 visibility。
- 历史 surface 的校正仍使用当前 TLAS；CPU appearance reset 是保守约束，不能据此声称
  任意动态场景的历史可见性与原帧一致。当前批没有 GPU 图像、性能或 FTZ 验证。
