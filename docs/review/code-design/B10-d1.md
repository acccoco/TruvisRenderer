# B10-d1：Sky worker 请求与关闭边界

> 历史说明：本文项目 hash、提交次数及“本报告所在提交”均按压缩前历史解释，实验引用保留为“压缩前证据基准”；第三方版本不变。当前分组见[提交压缩映射](commit-squash.md)。


基准 `cfeed488`，分支 `refactor`；局部修复与文档合为本报告所在提交。
本批检查 SkyDistributionBuilder 的线程/通道调度及 GpuSkyStore 请求接受入口，
沿调用方确认 CPU 结果如何进入共享上传队列；未完成 GPU 发布与组合 owner 审阅。

## 发现与局部修复

- **P2，已修复：worker 失败被视为正常等待。** 请求发送失败原来只记录日志并返回，
  GpuSkyStore 已提前提交 latest_request，后续相同 handle 被去重；结果通道断开也只返回
  空集合。现在发送/结果断连显式失败，请求被通道或 latest-pending 接受后才推进身份并
  退役旧分布；request id 耗尽也在退役前检查。保持现有 fail-fast 模式，不增加自动重启。
- **P2，已修复：局部结果集合在中断时丢失。** 原 poll 将结果收集到局部 Vec，再派发
  pending；派发诊断或 consumer 中途异常会丢弃尚未消费的结果。改为 builder 持有
  VecDeque，先保留完成结果再派发，GpuSkyStore 逐项取走。当前已取走结果的 GPU
  准备/提交失败仍需 B10-d2 处理，本批不宣称整个 sky 同步可恢复。
- **P2，已修复：关闭状态晚于失败诊断。** join 后先清除 pending、完成缓存及通道中的
  CPU payload，标记关闭后再报告 worker panic。重复 shutdown 无操作；关闭后的 request/
  poll 在两种断言配置下均拒绝使用。已运行 build 仍自然完成，不添加取消机制。

调度职责继续由现有 builder 承担，最多一个 in-flight build、一个最新 pending；不引入
通用任务框架。已完成结果和正在计算的工作集分开持有，不能把单 worker 等同于总内存
只有一份分布。公共 API、shader ABI、Alias 算法、GPU barrier 和队列顺序均未改变。

## 验证与证据边界

临时夹具 `.temp/code-design/B10-d1/{run.py,mocks.rs,main.rs}` 从基准和工作区提取实际
builder 调度实现、实际 observe_texture_loaded，保留真实 std 线程、通道和 JoinHandle；
仅用受控 build 替换 Alias 数值计算，texture/GPU entry/registry 为替身。
15 类场景在 debug assertions/overflow checks 开启和关闭时对照运行，共 **60 次进程
运行**符合预期。旧版结果用于复现缺口，不表示旧版满足新契约。

- 实际 worker 被门闩阻塞时依次请求 1/2/3，只构建 1/3；关闭等待已派发 build，丢弃未
  派发请求。Arc 计数确认 shutdown 后不再持有未消费 payload。
- 请求/结果通道断开、pending 派发失败、真实 worker panic 显式可观察；派发失败前接收
  的结果仍由 builder 持有。受控 consumer 取走首项后异常，其余两项保留到消费或关闭。
- join 的诊断异常不撤销 builder 已关闭状态；重复关闭、关闭后调用和通道积压回收覆盖。
- 正常请求去重、无关 texture 忽略、发送失败、request id 耗尽覆盖；后两者不提前退役旧
  分布或推进 latest_request。日志异常是注入的局部契约检查，不代表正常日志经常失败。

`cargo check --offline --locked -p truvis-render-runtime`、
`cargo check --offline --locked -p truvis-app` 与 `git diff --check` 通过，无新增编译警告。
未运行 GPU、图像回归或完整构建；夹具不证明 Alias/PDF 数值正确、GPU 内存可见性或
Runtime 在 panic 后可继续运行。未新增仓库单元测试。
