## 局部修复

**P2：RangeField 同一次交互重复提交。** pointerup、keyup 和 blur 分别调用 onCommit，
释放后失焦会发送两次相同 patch。World 虽然对相同 mutation 不推进版本，但 Web 仍排队请求，
增加 pending 和错误回包机会。

复用控件内的 useRef 记录本轮已提交值。释放和失焦共享去重；新 focus、pointerdown、非 Tab
keydown 或新 draft 重置记录，保留相同值重试、键盘编辑和未收到 pointerup 时的 blur 提交。
状态只属于 RangeField，不改变 session、协议、World/GPU 契约，不引入通用表单框架。

## 证据

`.temp/code-design/B23-a/probe.mjs` 用项目已有 rolldown 编译实际 RangeField 源码，替换的仅为
useRef 和 JSX runtime，以可控事件驱动真实 handler。基准 `pointerup → blur` 的提交数为 2；
修复版五组序列通过：pointerup/blur 去重、键盘释放/Tab 失焦去重、blur 兜底、同值鼠标重试、
同值键盘重试；draft 回调值保持一致。输出 `actual_range_event_sequences=5`。

`npm run build`、`npm run typecheck`（app/editor/web）和 `git diff --check` 通过。
没有新增永久测试、依赖或生成协议文件。临时探针不是 React DOM、设备输入或真实 Tauri 验收；
未修改布局与 CSS，未运行 GPU。这个局部事件检查不能证明整个 Web 状态机正确。
