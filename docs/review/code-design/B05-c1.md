# B05-c1：command/queue/sync/query 首轮

> 历史说明：本文项目 hash、提交次数及“本报告所在提交”均按压缩前历史解释，实验引用保留为“压缩前证据基准”；第三方版本不变。当前分组见[提交压缩映射](commit-squash.md)。


基准：`refactor` 的 `a8aed402`，工作区干净。读取 command pool/buffer/queue、submit info、fence、
semaphore、query pool、one-time helper，以及 CmdAllocator、RayCastService、BLAS compact 和 upload
的直接调用。第一轮按同步对象 owner/query ABI 闭合；command 状态与 one-time 的失败退场留作 c1b
续接，不将已提交 GPU work 当作未交付叶子资源回收。

## 本轮确认与局部修复

- **P1，Fence 表面 owner 可重复。** `commands/fence.rs` derive Clone，任何 clone 都能 destroy 同一
  handle；`GfxCommandQueue::submit` 消耗 Option<GfxFence>，RayCastService 依靠 clone 保留等待者。
  改为唯一 owner，submit 接受借用；等待和显式释放仍归 RayCastService，不改提交/等待顺序。
- **P1，同步/query 构造失败。** Fence naming 失败泄漏，Semaphore/QueryPool naming 失败触发遗漏
  release 的 Drop assertion；Semaphore destroy 的 logger 在 native release 之前可能 panic。
  复用叶子构造的局部 catch/release/resume；binary/timeline 的创建收敛到同一实现，保留 native type。
  wait_timeline 必须拒绝 binary semaphore，不能把同一 handle 类型当成可互换的同步语义。
- **P1，query 宿主 ABI 不受约束。** `query_pool.rs::get_query_result<T:Default+Clone>` 可以让 native
  写入 bool/String 等任意类型；当前 `WAIT` 缺少 `TYPE_64`，唯一生产调用却读取 Vec<DeviceSize>。
  [Vulkan query 结果规则](https://docs.vulkan.org/refpages/latest/refpages/source/vkGetQueryPoolResults.html)
  明确由 flags 决定 32/64-bit 结果，不由 Rust T/stride 决定；大于 32-bit 的 BLAS compact size
  可能被截断或饱和。限定标量 u64 结果、TYPE_64|WAIT 和支持的单值 query 类型；read/reset/write
  均检查 pool 容量与加法溢出。AS property 写入还须匹配可用的 AS query 类型。

## 本轮留下的 c1b 续接项

以下为本轮发现时的状态；后续局部修复与仍未闭合的边界见 [B05-c1b](B05-c1b.md)。

- `GfxCommandPool::destroy(&mut self)` 不检查 valid，重复调用会重复销毁；handle/reset/free 在
  destroy 后仍可使用。`free_command_buffers` 不核对分配池，也不撤销外部 clone。
- GfxCommandBuffer new 在命名失败时漏 free；begin 在 Vulkan begin 后转换 debug label CString，
  NUL 会使状态停留在录制中。wrapper 不跟踪 recording/executable/pending，且没有禁止 submit 的
  raw handle/资源先行失效。不能通过单个 bool 或 Rc 自动证明 native lifetime。
- CmdAllocator 保存 clone 后将另一个 wrapper 交给调用方；FIF owner 确实承担批量 free/reset，
  不能直接移除 Clone 而忽略此调用契约。根/单次 helper 内不必要 clone 与持久 owner alias 要区分。
- one_time_exec 在 begin/closure/end/submit/wait 的任一失败都可能遗漏 command 回收；闭包返回 R
  可能是 staging GPU owner。等待失败不能证明 work 完成，传播 panic 又可能触发 R/外层 owner 的
  Drop assertion。需把 command 与关联资源的交付/完成条件一起审阅，不能无条件 catch 后释放。
- submit info 持久保存数组和重复裸指针，submit 时又投影一次；typed context、fence 和 command
  同 device、外部同步、timeline 值单调性仍由 owner 保证。wait_timeline timeout 当前转 panic，
  host query WAIT 也不能替代 reset/reuse 的完成条件。

CmdAllocator 的长期 owner 与 FIF 安全点有具体用途，不按 clone/薄 wrapper 直接判为过度设计。
跨层 owner/safe API 重设仍只交 B26/B27 方案；本轮不实施最终全局修改。

## 验证与交接

第一提交为 `749da47c`：同步/query 对象的 owner、native type 与构造失败回收已修复。
Fence 不再 Clone，submit 使用 Option<&GfxFence>，RayCastService 只改借用表达式；reset→record→
submit→wait→free→invalidate 顺序保持。Semaphore 共用一个 private constructor，保存真实创建 type；
回滚不进入 logger。正常 Drop 仍只诊断，不调用 native release。

`.temp/code-design/B05-c1/make_probe.py/run_sync.py` 引入实际 Fence/Semaphore/QueryPool/Queue 源码，
用 mock device 记录事件，不触碰真实 GPU。

- debug assertions 开/关各 25 场景通过，覆盖成功、create/name/NUL/logger 失败、timeline 初始值、
  binary host wait 拒绝、submit 成功/失败时 Fence 仍由原 owner 持有并仅释放一次。
- 旧版 naming 失败分别只留下 fence+/semaphore+/query+；开启断言时 semaphore/query 的子进程
  以 3221226505 退出。修复后错误仍传播且每个已创建对象恰好释放一次；logger 不阻止 native 回收。
- clone 编译探针旧版接受、新版 E0599；binary wait 旧版进入 native wait，新版在调用前拒绝。
- Gfx/Renderer 编译检查通过。这里只证明 wrapper 的调用与所有权表达，不证明 GPU 等待/失效设备
  的资源退场安全；mock submit failure 也不作为实际 Vulkan failure 的完成证据。

第二提交为本报告所在提交：query 读取固定返回 Vec<u64>，使用 TYPE_64|WAIT；构造只接受非零容量
和六种单值 query，read/reset/AS property write 共用容量检查。合法空范围不进入 native；AS 写入
只接受四种 property 类型，遵循 [AS property query 规则](https://docs.vulkan.org/refpages/latest/refpages/source/vkCmdWriteAccelerationStructuresPropertiesKHR.html)。
当前 BLAS compact 的 DeviceSize 调用保持兼容；设备 feature 与 query reset/reuse 前置仍由 owner 保证。

`.temp/code-design/B05-c1/make_query.py/run_query.py` 使用实际 QueryPool 源码和提取的实际 AS write
方法体，通过 mock native 验证调用参数；debug assertions 开/关各自通过前后对照：

- 注入大于 32-bit 的两个标量，旧版 WAIT 得到 6/7，新版得到完整 4294967302/4294967303。
  mock 选择低位截断来复现宽度错误，不代表所有 Vulkan 实现的溢出策略。
- read/reset 的越界、加法溢出、越界空范围，以及 AS write 越界/类型不匹配均在 native 前拒绝；
  合法空范围不调用 native。每轮 native read/reset/write 从各 6 次降为各 1 次有效调用。
- 非零容量和支持类型在创建前验证，六种允许类型均成功创建/释放；native create/destroy 数量一致。
- Vec<String> 编译探针旧版接受、新版拒绝（E0308），不执行无效类型的 native 写入。
- Gfx/Renderer 编译检查与 Gfx 构建通过；未运行真实 GPU，不将 mock 结果视为 GPU 时序验收。

本轮两次提交已闭合同步对象与 query 宿主边界；下一子批 c1b 继续 command/one-time 状态链。
