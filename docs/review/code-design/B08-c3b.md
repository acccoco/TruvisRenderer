# B08-c3b：纹理槽与能力边界

> 历史说明：本文项目 hash、提交次数及“本报告所在提交”均按压缩前历史解释，实验引用保留为“压缩前证据基准”；第三方版本不变。当前分组见[提交压缩映射](commit-squash.md)。


基准：`refactor` 的 `e5435ab1`。从 Reader/TextureSlot 追踪到 AssetSystem 的颜色空间
和身份替换，再到 GpuMaterialStore、sampler 表、MaterialAccess、Phong 和 RT 路径。
本批核对转录完整性与当前能力，不把输入检查升级为完整渲染合规证明。

## 局部发现与修复

**P1：输入含无法表达的材质信息却返回成功。** 本批统一收紧四个确定的能力边界：

- alpha BLEND 原先只有警告并返回 Opaque，现在失败；当前 CoverageMode 没有混合模式，
  Phong pipeline 也明确关闭 blend，不能在导入器猜测透明外观。
- transmissionFactor > 0 且有 transmissionTexture 时失败，避免仅使用 factor 丢失逐像素
  透射；factor=0 时该贴图没有贡献，继续允许。required/optional 声明采用相同字段检查。
- Surface 不保存 IOR，自定义非默认值会丢失，现在拒绝；缺省或显式 1.5 继续使用现有表面
  模型，标量透射材质保留其 IOR。这不证明现有表面 BRDF 已满足 glTF，见后续模型缺口。
- COLOR_0 在 SubmeshData/顶点 ABI 没有载荷，原先被直接忽略，现在拒绝声明此属性的
  primitive，包括白色属性；不为它新增顶点格式或在导入层猜测烘焙到纹理的替代方案。

检查位于 GltfSceneReader 私有方法，复用现有声明/API，只有 coverage 转换改为 Result。
不新增公共类型、资源 owner、线程、sampler 表或 Shader ABI，不添加通用能力注册框架。
行为变严格：以前外观被近似或字段被丢弃的输入现在可能导入失败；不是这些 glTF 文件违法。
material/mesh 仍全部转录，因此未引用的上述输入也可能触发失败，未顺带修改可达资源策略。

## 已验证的现有转录

| 路径 | 当前事实与证据 |
|---|---|
| 四槽 | BaseColor/MR/Normal/Emissive 保留同一图片的独立 texCoord、transform、sampler；with_texture 只替换身份。 |
| UV transform | 普通槽使用 typed extension，Normal 使用通用 JSON 扩展；默认值、非法字段拒绝与 texCoord override 一致；两行系数表达 T·R·S。 |
| 颜色空间 | BaseColor/Emissive 为 Srgb，MR/Normal 为 Linear；AssetSystem 用 channel.color_space 注册，图片身份与槽参数职责分离。 |
| sampler | wrapS/wrapT 三种取值与两种 filter 构成 18 个编码，和 RenderSamplerManager 表一致；缺省 magFilter 为 Linear。 |
| 图片共享 | 同 image index 的 encoded bytes 共享 Arc；不同槽/颜色空间的后续纹理资产身份不能仅凭 Arc 相同合并。 |
| UV 缺失 | transform override 指向不存在集合时，primitive 导入仍失败；不能静默使用 UV0。 |

规范依据：[KHR_texture_transform](https://raw.githubusercontent.com/KhronosGroup/glTF/main/extensions/2.0/Khronos/KHR_texture_transform/README.md)、
[transmission](https://raw.githubusercontent.com/KhronosGroup/glTF/main/extensions/2.0/Khronos/KHR_materials_transmission/schema/material.KHR_materials_transmission.schema.json)、
[IOR](https://raw.githubusercontent.com/KhronosGroup/glTF/main/extensions/2.0/Khronos/KHR_materials_ior/README.md)
和 [glTF 材质](https://registry.khronos.org/glTF/specs/2.0/glTF-2.0.html#materials)
（2026-10-29 核对）。表中的代码事实不是各规范全部要求已实现的证明。

## 跨层待办，交接而不在本批改写

- **P1，B15/B11：minFilter/mipmap 未保留。** TextureSampler 只有单 filter，导入只看
  magFilter，GPU min/mag 也相同；GfxSampler max_lod=0，MaterialAccess 显式 sample_level 0。
  即使仅声明 minFilter=NEAREST，也会落到默认 Linear；仅修改 importer 取值不能同时正确
  表达 min/mag、mip 资源和 shader LOD。需连同数据形状、sampler 表与采样策略审阅。
- **P1，B15/B17：doubleSided 没有状态。** Phong 沿默认 BACK cull，TLAS 却始终设置
  TRIANGLE_FACING_CULL_DISABLE；Reader 忽略 doubleSided，不能声称两条路径已一致。
  需同时考虑剔除和背面法线，不在导入层强制一个固定 bool 代替完整设计。
- **P2，B15/B17：occlusion 未消费。** 四槽没有 AO，输入 strength/texture 被忽略。现有
  设计禁止把 AO 随意混入 path throughput；后续应区分 raster 间接项与路径追踪，而不是
  为了“读取字段”直接乘整个颜色。
- **P1，B17：固定表面反射与 rough transmission 仍是模型缺口。** 当前 realtime
  raygen_material 的多个分支使用 reflectance=0.8 和 `0.16 * reflectance²`，Surface 的
  默认 IOR 通过入口不等于 glTF 默认介电 F0 已匹配；rough BTDF 仍按既有设计回退反射。
  不能只改导入端 scalar，也不能把材质公式补丁混入本批；后续按 OpenPBR/现有采样契约核对。
- **B17 验证项：normal transform 与切线基。** 当前 authored 分支直接用导入 tangent，
  缺切线分支按变换后的 UV 差分重建，且没有 CPU MikkTSpace。是否与目标烘焙约定一致仍需
  参考资产/实现及 GPU 对照；这里只确认分支差异，不以猜测改变 tangent 或宣称已经验收。
