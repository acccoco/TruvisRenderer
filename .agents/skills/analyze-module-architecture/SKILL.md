# 模块架构分析

## 分析流程

1. 采用用户请求能够支持的最小模块边界；边界有歧义时说明假设或列出候选边界。
2. 先读 `AGENTS.md`、`docs/ARCHITECTURE.md`、相关 `docs/summaries/` 和模块 README，再检查 manifest、公开入口、调用方、测试与示例。
3. 从外到内追踪职责与非职责、公开接口、反向调用方、外部依赖、内部 owner，以及一条有代表性的运行或数据流。
4. 检查状态和资源由谁创建、持有、转移与销毁，识别隐式顺序、错误路径、线程与同步边界及性能热点。
5. 渲染相关模块额外检查 GPU resource、RenderGraph pass、FFI、shader ABI、坐标系和 CPU/GPU 同步契约。
6. 用当前源码、测试和文档支撑结论；无法确认的内容明确标为“推断”或“未确认”，性能结论说明是测量结果还是代码推断。

除非用户明确要求实现或更新文档，否则只分析，不修改文件。

## 输出要求

- 结论先行，只展开与用户问题有关的维度，不强制套用固定章节。
- 主要结论引用具体文件和 symbol；说明依赖方向、owner、生命周期和关键不变量。
- 以风险、未知项和需要继续核查的位置收尾。
- 只有图表能显著降低理解成本时才使用 Mermaid，并选择能说明问题的最少图表；图中关系也必须有源码依据或标明为推断。
