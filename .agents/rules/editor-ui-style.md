# Web Editor UI 风格规则

## 1) 适用范围

- 本规则适用于 `app/editor/web` 以及后续属于 Truvis Web Editor 的页面、组件、样式和 UI 资源。
- 本规则只约束 Web Editor 的视觉语言、信息组织和交互状态，不改变 Engine、Renderer、Shader、Editor protocol、Tauri transport 或渲染资源契约。
- 现有实现事实以代码为准；本文件定义后续 UI 改动必须保持的设计方向和不变量。

## 2) 风格定位

Truvis Web Editor 使用 **Truvis Light Technical Editor** 风格：浅色、紧凑、结构优先，面向 3D 创作和工程调试工具。

- 借鉴 Unreal Engine 的专业工具密度、工作区分割和状态反馈。
- 借鉴 Unity Inspector 的对象层级、属性分组、Foldout 和参数编辑方式。
- 只借鉴编辑器交互和信息组织原则，不复制具体产品的品牌颜色、图标、文案或实现。
- 界面优先支持长时间编辑、快速扫描和精确调参，不追求消费级 Web 产品的装饰性。

## 3) 主题与色彩

- Web Editor 固定使用浅色主题，不根据系统偏好自动切换深色主题，也不为单个组件引入独立暗色方案。
- 页面背景使用低饱和冷灰色；普通面板比页面背景亮一层；输入控件使用接近白色的独立表面。
- 主文字使用深灰色，辅助文字使用中灰色，禁用文字降低对比度但仍保持可读。
- 主强调色使用统一的蓝色或青蓝色，只表达选中、焦点、链接、可执行操作和重要进度。
- 成功、警告和错误使用稳定的绿色、琥珀色和红色；状态不能只依赖颜色，还应结合文字、图标、边框或位置表达。
- 颜色必须通过 Design Tokens 或现有 CSS 变量表达。业务组件不得散落新的近似颜色值。
- 普通面板避免大面积渐变、玻璃效果和明显阴影；阴影只用于确有层级关系的浮层、菜单或对话框。Viewport 内的渲染占位效果可以独立处理。

## 4) 字体与文字

- 英文 UI 首选 `Source Code Pro` 等宽字体；字体资源应由产品显式提供，不依赖用户机器恰好安装。
- 中文必须配置明确的 CJK fallback，例如 `Noto Sans Mono CJK SC`、`Microsoft YaHei UI` 或项目确认的等宽/近似等宽字体。
- 参数、路径、对象 ID、版本号、坐标、矩阵和数值优先使用等宽排版，保证列对齐和快速比较。
- 使用字号、字重、颜色和间距建立层级，不依赖比例字体的字面宽度。
- 建议的字号层级：页面标题 16–18px，面板标题 13–14px，字段与正文 12–13px，参数和辅助信息 10–12px。
- 不使用过度紧缩的负字距；英文标题、按钮和长对象名必须在实际面板宽度下验证截断和溢出行为。

## 5) 布局与信息密度

- Viewport 是主要工作区域，Scene Hierarchy 位于左侧，Inspector 位于右侧；新增页面不得随意改变这三个区域的职责关系。
- 面板、列表、属性组和工具栏优先采用平面分割、标题、缩进和细边框建立层级，不把每个字段包装成独立卡片。
- 以 4px 为基础间距网格。常用间距优先使用 4、8、12、16px；除非布局约束明确要求，不引入无法解释的零散间距。
- 普通控件高度建议为 28–32px，列表行高建议为 28–34px，面板标题区域建议为 36–48px。
- 默认圆角控制在 2–4px；只有浮层或明确的交互容器可以使用更大圆角。
- 保持专业编辑器需要的信息密度，避免大面积留白、超大标题和只用于装饰的容器。
- 面板缩放、窄窗口和长文本必须有明确的最小宽度、换行、截断或滚动行为。

## 6) 交互状态

所有可交互组件必须定义并保持一致的以下状态：

- `default`：默认表面、边框、文字和控件行为。
- `hover`：提供轻量背景或边框反馈，不改变布局尺寸。
- `focus`：使用可见的键盘焦点环或强调边框，不能只依赖鼠标悬停效果。
- `selected`：使用统一强调色、背景层级或边缘标记表达当前对象。
- `disabled`：降低对比度并禁止操作，同时保留足够信息说明不可用状态。
- `dirty`：明确表达本地修改尚未提交或尚未同步。
- `warning` / `error`：同时表达状态类型和可采取的行动，不能只显示颜色。

状态变化应使用短时、低幅度的过渡；不得通过持续动画、强闪烁或大范围位移吸引注意。必须遵守 `prefers-reduced-motion`。

## 7) 组件与实现约束

- 新 UI 优先复用已有基础组件、图标和 Design Tokens；不得为相同语义创建仅颜色或尺寸略有不同的重复组件。
- 新增组件时，必须同时考虑默认、悬停、聚焦、选中、禁用和错误/未保存状态，并在必要时补充展示样例。
- 标签和值应保持稳定对齐；数值、路径和 ID 的显示宽度、对齐方式和截断策略应具有一致性。
- 图标优先使用统一的线性图标系统，保持相近的视觉尺寸、线宽和基线；不得混用未经说明的填充图标风格。
- 视觉调整不得改变 Editor protocol、Tauri transport、Renderer controller 或 GameWorld 的职责边界。

## 8) UI Review 检查项

提交 Web Editor UI 改动前，至少检查：

- 是否保持固定浅色主题和 `Source Code Pro` 英文排版约定。
- 是否复用了现有颜色、间距、字体、圆角和组件 token。
- 是否保持 Viewport、Scene Hierarchy、Inspector 的空间职责和信息层级。
- 是否定义了新增交互控件的 hover、focus、selected、disabled 及异常状态。
- 是否避免无必要的渐变、玻璃效果、大阴影、过大圆角和重复卡片。
- 是否在窄面板、长文本、键盘操作和 reduced-motion 场景下保持可用。
- 是否只改变 UI 表现，没有把 UI 可见性或样式调整扩展成协议、Renderer 或资源生命周期改动。
